# 开篇引入

如果回到 2023 年，你大概不会相信一家名叫 Anthropic 的公司能掀起这么大波澜。当时 OpenAI 的 GPT-4 如日中天，而 Anthropic 连第一个产品都没正式发布，团队只有 5 个产品工程师，整个 API 业务只有一个人维护。大多数人（包括主持人 Lenny 自己）都认为：“根本没机会，OpenAI 已经赢了。”

然而两年后，Anthropic 不仅跻身顶级 AI 实验室，年收入据报逼近 500 亿美元，更接连推出一连串改变行业预期的产品：Claude Opus、Computer Use、MCP、Claude Code，以及引发“智能解锁”争议的 Claude Fable/Mythos。他们究竟是怎么做到的？

这期 Lenny’s Podcast 请到了 Dianne Penn——Anthropic 研究及实验室团队的产品负责人。她是公司第一位技术产品经理，参与了从 Claude 2 到 Fable 每一个模型的发布，并亲手孵化了 Claude Code、MCP、Skills、Claude Design 等众多明星产品。在整整一小时的对话里，她毫无保留地分享了：

- Anthropic 早期“自底向上”的文化如何诞生；
- 模型能力与产品体验如何互相加速；
- Labs 这种内部孵化器的运作秘密；
- 产品管理角色在 AI 时代的根本性转变；
- 为什么说“Evals 是新 PRD”；
- 以及她如何在指数级变化的疯狂节奏中保持清醒、避免倦怠。

这篇文章将这段对话完整重构，按照逻辑顺序展开每一个关键主题。无论你是产品经理、技术管理者，还是对未来 AI 趋势好奇的人，都能从中获得超越原始观看的深度理解。

# 详细内容

## 1. 探索身份：早期的文化与实验 `[对话开场 - 早期故事]`

**核心观点**
Anthropic 早期尽管资源极度匮乏且不被外界看好，但强烈的使命驱动、自下而上的协作精神，以及诸如 Golden Gate Claude 这样的快速实验，帮助他们找到独特的身份和自信，这些特质延续至今。

**深度阐述**
Lenny 毫不掩饰他对 Anthropic 最初的怀疑：“记得当时我想，这些人没机会。OpenAI 遥遥领先。”Dianne 并未反驳，而是指出正是早期的文化奠定了后来的一切。

她 2023 年加入时，整个产品团队只有 5 名工程师，API 业务仅有 1 个人。然而，公司的使命、文化和价值观从一开始就非常坚实，并且被切实贯彻。“真的做到言行一致” `[Dianne 描述文化]`。那种感觉更像一个充满能量的创业公司，而不是一个立志成为巨头的实验室。

早期的核心问题很根本：AI 技术如何为用户和社会带来价值？他们从 claude.ai 这个聊天助手开始，逐渐演化出工具使用等功能。但真正让团队找到感觉的标志性事件，是 2024 年初的 **Golden Gate Claude**。

那段时间公司刚刚发布了一篇可解释性研究，研究者发现模型内部有一个特征与“金门大桥”深度关联。如果手动增强这个特征，Claude 就会在所有回应中痴迷地提到这座桥。比如问它意面食谱，它会说：“下面是一道食谱，而它的橘红色就像金门大桥的国际橘。”（`[Dianne 复述例子]`）团队嗅到了趣味性，决定快速让它变成真实体验。

“我们在 24 小时内就在 claude.ai 上让整个体验上线，工程、产品、设计和研究团队一起协作，许多人是自愿贡献时间的。” 这个项目完全是从下而上发起的，没有高层指令。虽然最终只触达了大约 2000 人，但 Dianne 认为那是一个隐性转折点：“它让我们感觉：我们能够构建新的用户体验，以不同于竞争对手的方式展示我们的研究，并且保持创业公司的节奏。” `[原话]`

自此，团队确认了自己独特的身份：不仅做基础研究，还能用快节奏、自底向上的方式将研究成果变为有辨识度的产品。后来的 Labs、Claude Code、MCP 等产品都脱胎于同样的基因。

**个人感受**
Dianne 在讲述 Golden Gate Claude 时语气里带着真挚的怀念。她说：“我看到了工程师和设计师自愿抽出时间……那让我觉得文化真正被实践了。”她强调这种“奉献时间”的感觉非常“Anthropic”。

**延伸思考**
对于很多技术公司，早期身份模糊时，尝试一些有品牌辨识度的快速实验（即使是“怪”项目）能高效凝结团队共识并向外界传递差异化形象。这种实验不应该被低估，它可能成为文化的最强载体。

## 2. Opus 3：模型能力的转折与编码差异化 `[关于 Opus 3]`

**核心观点**
Opus 3 的训练和成功发布是 Anthropic 内部第一个重大转折，不仅证明了他们能构建前沿模型，更让他们敏锐捕捉到“代码生成”这个关键的差异化战场。

**深度阐述**
当时公司不到 200 人，决定训练一个真正的 frontier 模型。Dianne 回忆起训练和测试 Opus 3 的几个月，特别是圣诞节期间，所有人各自在家里的父母家通过网络协作，每个人视频背景里都是童年的房间。“看到大家的童年背景，那种画面很特别。” `[Dianne 描述]` 这种一起在“壕沟里”工作的经历建立了深层的信任基础，后来许多当时的同事成了公司核心力量的领导者。

在 Opus 3 的开发过程中，Dianne 注意到了一个关键信号：用户开始用语言模型执行较长的代码生成任务，而不仅仅用于自动补全。她意识到这是一个机会，可以针对性地训练 Opus 3 在编码上做得更好。“2023 年我刚加入时，没人把 Anthropic 和代码放在同一个句子里。” `[原话]` 而这个相对较小的训练调整却带来了巨大的竞争差异，吸引了一批早期的开发者和爱好者，帮助团队在最初就建立了一群忠实用户。

**个人感受**
Dianne 说那段时间虽然辛苦，但看到团队在假期里依然热情投入，大家相互信任，那成为她最珍视的经历之一。同时，她发现了“代码”这个信号，并主动推动训练调整，显示出产品直觉在模型开发中的关键作用。

**延伸思考**
在一个技术飞速发展的领域，差异化不一定来自最宏大的革命，往往来自对细微市场信号的洞察并快速行动。产品经理需要深度嵌入模型训练过程，才能捕捉这些机会。

## 3. Opus 4.5 与 Claude Code：前沿产品与前沿模型的指数协同 `[关于 Opus 4.5]`

**核心观点**
Opus 4.5 的大爆发不仅是模型自身智能的跃迁，更是因为 Claude Code 这个产品载体已经成熟。两者相互成就，形成正反馈循环，推动采纳率爆炸。

**深度阐述**
一年后的同一假期，团队再次迎来关键时刻：Opus 4.5。但与一年前不同，这次他们同时拥有了一个出色的产品——Claude Code。Dianne 的总结非常精彩：“Opus 4.5 如果没有像 Claude Code 这样的产品，就不会有那样的高光时刻；同样，Claude Code 如果不搭配 Opus 4.5，也不会有那么快的采纳加速。” `[原话]`

Claude Code 作为一个 agent 式的编码工具，已经经过了数月的迭代。团队内部经常说：“你需要有前沿产品，才能让人感受到前沿模型的魔力。” Opus 4.5 的智能达到了一个新的临界点，让 Claude Code 有可能在广泛场景下端到端地处理复杂任务。这种模型和产品的双轮驱动模式，让双方都进入了“指数加速”阶段。

**个人感受**
Dianne 谈到 Opus 4.5 时明显兴奋，她说团队在 Claude Code 上积累的经验让模型发布后的效果被放大了。“没有那次协同，这次发布不会那么特别。”她认为这是一个很多人低估的关键因素。

**延伸思考**
对于所有 AI 公司，这个教训很深刻：不要等到模型完美了再开始产品布局。预先构建优秀的产品界面，当模型能力跃迁时才能立刻释放最大价值。产品和模型应该同步进化，而非各自独立。

## 4. Labs：内部孵化“非连续大赌注”的模式 `[关于 Labs]`

**核心观点**
Labs 是 Anthropic 内部的创新孵化器，专门识别那些可能成为 10x、100x 甚至 1000x 的“非连续型赌注”。通过极小的团队规模、强烈的主题自信与灵活的实验方式，成功孵化出 Claude Code、MCP、Skills 等关键产品。

**深度阐述**
Lenny 好奇：Anthropic 本身已经很创新，为什么还要单独设一个 Labs？Dianne 解释说，Labs 的使命是应对那些可能不在主线路线图上、但一旦成功就有改变化学反应的“非连续赌注”。他们遵循一个原则：“对一个主题或领域非常坚定，但对具体的原型保持灵活。” `[方法论]`

团队很小，往往一个想法从一个工程师开始。他们采用“内部公开工作”文化，在 Slack 频道里分享实验和发现，其他人可以立即迭代，大概经过 10 次左右的尝试就可能碰到某个“魔法时刻”。这种模式的结果包括：Claude Code、MCP（模型上下文协议）、Skills、Claude Design，以及核心能力如 Computer Use、Tool Use 和 Reasoning。

即使有些实验短期内不成功，团队也会保留经验，在一两个模型版本后重新尝试。Dianne 强调：“我们选的就是那些真正喜欢 0 到 1、能接受很多赌注在当下不成功的人。” `[原话]` 这种文化让 Labs 能够保持高度敏捷，同时持续为 Anthropic 的整体策略提供前瞻性视野。

**个人感受**
Dianne 非常大度地把 Labs 的成功归功于 Ben Mann 的愿景和团队的忍耐力。“有很多项目我们投入了心血但暂时没见效，那是很难受的。但大家仍然愿意再试。”

**延伸思考**
对大公司内部创新来说，这套方法论有很强的借鉴意义：小团队、强信心、快速迭代、乐于共享和迭代失败，比大规模投入一个未验证的方向更可持续。同时保留知识以便复用的思路也非常关键。

## 5. 产品管理进化：Evals 是新的 PRD `[产品管理进化]`

**核心观点**
在 AI 产品中，由于模型行为的非确定性，传统 PRD 的效果下降。而 Evals（评估集）正在成为定义问题、衡量进展、驱动模型改进的核心工具。产品经理必须“既 sweat the pixels，也 sweat the tokens”。

**深度阐述**
Dianne 提出了一个在公司内广为流传的说法：“Evals are the new PRDs。” `[原话]` 这句话背后是一种根本性的工作方式转变。当用户反馈模型表现不佳时，传统做法可能是写一个 PRD 描述功能需求。但在 AI 产品中，同样的反馈可能来源于多种根本原因：模型幻觉、指令跟随失败、工具调用错误、检索错误，甚至是对齐问题。

产品经理的职责是先通过阅读用户对话记录，深入理解失败轨迹，识别出确切的失败模式，然后构建一组可重复的测试样例（eval），用它来度量模型是否改善。Dianne 举了一个早期案例：Claude 在 Claude 2 时期被用户抱怨“不遵循指令”。她深入调研后发现 80% 的情况指的是“模型无法输出正确的 JSON”。于是她构建了 30-40 个针对 JSON 输出的 eval 案例，加进评估体系。在后续版本中，这个 eval 从不及格变成了每次都接近 100% 通过。`[案例细节]`

然而 PRD 并未完全消亡。Dianne 指出，当需要让一大群人（包括产品、工程、安全、法务等）对同一个目标达成一致时（比如新模型发布的整体目标），PRD 依然是有效的对齐工具。在全新模糊的领域（如 Computer Use），PRD 的愿景部分也能帮助探索方向。但优先级确实变了：Eval 成为了推动日常改进的最强抓手。

**个人感受**
Dianne 强调，“产品经理现在必须是离 details 最近的人。” 她自己在公司里以愿意“读上千行用户对话记录”而闻名。她说只有这样才能构建出真正反映用户痛点的 eval。

**延伸思考**
这其实是 AI 时代的“测试驱动开发”。传统 PM 的工作多集中在文档和沟通，而现在的核心输出变成了“正确构造问题与度量方法”。能够设计高质量 eval 的能力，可能成为区分优秀 AI PM 的关键分水岭。

## 6. 连接用户与研究者：将模糊反馈变为行动 `[与研究者协作]`

**核心观点**
将模糊的用户反馈转化为研究人员可执行的模型改进方案，是 AI 产品经理最有价值也最困难的工作。需要分解问题根因、构建可复现的评估、并用研究者的语言沟通。

**深度阐述**
Dianne 细致描述了协作流程：当收到“Claude 表现很差”这类反馈时，她不会直接告诉研究者“请修复 Claude”，而是先去分析用户对话轨迹，判断是工具调用有问题，还是检索错误，还是超出当前能力范围。不同根因对应不同的研究方向。

接下来她需要构建一个代表性的 eval，能可靠地衡量这个问题在模型上的发生频率和严重程度。“你没法改进你无法测量的东西。” `[Dianne 原话]` 然后带着这个 eval 去找研究者，讨论这是否值得作为改进重点。整个流程紧密嵌在模型训练周期中，产品经理的角色更像一个“翻译员+诊断师+测试工程师”的综合体。

**个人感受**
Dianne 坦承这是她工作中最有挑战的部分，但也最有成就感。她说：“当你看到下一个版本确实在这个 eval 上提升了很多，你就知道你的工作真正改变了用户体验。”

**延伸思考**
这个模式对其他类型的 AI 产品团队同样适用。建立清晰的“用户反馈 → 问题分类 → eval 构建 → 可量化追踪”闭环，可以大大加快模型迭代和产品优化速度。产品经理的技术理解力在这里变得比以往更加重要。

## 7. 思考的伙伴：如何与 AI 协作而不丧失自己的声音 `[关于思考与认知]`

**核心观点**
AI 最理想的使用方式不是让它替你做一切，而是作为“思考伙伴”：你先有自己的观点，然后让 AI 挑战你、扩展你。同时要警惕思考外包，在个人风格和判断力上保持主导。

**深度阐述**
Lenny 提到大众焦虑：依赖 AI 会不会带来“脑腐”？Dianne 认为关键不在于是否使用 AI，而在于如何使用。她自己在准备重要对话时，会先用自己已有的框架想好观点，再打开 Claude 问：“我准备用这个方式处理，你怎么看？” Claude 可能会提出她遗漏的视角，挑战她的假设。这种互动让她更强大。

她特意强调，Claude 的“不盲从”非常重要：“一个只会同意你的思考伙伴是不合格的。” `[原话]` 这恰好得益于 Anthropic 在安全和对齐上的投入——宪法训练让 Claude 在必要时拒绝不合适的请求或主动提出不同观点。这种“建设性的不服从”是优秀伙伴的核心特质。

但她也会区分使用场景：对于标准化报告（如每周业务回顾），她愿意完全委托给 AI，自己只做验证人；而对于体现个人观点的写作、策略思考，她会始终让自己走在前面。她说：“写作和思考是一体的，如果我让 AI 替我写所有东西，我的思考能力也会变弱。”

谈到 AI 写作的“机器味”，她承认目前在写作质量上投入的训练不足，但团队正在积极改善。她认为未来更重要的可能不是“谁写了”，而是“谁验证和负责最终输出的质量”。

**个人感受**
Dianne 自己就是在用这些原则工作——她分享了一个自己频繁使用的用例：把《关键对话》这本书的内容做成 Skills，用来帮助自己准备困难的管理沟通。“Claude 不是告诉我答案，而是帮我理清思路。”她说这种感觉非常棒。

**延伸思考**
在 AI 逐渐接管生产性任务的趋势下，主动培养“先思考，后借助 AI”的习惯至关重要。教育和工作培训都应该强调这种主体性——工具应该放大，而非取代人的判断力。

## 8. 未来最有价值的技能：判断力、好奇心与坚持 `[未来人才与教育]`

**核心观点**
当 AI 可以完成越来越多具体任务时，人类最不可替代的能力是基于真实经验积累的**判断力**、面对未知的**好奇心与毅力**，以及坚持**自己的立场和独立思考**。

**深度阐述**
Lenny 问：“在 AI 越来越强的未来，人类最宝贵的到底是什么？” Dianne 的第一个答案是“判断力”。“判断力是大量复杂经验积累的结果，而 AI 还没有足够多的真实体验。” `[原话]` 其次是“主动性和坚持”，这些品性目前仍难以通过训练得到。

她将同样的理念应用到对两个孩子的教育。她鼓励他们发展好奇心、坚持自己的观点（“对妈妈也要有主见”），并相信自己的内在声音。她说：“我们希望孩子最终成为成年人，而不是永远在找别人的答案。”她分享了一个小细节：有人建议让孩子只用早期 AI 模型以保证他们仍需要努力，她觉得这个想法很有趣但未置可否。更重要的是先培养坚实的内心基础。

对于职场人，特别是产品经理，她认为那些愿意深入细节、亲自使用模型、自己构建 evals 的人会脱颖而出。即使招聘高级管理者，她也坚持同样的标准：“你必须亲自动手 shipping，才能真正理解你在管理什么。”

**个人感受**
Dianne 分享了祖父对她的影响：“他总说——**无论你走多远，总有更高的层次**。”`[原话]` 这句话帮助她保持谦逊和进取心。她也将这种心态带到团队：每次认为达到巅峰时，新的挑战立马出现。“那种一直在攀登的感觉驱动着我。”

**延伸思考**
在 AI 赋能极大化的情况下，唯一不可复制的就是个人经验和基于此的直觉判断。公司选拔人才时，除了技术能力，也应该看重候选人对未知领域的探索热情、在模糊环境下的决策力。

## 9. 团队文化：对抗倦怠的秘诀在于共同承担 `[团队文化与倦怠预防]`

**核心观点**
在 AI 指数级变化的极高压力下，避免倦怠不是靠个人硬抗，而是靠构建一个低自我、高互助的团队文化——让成员能真正相互替补、信任和共情。同时，保持对技术的好奇心和乐趣可以持续注入能量。

**深度阐述**
“2024 年我们发布了四个模型系列，但 2025 年第二季度我们就发布了比去年全年还多的版本。” `[Dianne 例子]` 节奏快到惊人。Lenny 问她是如何不烧坏的。

Dianne 首先归功于团队：“没有人可以独自支撑这样的节奏。”她描述了一个常见的场景：某个模型发布的前夜，即使不是自己负责的模型，其他 PM 也会主动留下来帮忙审 blog post、想 demo 点子，互相成为“额外的一双手”。他们内部称之为“进入蜂巢思维”。这种文化让她能够放心休假——她知道团队会处理好一切，不会等她回来时堆积三倍的工作量。

她也强调个人层面同样需要支持。她的丈夫非常理解她对科技的热情，“这是我第六年全身心投入 AI，他看着我一路过来。”`[个人分享]` 此外，她自己还会从工作中找到乐趣，而不是仅仅把它当任务。她建议人们：“不要自己一个人闷头实验，找一两个同样好奇的人一起探索。当你看到别人第一次用出新功能时的惊喜，那种快乐是共享的。”`[原话]`

**个人感受**
Dianne 说：“有些最好的点子就是在 Slack 频道里，一个人分享一个原型，其他人在 10 分钟内迭代出更好的版本。这种交流本身就有极大的乐趣。”

**延伸思考**
在 AI 使团队规模变小，甚至很多开发者开始与 agent 协作而不是与真人协作的背景下，组织应该更加刻意地创造人际连接的机会。互助文化不是自然产生的，需要从招聘（低自我、团队导向）和激励机制上培养。

## 10. 闪电问答：书籍、剧集、交易员的烙印与人生哲学 `[快速问答环节]`

**核心观点**
Dianne 分享了她反复推荐的书籍（《如何让孩子成年》和 Eric Ries 的《不可腐化》）、刚追完的《辐射》剧集，以及她作为高风险债券交易员的早期经历如何塑造了她的信念和领导风格。

**深度阐述**
- **书籍推荐**：她推荐了两本书。一本是育儿书《如何让孩子成年》，框架好：我们的目标不是养孩子，而是养成年人。这让她的教育方式更清晰。另一本是 Eric Ries 的《不可腐化》，讲如何打造持续优秀的企业文化。她提到书中关于“文化指标”和“价值观衡量”的观点对她很有启发。
- **剧集**：休假时她追完了 Amazon 的《辐射》，觉得“机智、幽默、动作感强”。
- **职业烙印**：在 J.P. Morgan 做高收益债券交易员的四年，她是交易台上唯一的女性，背景也比较独特。那段经历教会她：“即使你是最资浅、看起来和大家都不一样的人，只要有最好的想法，你就应该自信地提出来。而最重要的不是你是谁，而是你的想法的质量。”`[原话]` 这种信念让她现在更愿意在团队中鼓励每个人，无论级别如何，提出自己的见解并付诸行动。
- **人生哲学**：祖父的教诲：“无论你走多远，总有更高的层次。”她面对每一个“第一次”的新挑战时都会想起这句话。它提醒她保持谦逊，也激励她不断成长。

**个人感受**
她分享这一切时非常自然，可以看到每个故事都早已融入她的价值观。

**延伸思考**
一个人的早期职业生涯和家庭教育往往留下了深刻的烙印。在快速变化的领域，那些跨领域的经历（比如金融交易）带来的原则性思维方式，往往比纯技术背景更具韧性。

# 精华收获

1. **文化 vs. 流程**：自下而上、使命驱动、快速实验的文化是所有创新的土壤。Golden Gate Claude 这种“小实验”比宏大计划更能建立团队认同。

2. **模型与产品的双轮驱动**：最成功的突破总是发生在前沿产品和前沿模型同时成熟时。不要等待模型完美，提前优化产品界面，在模型能力跃迁的那一刻释放全部潜力。

3. **Evals 是新的 PRD**：在 AI 的非确定性世界里，可度量、可复用的评估集是驱动改进的第一工具。产品经理的核心产出，不再只是文档，而是精心设计、反映真实用户痛点的评估系统。

4. **先思考，再使用 AI**：防止“脑腐”的关键不是远离 AI，而是建立正确使用习惯——先有自己的立场，再让 AI 挑战和扩展。保持对写作和决策的个人主导。

5. **未来最稀缺的人类技能：判断力、好奇心、坚持**。这些无法被算法复制，需要真实经验和自主意志的培养。

6. **防止倦怠的根本是“不独撑”**。互助团队、低自我文化、对技术本身的享受，共同构成了可持续的工作节奏。
