# AI 营销代理是新的编程代理：两大获客系统搭建全指南

在 AI 浪潮中，**营销代理（Marketing Agent）正在成为新的编程代理**。就像当年编码代理让“按需创建软件”成为现实一样，部署营销代理的意义在于——你可以在自动驾驶模式下持续获得客户。本期内容来自 Greg Isenberg 的播客节目 **Sip Baby**，嘉宾 **Cody Schneider** 分享了他如何利用 **Claude Code** 或 **Codex** 这类工具，构建一套完整的营销代理系统。Cody 不仅会展示两个端到端的营销代理，还会公开所有需要的工具链。最重要的是：没有任何门槛，不卖课，直接公开教学。

---

## 一、核心策略：为什么是 LinkedIn 互动？

在开始搭建之前，先理解这套系统的战略逻辑。

Cody 指出，**冷邮件（Cold Email）正在被“灭杀”，回复率全面下降**。事实上，现在每个营销渠道都在下降，因为 **AI 生成的垃圾内容正在淹没整个领域**，所有赛道都变成红海。

那么如何脱颖而出？答案是：**寻找信号或触发事件，表明人们正在“举手”表达兴趣**。当一个人点赞或评论了某一主题的内容，这本身就是一种“手举起来”的信号——说明他对这个东西感兴趣。这意味着我们不再只依赖传统的企业画像（如公司规模、行业、人群特征），而是直接判断目标客户是否对该主题有真实的兴趣和倾向。

这套系统可以做到：**监控某个垂直领域内影响者的 LinkedIn 帖子，提取所有互动者，然后通过“瀑布式数据丰富（Waterfall Enrichment）”找到他们的邮箱甚至电话号码，最后对这些线索进行冷邮件和 LinkedIn DM 外联**。

## 二、营销代理一：冷外联获客系统

以下就是完整的冷外联系统搭建步骤，也是 Cody 在节目中演示的“第一台营销代理”。

### 第一步：找到利基市场中的影响者

首先，打开 LinkedIn，找到你所在领域的创作者或公司账号。不要用代理来自动完成这步——**只需要手动整理一个包含 10-20 个影响者/账号的表格**，就足够支撑起一个有效渠道的线索量。

以演示为例，一开始用“AI for WordPress”作为关键词搜索，但效果很差。改用“AI marketing”后，信息流立刻出现了大量与目标受众相关的内容。判断标准很简单：**系统呈现的内容是不是你的目标客户会去互动的内容**？如果是，这些创作者就是值得监控的“信号源”。

**注意：不一定是个人创作者，也可以是品牌账号**。如果某个企业账号的互动者正好是你的目标客户，同样可以用。例如 **Clay** 这样的账号也完全可以。

另外，一个常见的效率误区是试图监控整个行业。实际上，**任何一个细分领域都只有少数几个头部创作者，而所有人都会和这些头部内容互动**。只要监控这些头部账号，就能覆盖该行业约 80% 的表面交互面积，边际收益再往后就几乎为零了。同样的逻辑也适用于广告创意：与其让代理不断生成雷同的创意，不如追踪 10 个 Instagram 人类创作者，从他们的爆款内容中提取新钩子、新话题，进行二次混剪。

### 第二步：用 Amplify 抓取互动者

接下来，需要一个叫 **Ampify** 的工具。这是一个**抓取 API（Scraping API）**，只需一个 API Key，就可以抓取 LinkedIn、Twitter 等多个平台的数据。它能将外部数据带入你的代理上下文，让代理做出更明智的决策。

Cody 特别提到，团队长期使用 **API Maestro** 提供的 LinkedIn API 端点，因为它连接最稳定。这个第三方提供了大量可调用的功能函数。你只要在 Ampify 上拿到 API Key，就能让 Claude Code 或 Codex 等编码代理调用这些端点。

对于本套系统，使用的两个核心端点是：

- **Post Comments**（帖子评论）
- **Post Reactions**（帖子反应）

这两个端点可以提取出“某条帖子的所有互动者”。Cody 在现场演示了如何在 Claude Code 中完成这个过程：将 Appify API Key 存放在本地目录，让代理先阅读端点文档，再传入帖子 URL，代理就会自动提取所有互动者信息。

在实际落地上，你不需要每次手动运行。**把这套代码部署到云端，设置每日定时任务，自动检查这些影响者是否发布了新帖子，然后自动提取出所有新的互动者**。就像现场演示中那样：60 多个公开个人资料被提取出来，所有联系人都会陆续被抓取出来。

### 第三步：什么是“代理”？先做 ICP 筛选

有人问：这看上去只是自动化，为什么叫“代理”？Cody 的回答是：

> 代理本质上是完成一个“待完成的工作（Job to be Done）”。它的内核是**代码 + 可能的思考循环 + 实时数据流**。

一个营销代理的职责是：找到线索、主动外联、并在线索提问时持续响应、推动他们进入转化漏斗。

在提取到 LinkedIn 联系人后，最好先加入一个 **ICP（理想客户画像）筛选环节**。代理可以先研究这个人和他所在的公司，例如公司有多少员工等；如果符合客户画像，再推进到数据丰富和外联流程。这个筛选过程可以交给大语言模型（LLM）来完成。

### 第四步：瀑布式数据丰富（Waterfall Enrichment）

拿到 LinkedIn 个人资料后，下一步就是找到邮箱和电话号码，这被称为**瀑布式丰富**。Cody 给出了一个工具优先级链：

1. **GetLeads.io**：一个聚合了大量 B2B 联系人的数据库，可通过 API 访问。优先使用它的邮箱数据，因为它通常最便宜也最准确。
2. **Apollo**：在 GetLeads.io 中找不到的那部分联系人，再“瀑布”到 Apollo 查找。
3. **Origami**：如果 Apollo 还没有，继续下沉到 Origami。Cody 非常欣赏该团队，尤其是 Finn 的团队做得非常好。

实际操作中：假设你有 50 个 LinkedIn URL，GetLeads.io 找到其中 32 个人的邮箱；剩下的 18 个发给 Apollo，找到其中 10 个；最后 8 个再用 Origami 或 Prospio 等工具处理。**从最便宜、最准确的工具开始，逐级向下**，最终可以实现约 80% 的邮箱找到率。如果你想更省事，有些工具如 **Origami 本身就是聚合器**，它内置了瀑布式流程——你直接丢一个 LinkedIn 链接进去，它会自动串联各种数据源。

另外还有一个值得团队关注的工具：**Lead Magic**。它尤其擅长查找手机号码，数据质量也不错，可以作为电话信息的补充来源。

### 第五步：验证邮箱地址

所有从数据提供商拿到的邮箱，都必须经过验证。Cody 使用的工具是 **MillionVerifier**。它能把邮箱分为“有效（Good）”“有风险（Risky）”“无效（Bad）”等不同状态。一定要在发送前做二次验证，因为**发送到无效邮箱会严重损害你的邮件送达率（Deliverability）**。GetLeads.io、Apollo 等虽然自带一定检查，但最好还是再跑一遍验证。

### 关于合规性的讨论

Greg 在这里提出了一个“笨问题”：获取这些人的邮箱合法吗？Cody 回应：

> 获取邮箱这件事本身是完全合法的，因为本质上你是从数据经纪商那里购买数据，而这是允许的。关键在于后续如何使用这些数据。在美国，你可以合法发送冷邮件，也可以将人添加到邮件订阅列表并做到反垃圾邮件合规，但这有一整套合规清单。而在欧盟，规则则完全不同。所以请自行研究并遵守当地法规。

他同时也提醒：“这些数据公司如何拿到数据，背后可能是另一个阴暗的网络，但今天我们讨论的这个环节，在黑帽与白帽的光谱上，已经相当靠近白帽了。”

### 第六步：购买发送邮箱的基础设施

找到并验证了联系人之后，你需要真正能发送冷邮件的“基础设施”。**绝不能从你的公司主域名发送大量冷邮件**，否则会彻底毁掉主域名的送达率。正确的做法是购买**独立的“燃烧域名（Burner Domains）”**，并把不同用途的邮件域名分开：

- 冷邮件专用域名
- 营销邮件专用域名
- 交易类邮件域名（例如密码重置邮件）
- 团队日常工作邮箱域名

可选的服务包括：

- **InboxKit**：可购买冷邮箱，价格与大多数服务差不多，而且经常有折扣活动。
- **Instantly.ai**：同样提供现成的邮箱/域名套餐，你也可以直接从 Instantly 购买预建的收件箱。
- **Hypertide**：这是 Cody 团队合作并推荐的供应商。以 Hypertide 为例，**大约 100 美元/月的邮箱基础设施成本，可以支持发送约 10,000 封冷邮件**。总体上，包含发送软件和收件箱基础设施，初期的启动成本大约在 200 美元左右。Instantly 的入门套餐通常从每月 97 美元开始。

### 第七步：发送冷邮件和 LinkedIn DM

接下来需要一个发送平台。**Instantly** 是 Cody 团队常用的冷邮件发送平台。发送逻辑是：

- 你将整理好的每个联系人的个性化变量写入邮件，通过 API 推送进 Instantly，由平台批量发送。
- Instantly 也支持 Webhooks：一旦收到正面回复，它会把这个信号回传给云端服务器上的代理。
- 代理收到回复后，可以根据预设目标（比如引导对方预约演示）来管理收件箱、回答问题、推动对方进入下一个环节。

LinkedIn DM 外联则使用：

- **HeyReach**
- **Bot Dog**

这两个平台都提供 API，可以实现 LinkedIn DM 的自动化投放。Cody 也提到，有人直接用 **LinkedIn InMail** 配合这套策略，同样取得了惊人的效果。

### 第八步：让代理管理收件箱

真正的“代理”能力体现在收件箱管理上：

- 代理负责为每一位联系人撰写个性化邮件，并通过 API 推送到发送平台。
- 当 Webhook 传来积极信号时，代理接管对话：回答问题、消除异议、促成预约演示。
- 代理可以连接你的日程工具（如 **Calendly** 或 **Cal.com**），查看对方是否真的预约了会议，从而追踪最终转化效果。
- 甚至可以设置“沉睡客户唤醒”流程：**每六个月自动重新联系那些没有回应的线索**。

这就是一个完整的“**装在盒子里的 SDR（销售开发代表）**”：寻找新线索、找到邮箱、写邮件、判断 ICP 适配度、发送、管理收件箱。Cody 强调，这里的“代理”不需要复杂到“让上帝住进盒子里操作邮箱”，它就是代码 + 一个 LLM 而已。不需要过度工程化，很多时候一些所谓的 Agent 框架反而是多余的“膨胀体”——**回到最简单、最不容易出错的方案**。

### 部署与运行

要把这套系统真正跑起来，你需要一台永远在线的服务器。可使用 **Railway** 这样的服务，或者像 Cody 团队在 **Graft** 平台所做的那样——拥有一个数据管道/数据仓库（例如 **ClickHouse**），再配合一个部署代理的服务器。只要有了实时数据流和服务器，代理就能每小时或每天自动运行。

Greg 补充了一个关键观点：**“我们正在进入软件工厂时代”**。无论用 Claude Code 还是 Codex，最难的不是代码，而是策略——你打谁、为什么打、整套工具栈怎么组合。一旦想清楚，接下来就是用软件去完成任务。

## 三、营销代理二：有机内容生成系统

很多观众觉得冷外联不是自己的路线，因此 Cody 还分享了第二个代理——**用 AI 打造团队成员的 LinkedIn 个人品牌内容**。

### 为什么必须从真实对话中提取源材料？

有了 AI，你当然可以说“帮我写条 LinkedIn 好内容”，但这样生成的内容大概率非常平庸，而且很容易被 LinkedIn 新推出的 AI 内容标记功能识别。**更好的方法是：从真实的人类对话中提取原创素材**。

Cody 的实操流程：

1. **录制/采访**：比如每周与团队进行一对一对话，问他们“这周学到了什么？”不需要固定主题，就是聊天。内容可以来自销售电话中的客户反馈、技术团队的洞察、内部 Slack 讨论，甚至 **Gong 通话记录**。
2. **提取洞察**：把采访文字记录交给 LLM（例如 Claude Sonnet），由它提炼出有价值的观点。很多时候，真正的宝藏就藏在客户为什么没买、为什么犹豫这些细节里。
3. **生成帖子**：基于提取的洞察，让 LLM 写作成 LinkedIn 帖子。
4. **自动排期**：使用 **Ordinal** 进行排期发布。Ordinal 可以连接多个 LinkedIn 账号，也支持各账号之间互动；通过 API 或 MCP，可以把写好的帖子自动推送到不同账号。
5. **数据回流**：Ordinal 提供 LinkedIn 帖子的分析数据，可以看到每条内容的效果。这些数据反馈给代理后，它就会知道哪些主题、哪些格式更容易获得曝光，然后在下一轮创作时更偏重这些方向。

这套流程本质上复刻了顶尖社交媒体经理的工作方式：

- 挖掘好想法；
- 针对想法制作内容；
- 发布内容；
- 分析数据，找出表现最好的内容；
- 把胜出的想法做成内容日历，反复混剪、换角度。

Cody 分享了自己的经验：**一条真正有效的帖子，每 90 天换个角度重发一次，效果依然很好**。因此，与其不断创造新想法，不如“挖掘市场已经买账的内容”，再结合自己的独特角度重新表达。对创业者也一样：不要总想发明一个全新的市场需求，而是要问自己：**市场现在想买什么？我能不能造出来并卖给他们？**

### 社交媒体经理的角色进化

Greg 直言：社交媒体经理这个岗位已经“死了”，或者说必须进化为“**社交媒体代理经理**”。一个人未来可以同时管理 10、20、甚至 100 个账号，系统性地产出内容。Cody 补充道，他已经见过公司用这套方法让 7 人销售团队每天稳定输出内容，而且每一篇都足够独特。

另一个有趣的例子是：Cody 自己通过 AI 生成素材、发表内容，获得了大量免费曝光和互动；**平台甚至反过来为创作者付费**（例如 YouTube 的分成）。他算了一笔账：LinkedIn 上的平均展示成本大约是每千次 22 美元。即使是一个只有 500 粉丝的账号，一条帖子获得 1000 次展示，就相当于免费赚到了 20 美元的媒体价值。

### 主题页与匿名品牌策略

如果你不想做个人品牌，Greg 提供了一个“秘密配方”：**创建主题页或话题页**。

例如他的好友 **Julian Shapiro**，并没有给自己的代理公司 Demand Curve 做 X（Twitter）账号，而是创立了一个名为 **@Growth Tactics** 的主题账号。所有对增长策略感兴趣的人都会关注这个页面，进而了解到他的公司和产品。这就是“社交媒体媒体公司”的打法。

另一个例子是 **Chase Passive Income**——一个类似 meme 页面的账号，但同样通过聚合和整理高质量内容，吸引大量注意力，再将注意力转化为所建产品的潜在客户。你不一定非要露脸，可以做一个匿名的、提供价值的主题账号，用免费的注意力驱动 inbound 流量。

## 四、核心观点：营销只是代码，不要在令牌上烧钱

在整场对话中，Cody 反复强调一个“范式转移”：

> **唯一的代理其实是编码代理。** 其他所有“营销代理”本质上是编码代理造出来的软件。

营销已经变成了代码：

- 生成一个香蕉图片，本质上是一个 JSON 提示词；
- 生成一条 AI 视频，背后是 LLM 抓取 Reddit、读取内容、写脚本，然后调用 API 生成；
- 排列组合这些 API 调用，就是一套自动化营销系统。

因此，**不要为每一次 API 调用向 Anthropic 或 ChatGPT 支付“令牌税”**。如果你只是在做一件可以写成固定软件的事情，就别让 LLM 每次都“思考”一遍。正确的做法是：

> 你支付的应该是“制造软件的代码能力”，而不是“执行动作时燃烧的令牌”。只在真正需要推理时使用推理，其余动作都应该跑在非常便宜的算力上。

过度使用 Agent 反而容易增加出错概率。例如让 Claude 直接操作 Facebook 广告账户，可能导致账户被毁；但如果你构建一套定制化软件，去模拟一个顶级媒介买手的流程——研究创意角度、制作创意、测试、砍掉失败者、放大赢家——得到的结果会稳定得多。
