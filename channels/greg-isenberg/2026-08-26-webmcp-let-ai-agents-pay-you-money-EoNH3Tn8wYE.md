# AI Agent 即将成为互联网的新金主：WebMCP 如何让网站「长出按钮」直接收钱？

想象一下：未来几年内，互联网上会突然涌入数千万甚至上亿个「AI 访客」——它们是 AI Agent，自动帮你搜索、比较、下单、预订、管理账号。它们不再是人类浏览器的模拟器，而是独立的「数字消费者」。这听起来像是科幻，但 Greg Isenberg 在这期节目里想告诉你的是：这件事已经在发生，而且**其中蕴含着数以亿计的财富转移**。

问题在于，今天的互联网根本没有为这些 Agent 设计。如果网站无法被 AI Agent 高效理解与操作，那么它们就会在这场新的流量大战中全军覆没。而 Google 和微软联合推出的新实验性标准 **WebMCP**，可能会成为这个新世界的「公共基础设施」。

在这一期节目中，Greg Isenberg 请来了他的朋友 Vinnie，用一场真实的咖啡机购买演示，把 WebMCP 是什么、为什么重要、如何抓住先发机会，以及两个现在就能开始做的现金流创业点子，讲得透彻又热血。对于任何关心 AI 时代商业机会的创业者来说，这期节目都值得反复听。

如果你关注 AI 领域的创业机会，你大概已经知道：ChatGPT 出现后，大家最关心的是「AI 能不能回答问题」；再后来，大家关心「AI 能不能引用我的内容」。而 Greg Isenberg 在节目开头抛出的观点，直接把竞争的维度拉到了一个新高度：**「AI 能不能帮用户完成任务？」**

但好消息是：你不用从现在开始把网站重新写成一堆复杂的 API。Google 和微软已经给出了一个「中间层」方案，叫 **WebMCP**——它不是让你把网站拆掉重建，而是让你给网站「装上按钮」，让 AI Agent 像人类一样「看得懂、点得动」。最疯狂的是，这个功能目前还处于实验阶段，知道的人少之又少。正如 Greg 在节目结尾说的一句话：**「套利的机会永远存在于实验性阶段。」**

### 一、AI Agent 是互联网上的「新物种」——而互联网还没准备好接待它们 `[视频开场 0:00-0:35]`

**核心观点**：AI Agent 即将成为互联网上全新的「访客」和「消费者」，这将带来数十亿美元级的财富流动，但今天的网页从根本上就不是为它们设计的。

**深度阐述**

节目一开始，Greg Isenberg 就抛出了一个让人心跳加速的判断：**「AI Agent 即将成为互联网上一种全新的访客。我认为在这个过程中会有数十亿美元的财富易手，因为数百万个 AI Agent 将要在互联网上浏览和购买东西。」**

这句话的潜台词非常凶狠：过去二十年，互联网的流量入口是「人类搜索」，SEO 的核心是「让 Google 读懂你的页面」。但未来，流量入口会多出一个庞大到难以想象的「AI 消费者群体」。它们会作为人类的代理，在网站上搜索、比较、加购、下单、预订、管理账户。如果网站只能被「人类的眼睛」阅读，不能被「AI 的程序逻辑」轻松操作，那这些 AI 消费者就会直接绕过你——你的网站甚至不会被 Agent「看见」。

Greg 接着提出了一个关键问题：「一个『对 Agent 友好』的网站或 App 到底是什么样的？你该怎么去构建一个？」这其实是给所有创业者和开发者立了一个新课题。

正是在这个语境下，他引入了那个让他惊讶「为什么没有更多人讨论」的新东西——WebMCP。他的原话是：**「这个由 Google 提出的叫 WebMCP 的小东西，老实说我很惊讶没有更多人在讨论它。它的核心思想很简单：网站可以为 AI Agent 暴露更干净利落的操作动作（Actions）。」** `[视频开场]`

- 通俗解释：就像搜索引擎需要一个 `robots.txt` 来告诉爬虫「你可以抓取哪些页面」，WebMCP 试图做的是：告诉 AI Agent「你可以在这页面上做什么，以及怎么做」。它不是让 AI 像人类一样去猜这个页面是干嘛的，而是直接给 AI 一本「操作手册」——这里有搜索框，这里有预订按钮，这里有购买流程，你来吧。

**个人感受**

Greg 在说到「数十亿美元财富易手」时的语气，带着一种创业者看到「窗口刚刚打开」的兴奋。他反复说「我很惊讶没人在谈」，并直言这让他有点按捺不住。这种情绪贯穿了整期视频——不是焦虑，而是「暴风雨前的宁静」。

**延伸思考**

这让我想到互联网历史上一个类似的转折点：当移动互联网到来时，很多企业不重视移动端适配，结果在 App 时代被抛下。WebMCP 可能是一个同样级别的「适配性转折」——只不过这次使用的不是手机屏幕，而是 AI Agent 的「理解力」。现在没准备的网站，未来可能在 AI 流量上直接被所有人忽略。

### 二、Vinnie 的咖啡机难题：一个让所有「卖家」都心领神会的场景 `[视频前半段]`

**核心观点**：Vinnie 用自己购买咖啡机的真实经历，展示了一个典型的「复杂购买决策」痛点——规格太多、配件太多、信息分散，而这正是 WebMCP 能极大改善的体验。

**深度阐述**

为了让人更好地理解 WebMCP 解决了什么问题，Vinnie 讲了一个自己的故事。他经营着一家咖啡机和周边装备的网店（名为 Crema & Co），他自己热衷于购买咖啡设备。他在节目里说：

> "I was buying an espresso machine and it has like a lot of specifications. It's got a lot of gear and accessories and figuring out which one's right for me. Also which accessories fit was kind of a pain. So, it was a lot of back and forth googling, also putting stuff into an agent or ChatGPT or whatever and like does this fit? Will this work?"

> ——「我当时要买一台意式浓缩咖啡机，它有一大堆规格，还有很多配件和周边装备。要搞清楚哪一台适合我、哪些配件是兼容的，真的很痛苦。我不得不来回谷歌，还得把参数扔进 ChatGPT 之类的工具里问『这能兼容吗？这个能用吗？』」 `[视频前半段]`

这是一个非常生活化的痛点：你不是不想买，而是「怕买错」。当你面对一个拥有几十种规格、配件命名规则各不相同（有的用尺寸、有的用名字、有的是品牌名）的商品页面时，人类自己都头大，AI Agent 更头大。Vinnie 心想：如果有一个网站能把「AI Agent 可以执行的操作」直接暴露出来，那么用户只需要在自己的 Agent 里说一句话，「帮我找台能做两杯 flat white、宽度不超过 32 厘米的咖啡机」，Agent 就能直接与网站对话，甚至完成对比、推荐、加购。

他在节目里当场演示了这段对话：输入「我想从现在的 Mara X 升级，要能轻松每天做两杯 flat white，并且能放进我 32 厘米宽的台面」。屏幕上的 WebMCP 工具立刻调用了网站数据，筛选出两款符合要求的机器，并且自动把它们「并排对比」；更有趣的是，它还会高亮出这些机器与需求相关的关键规格——是否兼容你现有的粉碗、能否满足两杯出品量、宽度是否符合台面限制。整个过程没有让用户去翻十页产品说明书，也没有让用户复制粘贴一堆参数。一秒钟，答案自己浮出来。

**视觉/结构信息描述**

视频中在演示时，画面右侧出现了一个浮动的工具列表，相当于该网站对 Agent 开放的「能力菜单」。里面包含诸如「搜索产品」「获取我的设备」「添加购物车」「应用优惠券」等工具，并且在右边有一个「可用/仅登录可见」的状态标签。演示时，Agent 在对话中完成操作后，页面上会真实地出现商品列表、对比框、以及购物车的变动——它不是只在聊天里回复，而是直接对真实页面进行操作。`[演示画面]`

**个人感受**

Vinnie 在讲到这段时，明显带着一个「硬核咖啡爱好者」的自豪，他说：“我不知道是不是因为我本身就是个咖啡迷……但这段演示真的击中我了。”他背后就摆着一整套咖啡设备。这个场景是真的，痛点是真的，而 WebMCP 恰恰是在这种「复杂、规格繁多、防误购」的场景里，效果最惊艳的。

**延伸思考**

这个例子的价值不仅限于咖啡机。任何「决策门槛高、SKU 多、配件兼容性复杂」的电商品类——比如电脑装机、摄影器材、汽车配件、工业零件——都可能成为 WebMCP 最早的爆发应用场景。因为 Agent 最擅长的就是不知道疲倦地对比规格、消除歧义、并确认「是否兼容」。

### 三、到底什么是 WebMCP？一句话：网站长出「Agent 按钮」 `[视频中段]`

**核心观点**：WebMCP 的本质就是让网站拥有能被 Agent 直接调用的「动作按钮」，它相当于在传统网页之上建立了一层「agent-readable/agent-actionable」的工具层。

**深度阐述**

Greg 在节目里自己做了那个堪称精准的概括：**「简单来说，WebMCP 就是带有 Agent 按钮的网站。我们是在让网站变得可被 Agent 阅读、可被 Agent 操作。对吗？」** Vinnie 马上点头：「没错。」

这句话值得拆解。常规的网页是由 HTML、CSS、JavaScript 组成的，人类看网页时，大脑会理解「这是一个搜索框」「这是一个加购按钮」「这是一个结算台」。但 AI Agent 之前要看懂网页，只能靠两种笨办法：其一，抓取整个 DOM（就是网站全部的后台代码）——一个网站可能有几千行代码，其中 90% 对完成任务毫无帮助，Agent 必须自己在一团乱麻里找出「哪个按钮是干嘛的」；其二，模拟人眼去截图，然后像人一样「看」屏幕去点击。这两种方式都极其低效且脆弱——只要页面布局改一下，Agent 就可能会迷路。

WebMCP 彻底改变了这种逻辑。**网站主动告诉 Agent：我现在给你提供一套工具菜单，这套工具定义了你可以在这个网站上做的所有事情，并且每种工具都有明确的执行方式。** 比如一个咖啡机商店可以提供：

- `search_machines(筛选条件)`
- `compare_machines(机器A, 机器B)`
- `get_my_gear()`（获取该用户已购设备，用于兼容性判断）
- `get_cart()`
- `apply_coupon()`
- `checkout()`

于是，Agent 不再需要理解整个网页，只需要像一个「熟练的 App 用户」一样调用这些工具。效率从「扫描整个 DOM」降到了「直接调用 API」。Vinnie 在演示时说：**「看屏幕上正发生的一切——它操作了网页，找到了两款机器，把它们并排放好，甚至还高亮了与我要求匹配的关键特性。」** `[视频中段]`

更让人兴奋的是，**这些工具不是写在某个独立服务器上的，而是直接通过浏览器会话暴露出去的**。也就是说，你不用重新搭一套后端架构，你的网站仍然是一个普通的网站，只是它现在多了一层「Agent 接口」。

**视觉/结构信息描述**

视频中的工具列表是浮在演示页面上方的半透明面板，列出了多种 action 的名称，例如「搜索产品」「对比机器」「获取我的设备」「获取购物车」「添加优惠券」等。列表分成了「始终可用」和「登录后可用」两栏，Vinnie 登录后和退出登录后，列表里的工具数量会发生明显变化。这给观众非常直观的概念：WebMCP 的「工具可见性」可以跟随用户身份状态而改变。`[演示画面]`

**个人感受**

这段解释最打动人的地方在于：Greg 用一个非常朴素的词把它说透了——「Agent 按钮」。这个概念一出来，你瞬间会意识到：这不仅仅是技术，而是一种全新的产品设计范式。网站从此要开始思考「我们能为 AI 做点什么」，而不是只思考「我们能为人类展示什么」。

**延伸思考**

如果你经营一家 SaaS 公司，你可以把 WebMCP 理解为「为 AI 提供产品试用版的入口」；如果你经营电商，你可以把它理解为「24 小时在线的智能导购」；如果你经营内容站，你可以把它理解为「让你成为 Agent 被引用来源的新方法」。一旦开始这样想，可能性会指数级增长。

### 四、WebMCP 与其他方案的竞争格局：为什么「中间层」是最优雅的答案 `[对话中段]`

**核心观点**：Vinnie 用一张「光谱图」展示了 Agent 与 App 交互的五种主流方式，从完全无界面的 headless 到被限制在某个 App 内的 In-App Agent，而 WebMCP 恰好处于最合理的中间地带。

**深度阐述**

Vinnie 引用了 Cloudflare 的 Dylan 在 Twitter/X 上的一句流行感慨：**「我不想用你的产品里的 Agent，我想让我的 Agent 能高效地使用你的产品。」** `[对话中段]`

这句话语气很轻，打击面却很重。它批判的是那些靠「App 内小助手」圈住用户的思路——比如你打开某个 App，里面有一个内置聊天机器人，但你只能用这个机器人干它被设定好的活，不能把你自己的、带着全量上下文记忆的 AI Agent 带进来。用户越来越不愿意被锁定在某个产品的 Agent 里，他们希望自己的通用 Agent（比如 Claude、ChatGPT、Grok 等）能直接去任何网站完成任务。

Vinnie 为此展示了一张图，把 Agent 连接 App 的几种方式按「离 UI 的距离」从左到右排开：

1. **Headless（无头）**：完全没有界面，Agent 直接打 API。这种方式集成成本高、认证麻烦，而且 Agent 无法操作 UI。
2. **MCP Server（传统 MCP）**：在 App 后端之上再加一层 MCP 协议层，Agent 可以调用工具。但它无法直接操作 UI，而且部署复杂度更高。
3. **Computer Use（计算机使用）**：Agent 模拟人类操作一台电脑，通过截图、点击屏幕来完成任务。这种方式极其“暴力”但目前又慢又脆弱，因为截图识别和坐标点击很容易因为一点点布局变化就失败。`[对话中段]`
4. **Browser MCP（浏览器 MCP）**：Agent 拿到整个网页的 DOM 代码，自己解析 HTML、决定点击哪里。这比截图好一点，但依然是在“读海量代码”，比较脆弱。
5. **WebMCP**：网站主动暴露工具，Agent 通过浏览器会话调用这些工具。效率和稳定性远超前两种。
6. **In-App Agent（App 内 Agent）**：每个 App 内置一个自己的 AI 助手，用户只能跟它对话。这是 Dylan 在推文里抱怨的模式，因为它把「用户个人的 Agent 记忆」和「App 的功能」割裂开了。

WebMCP 的特殊之处在于，它一方面兼容了「任何 Agent 都可以用」（Bring Your Own Agent），另一方面又不需要像 API 那样处理复杂的认证和 token；因为**它直接复用了浏览器的登录会话**。Vinnie 用一句话点出了它的技术核心：**「用 WebMCP，你只需要登录你的网站，你的 Agent 就自动拥有了相应的权限，因为所有状态都保留在浏览器会话里。」** `[对话中段]`

**视觉/结构信息描述**

这张演示图从下往上排列了一连串的「Agent 与 App 接触方式」，最底部是 Headless，往上依次是 MCP、Computer Use、Browser MCP，然后处在中间偏右的是 WebMCP，而最靠右则是在 App 内嵌的 Agent 侧边栏。Vinnie 在讲解时用鼠标在图上指来指去，并多次强调 WebMCP 解决了「既要效率又要灵活性」的两难问题。`[演示画面]`

**个人感受**

这部分信息量最大，但是画面语言很清晰。Vinnie 不是在讲一个孤立的新 API，而是在讲一个「生态位」：当所有人都冲向「全自动 Agent」时，WebMCP 提供了一个更务实、更稳妥的过渡方案。这让人想到早期 Google Maps API——它不强迫你变成一个导航 App，但它让任何网站都能变成一张地图。

**延伸思考**

对于创业者和产品经理来说，这张图其实就是一个路线图。你不必一上来就做全套 MCP Server，也不必搞一个昂贵的 Computer Use 系统，你可以先给网站加一层 WebMCP 工具层，让通用 Agent 先能用起来。这是目前成本最低、见效最快的「AI 化」路径。

### 五、条件工具的魔法：登录状态即权限，天然解决认证难题 `[对话中段]`

**核心观点**：WebMCP 支持「条件工具」——随着用户登录状态、浏览器会话状态的变化，网站暴露给 Agent 的工具集也会动态调整；这解决了以往 Agent 认证接入的最大痛点。

**深度阐述**

Vinnie 在演示时切了一下屏幕：当他处于登录状态时，那个网站的工具列表里出现了很多高权限动作——「获取我的已购设备」「应用优惠券」「查看购物车」「结算」等；而当他退出登录后，再次刷新，工具列表瞬间只剩下三个基础公共同步工具，比如「搜索产品」「查看热门商品」等。`[演示画面]`

这个能力听起来平平无奇，但它解决的其实是 Agent 商业化里最头疼的一环：**认证与授权**。过去你想让 Agent 帮你完成下单、查订单、使用优惠券等操作，最麻烦的就是它如何证明「我是我」。走 API 方案，用户得去申请 API key、把密钥交给 Agent、处理 token 过期；走 MCP Server 方案，同样要配置一堆 OAuth 流程，普通用户根本搞不定。而 WebMCP 直接建立在浏览器会话之上——

- 你在网站上正常登录，你的 Agent 就自然继承了你的身份；
- 你没登录，Agent 就只能用公开工具。

这意味着**线下的身份系统完全被复用**，不需要额外开发任何认证基础设施。Vinnie 的原话是：**「这是让 App 变得 Agent-Native 最不技术化的方式，却同时拥有最大的灵活性。」** `[对话中段]`

**个人感受**

你可能不一定能立刻体会开发者听到这个会有多爽：过去为了解决「Agent 怎么安全地代表用户操作」这个问题，工程师们要设计 token、权限、审计、API 网关……而 WebMCP 用一句「浏览器替你搞定」就把复杂度抹掉了。对于不懂 API 的小商家来说，这是一个天大的利好——他们不用懂技术，只需要保证网站有一个正常的会员系统就够了。

**延伸思考**

但这同时引出一个新问题：浏览器的安全边界会成为 Agent 的安全边界。如果用户在自己电脑上登录了网站，然后让 Agent 操作，这个 Agent 能做的操作上限就是「用户手动登录后能做的事」。各家 Agent 厂商如何监管这种权限，会是接下来非常值得关注的合规话题。

### 六、从 SEO 到 AEO 再到 WebMCP：搜索引擎的权力交接 `[对话中段]`

**核心观点**：SEO 时代看「Google 能不能理解你的页面」；AEO（Answer Engine Optimization）时代看「AI 能不能引用你的答案」；而现在的 WebMCP 时代，看的是「Agent 能不能在你的网站上完成任务」。

**深度阐述**

Greg 在这里贡献了整个节目中最具战略视野的一段话：

> "One of the reasons I think this actually matters is if you think about SEO, right? It was like can Google understand the page and then we had AEO which is can AI cite the answer. And now we're entering this WebMCP era which is basically can the agent finish the job?"

> ——「我认为这件事真正重要的原因，你可以回顾一下 SEO：当年的问题是『Google 能不能理解页面』，然后我们经历了 AEO——『AI 能不能引用我的答案』。而现在我们正在进入 WebMCP 时代，核心问题变成了——『Agent 能不能在你这儿把活干完？』」 `[对话中段]`

这三句话串起来的脉络特别清晰：互联网的商业价值，永远取决于「流量入口」的形态。搜索引擎时代，流量的终点是「让用户点击你的链接」；AI 问答时代，流量的终点是「让 AI 引用你的信息」；而到了 Agent 时代，流量不再是「看」和「点」，而是「执行」——Agent 会直接在网站上完成预订、采购、申请、操作。

所以，Google 和微软之所以联合发起 WebMCP，不仅仅是为了技术进步，更是在赌一个繁荣的「AI 经济体」——如果整个互联网对 Agent 不可用，那么 Agent 的使用场景就会受限，大模型的价值就会打折扣。Vinnie 也补充道：**「他们不想看到一个残废的互联网。」** `[对话中段]`

**个人感受**

Greg 说这句话的时候，你能感到一种「格局打开」的激动。他不只是在讲一个技术，而是在把 WebMCP 放到「流量变现的漫长历史」里，让你看到它正处于一个新纪元的起点。

**延伸思考**

如果你的公司现在还在每月花钱买 SEO 关键词广告，或者还在做「让 AI 引用你」的内容营销，那么你很容易忽略「让 Agent 直接完成转化」的新战场。这个新战场不是关于流量，而是关于「交易权」。谁先让 Agent 能顺畅地代表用户完成整个交易闭环，谁就可能在未来 AI 经济里占据最耐用、最难被绕过的卡位。

### 七、不止咖啡机：WebMCP 的行业金矿地图 `[对话中段-后段]`

**核心观点**：WebMCP 最适合的场景具有共性——复杂、高决策门槛、规格兼容、受监管或需要身份验证。电商、SaaS 管理后台、受监管行业（保险与银行）及企业内部工具是最佳切入点。

**深度阐述**

Vinnie 实际上不只是在演示一个咖啡店。他后来又对 Agent 说：「你推荐的这款 Liz Bianca 很不错，再给我推荐一些合适的配件吧。」于是 Agent 立刻调用了「get my gear」工具，识别出用户已购买的设备，再与商店当前商品做兼容性匹配，直接推荐了一款「Litz 净水器双件套」，并询问是否加入购物车。当用户确认后，它甚至自行调出优惠券「BARISTA10」，在结账页应用了 10% 折扣。全程用户只需要点头确认。`[演示画面]`

这段演示最大的魔力在于：Agent 不是简单地返回一系列商品链接，而是**基于商店的实时上下文、用户的历史数据和偏好，直接完成了一次带交易动作的「导购 + 结账」**。

那么这种体验可以复制到什么行业？Vinnie 给出了非常清晰的分类：

- **复杂兼容型电商**：相机系统、电脑硬件、咖啡器材、汽车零配件。凡是「规格多、容易买错」的商品，Agent 都能大大降低用户的决策成本。
- **SaaS 管理后台**：任何管理后台、控制台、数据分析面板、营销工具。内部团队可以用自然语言让 Agent 完成「建报表、修改配置、批量操作」等任务。
- **受监管行业**：保险、银行、医疗等。它们天然不适合让用户把自己的 API key 交给 Agent，但可以用 WebMCP 做出「只读」或「低敏感操作」的工具，帮助用户查询信息、找到入口、总结条款。
- **企业内部工具**：哪怕不对客户开放，你也可以用 WebMCP 优化员工的操作流程。`[对话中段-后段]`

Vinnie 特别指出：**「这些领域里，WebMCP 最妙的一点是你可以只用只读工具，不触碰任何敏感操作，这样既安全，又确实能提升体验。」** `[对话中段-后段]`

**个人感受**

Vinnie 在讲解时完全没有在念 PPT，他是在「分享一个自己刚刚亲手做出来的成果」。你能从他的语言里听出一种「终于找到一个优雅方案」的成就感。他说到「我不知道是不是只有我这种咖啡控才这么激动」时，那种略带自嘲的真挚，让整段技术演示变得非常有温度。

**延伸思考**

如果让我补充，我觉得旅游行业（机票、酒店，行程组合复杂）、本地生活服务（预约、比价、取消）、甚至招聘平台（匹配岗位、筛选简历）都可能在 WebMCP 上找到爆发场景。这个工具的真正意义不是「客服」，而是「把可重复的交易流程变成可被 AI 直接驱动的管道」。

### 八、创业机会一：Agent 转换代理机构（WebMCP Conversion Agency） `[视频后半段]`

**核心观点**：立即着手为传统的「无聊行业」（律所、牙医、HVAC、医美、家装）搭建 WebMCP 工具，把他们变成「Agent-Ready」的网站，收取搭建费和月费，并且可以通过打包 MCP、内部工具等增值服务做成长期现金流生意。

**深度阐述**

Greg 亲自出来分享了第一个可以立刻起步的商业模式。他说：

> "The first idea is a WebMCP conversion agency. How can you make boring business websites agent ready? These boring businesses like law firms, home service, HVAC, med spas, dentists. You just go and create V1 tools for them. That can be requesting a quote or booking consults."

> ——「第一个想法是 WebMCP 转化代理机构。你怎么把无聊的生意网站变得对 Agent 友好？比如律师事务所、家政服务、暖通空调、医美、牙医……你只需要去帮他们创建第一版工具，比如『获取报价』或『预订咨询』。」 `[视频后半段]`

Greg 想做的事是教育这些行业：未来互联网上会出现一批新的「AI 访客」，这些访客会通过 Agent 直接预订服务。如果你的网站不能对 Agent 说「你可以来预订我的服务」，那么这些 AI 消费者就会被竞争对手接走。

商业模式的骨架是：

- **搭建费**：一个 V1 工具包，收 $200～$10,000，按客户规模浮动。
- **月费**：每月 $500～$700 左右，负责监控、迭代、更新工具。
- **后续叠加销售**：不仅做 WebMCP，还可以顺手做传统 MCP Server、内部员工效率工具等，做成一个「Agent 化全家桶」。

Greg 还特别提到，现在就有机会去抢注 `webmcp.com` 之类的域名，哪怕只是做一个展示性的落地页，都能吃到这波「新词红利」。`[视频后半段]`

Vinnie 补充说，WebMCP 是 Google 与微软 2025 年 2 月左右联合发布的实验功能，知道并会用的人极少。这恰恰意味着**第一批向传统企业销售「Agent 化服务」的机构，可以自封为专家**。他说：**「这是真正的新兴事物，如果现在学，你会拥有先发优势。」** `[视频后半段]`

**个人感受**

Greg 聊这个商业模型时，注意力很集中。他是真的认为「帮无聊公司做数字化改造」是一台久经考验的印钞机：过去是为他们建网站，后来为它们做 SEO，现在则可以把他们「Agent 化」。这种生意没有性感的技术难点，但现金流极其稳定。

**延伸思考**

这种模式很容易被复制，但第一个吃螃蟹的人往往能吃到最大的红利。你可以用「代理机构」的定位去积累二十个客户案例和口碑，然后在行业成熟之前，把自己升级成一个垂直领域的「Agent 化 SaaS」。这是典型的「服务 → 产品 → 平台」演进路线。

### 九、创业机会二：Agent 神秘顾客（Agent Mystery Shopper） `[视频后半段]`

**核心观点**：创办一项「Agent 验收」服务——用 AI Agent 去访问客户的网站，执行最重要的用户旅程（下单、预订、提交表单），然后输出一份报告，指出 Agent 是在哪里卡住、哪些描述有歧义、哪些流程缺少 Agent 工具支持。

**深度阐述**

第二个商业点子，本质上是把「测试」变成商品。Greg 的原话是：

> "I'm calling it the agent mystery shopper. It's testing whether agents can complete the most important user journeys. So if you think about a user journey, maybe it's a Shopify store... It's filing a claim, requesting quotes, ordering items. All these different things that you want the agent to do. So, the agent is going to run a bunch of tests and you, the customer, get a report back. Where did the agent get stuck? Were there bad descriptions? Were there missing tools?"

> ——「我管它叫 Agent 神秘顾客。就是测试 Agent 能否完成最重要的用户旅程。用户旅程可能是 Shopify 商店的购买流程，也可能是保险公司的理赔申请、报价请求、商品下单。Agent 会运行一堆测试，然后你的客户收到一份报告：Agent 在哪里被卡住了？是不是描述有问题？是不是缺少工具？」 `[视频后半段]`

这个商业模式太妙了，因为它把焦虑变成了产品。

- 对任何一个认真做 AI 流量布局的公司来说，「我的网站到底能不能被 Agent 跑通？」是一个必然会问的问题。
- 你提供一份像「信用报告」一样的 Agent 友好度评估，指出转化风险点，并给出修复建议。这天然就是一次「被需要的销售入口」——报告末尾再加一句「我们也可以帮你修」，就和上一个 Agent 转换代理机构完美闭环了。

收费标准：几百美元一次，或者做成按月订阅（每月固定跑几轮测试，持续监控）。

Vinnie 对这个想法直接表示认可，并说这个业务甚至可以打包进第一个代理机构服务里，作为一个「诊断阶段」的产品，用来挖掘客户需求。`[视频后半段]`

**个人感受**

这个点子很「Greg Isenberg」——看似简单，却直击痛点。因为绝大多数创始人根本不知道现在自己的网站对 Agent 的「友好度」是多少。这个不确定性本身就是卖点。

**延伸思考**

未来这种「Agent 用例测试」可能会成为像「网站渗透测试」一样的标准品。谁能先建立起一套通用的「Agent 旅程评分体系」，谁就有可能成为这个细分领域的事实标准。这个赛道听着不热闹，但天花板可能很高。

### 十、现在就上手：如何立刻玩转 WebMCP `[视频结尾]`

**核心观点**：WebMCP 是 Chrome 里的实验性功能，可以通过开启 Chrome flag 和远程调试来体验；官方提供了包含 16 个工具的示例咖啡店网站，以及一个 GitHub 开源仓库，所有人现在就能免费上手。

**深度阐述**

讲完商业机会后，Vinnie 给了最实在的「行动指南」。他展示的示例网站是 `cremaandco.clientfly.dev`——Demo 站点上已经内置了 16 个 WebMCP 工具，任何有 Chrome 浏览器的人都可以立刻体验。

但因为是实验功能，你需要先打开两个设置：

1. **Chrome Flags**：进入 `chrome://flags`，开启 WebMCP 支持。
2. **Chrome Inspect**：开启远程调试（remote debugging），这样 Agent 才能与浏览器会话联通。

此外，如果你想自己构建一个带 WebMCP 的网站，可以直接从视频中提到的 GitHub 仓库克隆代码（在页面上点右上角 WebMCP 工具旁边那个 repo 按钮），整个项目免费开源。Vinnie 鼓励大家：**「把它 clone 下来，改成你自己的版本，开始玩一些有趣的商业想法。」** `[视频结尾]`

Greg 最后不忘给那些总觉得「太早」的人一个警钟：

> "Why even bother playing with this stuff? I love playing when things are experimental because when the arbitrage exists, it's when it's experimental. I love trying things, getting my hands dirty, and seeing what I can build now because when it's going to be super popular, that's when that window starts closing."

> ——「有人会说，这太早期了，为什么要折腾？但我就是喜欢在实验阶段玩东西，因为套利的机会就存在于实验阶段。我喜欢动手尝试，看看现在能建出什么，因为等它变得超级流行时，机会窗口就开始关闭了。」 `[视频结尾]`

这个观点和「当你知道一件事是机会时，它往往已经不是机会了」异曲同工。Vinnie 还补充了一个历史参照：当年 GPT-2、GPT-3 刚出来时，也有无数人嗤之以鼻说 AI 距离真正改变世界还早得很，结果没几年 ChatGPT 就引爆了一切。WebMCP 的提案其实在两年前（2023 年）就有了雏形，今年才正式上线，Google 为此准备了很久。**如果你只因为「它还是个实验功能」就视而不见，你大概率会错过第一波红利。**

**个人感受**

Greg 这段话是真的热血。他不是在主持一档访谈节目，而是在向观众发出一条邀请：现在进场，你还有机会做那个「第一批吃螃蟹的人」。而 Vinnie 的那句「我们说的是 Google，他们有很好的眼光」，也给观望者提供了一颗定心丸。

**延伸思考**

「实验功能」四个字里，藏着两种态度：一种人看到「不稳定、不成熟」，另一种人看到「没有标准、没有巨头垄断、有重新洗牌的机会」。WebMCP 目前正处于这个「混沌阶段」。正如移动互联网初期，www 网站转 App 时，早期做响应式网站的那批开发者都赚到了钱；今天，你如果能在 WebMCP 方兴未艾时把技术吃透，那将是极其稀缺的先发技能。

## 延伸思考：WebMCP 预示着什么样的 AI 经济？

WebMCP 表面上是一个浏览器功能，但它背后预示的，其实是一种全新的「人机界面」模型：

1. **未来的搜索不再是「返回链接」，而是「完成任务」**。Agent 会成为消费者与商业世界之间的中间人，而 WebMCP 就是它们用来「交易」的通用语言。
2. **网站的价值将从「内容展示」变为「工具的可用性」**。一个没有 WebMCP 的网站，可能仍对人有价值，但对 AI 驱动的流量来说，就是一座无法进入的孤岛。
3. **自然语言将变成「新的 API 浏览器」**。普通人不需要懂技术，因为他们手里的 Agent 可以直接读取网页工具列表并执行。技术门槛大幅降低，谁的产品对 Agent 更友好，谁就能赢。
4. **权益与隐私问题会被重新定义**。当 Agent 拥有浏览器会话时，它们到底能不能代表用户做出「有约束力的交易」？这将倒逼平台设计新的授权体系。

这个方向极其值得我们继续追踪。也许在一年后我们再回来看这期视频，会像现在回看 2019 年讨论「为什么大家的网站都要做成响应式」一样，觉得理所当然。

## 精华收获

- **WebMCP 正处在 AI 商业模式的最新窗口期**：它让网站可以向 AI Agent 暴露「工具按钮」，使 Agent 能够直接完成搜索、预订、购买等任务，这可能是继 SEO、AEO 之后新的流量红利。
- **它最适用的场景是「复杂决策型」交易**：高规格、重兼容性、需要比较和确认的商品（咖啡机、相机、电脑硬件、车零件、保险与银行服务）是最早的落地场景。
- **它解决了 Agent 认证的痛点**：通过复用浏览器登录会话，WebMCP 避免了传统 API Key 和复杂鉴权流程，任何通用 Agent 都能即插即用。
- **两个可以立刻启动的创业方向**：
  - **Agent 转换代理机构**：帮传统行业把网站变成 Agent-Ready，赚搭建费和月费；
  - **Agent 神秘顾客**：专门测试并报告网站的 Agent 友好度，作为独立的诊断服务。
- **现在就动手**：去 Chrome flags 开启 WebMCP 支持，体验官方 Demo（cremaandco.clientfly.dev），克隆 GitHub 仓库开始构建自己的第一个 Agent 工具层。
