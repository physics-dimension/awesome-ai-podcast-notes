# 五个 GitHub 开源项目：在智能体时代抢占先机、赚钱提效

我不确定你怎么想，但我最近在 GitHub 上花的时间越来越多了。原因很实在：**GitHub 已经成为“智能体时代”获取不公平优势的最佳去处之一**，因为你能在这里提前看到那些 6 个月后才会被广泛讨论的工具。很多最终会变成 SaaS 公司、代理机构、工作流和创业想法的东西，首先会出现在 GitHub。就像那句名言：**未来已经到来，只是尚未均匀分布。**

所以，在今天的节目里，我尝试做点新东西：翻遍了最近 30 天备受关注的很多 GitHub 仓库，挑出了我认为你应该知道的五个。无论你是想构建产品、赚钱、节省时间，还是只是想让 AI 帮你完成更多任务，这些仓库都值得一看。有些偏技术，但我会用通俗语言解释：每个仓库是做什么的、为什么重要、怎么用，以及你今天怎么亲自尝试。

需要说明的是，其中最后一个来自 NVIDIA，另外几个来自小型开发者。每一个我都能想象有人用它赚钱或节省大量时间。这五个仓库完全免费且开源，意味着代码可以免费使用；但你也知道，其中一些有依赖，例如有一个依赖 **11 Labs（ElevenLabs）**，那是要花钱的，请注意。

我们开始吧，最后见。如果你还没有点赞、评论和订阅，现在就去点一下吧，让算法的信息流里充满这类有价值的内容。

## 1. No AI Slop Skill（Peter Yang）：去掉 AI 味，保留你自己的声音

第一个仓库是我朋友 Peter Yang 的 **No AI Slop Skill**。推荐它是因为每个用 AI 写作的人都遇到过这个确切的问题：你让 ChatGPT 或 Claude 帮你写点东西——一条推文、一篇 LinkedIn 帖子——从技术上看文字没问题，语法也对，句法也对，但总有一种奇怪的味道。可能听起来过于精致、过于对称，或者太公式化；有时是“不是 X，而是 Y”这种句式，有时是频繁使用“quietly（悄悄地）”这类词。我觉得，这就像在阅读一场假的 SaaS 大会的主题演讲。一旦你注意到这种味道，就再也无法无视它了；现在很多人都能“闻”出来。

真正酷的地方在于，Peter 的这个技能本质上是一个编辑器：它会移除这些 AI 模式，同时尽量保留你本人的声音。最后这一点很重要，因为很多写作工具会让你的文字更干净，却也磨掉了那些有趣的部分，让所有人听起来都一样。如果你和别人听起来一样，就很难脱颖而出——你其实想做相反的事。

这个仓库会寻找那些让文字感觉像 AI 生成的模式，帮助草稿读起来像真人写的。为什么这很重要？如我所说，如果你今天在构建产品，你无时无刻不在写作，而且希望自己脱颖而出。我个人就在写推文、落地页、冷邮件、发布帖子、产品更新、新用户引导文案；如果你有投资人，你还要写投资人更新。你不想听起来像通用 AI，因为人们会感觉到。他们也许不会说“这是 AI 写的”，也不会明确回复告诉你，但他们就是不那么信任你了。他们只会继续下滑，不回复；他们甚至可能不会相信你说的话，因为他们觉得这是 AI 写的。所以这个仓库与其说让写作更好看，不如说是**让你的沟通更可信**。

如果你想试试，可以把它安装成一个技能（skill）。我建议这么做：输入 `npx skills add`，然后粘贴 GitHub 链接。所有仓库的链接我都会放在节目笔记和视频描述里，方便你直接操作。然后，你可以在自己的智能体工作流中使用它。实际用法我会这样跑：先写一个粗略草稿——我不会让 AI 从头凭空生成全部内容；先写大纲，把真实要点写下来，哪怕很乱；然后让这个技能去除 AI 打磨痕迹，同时保留你的语气。

这就是值得思考的工作流：**首先有人的想法，其次是 AI 清理**。这和现在很多人创作内容的方式不同——他们要么直接让 AI 写一切，试图一次成型，然后又说“这看起来不好”。而这种“人机混合”的方法非常有意思。这是第一个。

## 2. TryCompAI 的 CRM：让智能体替你维护客户关系

第二个仓库是 TryCompAI 推出的开源 **CRM**，一个为 AI 智能体构建的 CRM。听起来有点技术，甚至有点无聊，我会尽量拆解得简单，让你明白如果正在创业，如何真正从中获得价值。

普通 CRM 是存储关系、客户和线索的地方；基本上是一个包含姓名、邮箱和备注的数据库，有时还有销售阶段。问题在于，几乎所有的 CRM 都依赖你亲自维护：你得记得更新联系人，记得上次聊了什么、对方说过什么、谁冷淡了，基本上要让 CRM 保持干净。因此，如果你和我差不多，你曾经有过一个 CRM，然后它变成了“墓地”，你慢慢就不再更新了。刚开始很兴奋，几周后数据陈旧、笔记混乱，于是你停止更新；那些本来可能让你赚钱的人，最终躺在一个没人愿意打开的工具里。

这个仓库有趣的地方在于，它把你的 CRM 当作**智能体的工作空间**，而不是你的文件柜。智能体可以查看记录、研究人物、丰富公司信息、安排跟进，并让笔记保持最新。基本上，你不想做的那些琐事，它都能替你做。整个“AI CRM”的理念是：它不只是存储信息，而是替你维护关系图谱。如果你是创始人，这很重要，因为大多数企业失败并不是因为缺少机会，而是机会散落各处。你半年前收到一个热情的介绍，或者一个客户说“之后再来找我”，然后你就忘了。那些邮件里藏着真金白银。

所以这里的使用场景不是替代 Salesforce，我只是提一个比较有用的场景。我会这样做：假设我在为播客找赞助，我可以通过它跑我的赞助管道；追踪代理线索；管理投资人更新（如果有投资人的话）；或者跟进所有加入某个我用 vibe coding 做出来的产品 waitlist 的人；也可以让它完整地处理一个小型 SaaS 的客户成功。

如果我要测试它，我会从一个很小的流程开始：建一个类似“warm leads I can't afford to forget（我不能忘记的活跃线索）”的管道，然后把每个表现出购买意图的人都放进去：回复过邮件、预约过电话、问过价格，或者说“45 天后再联系”“圣诞后再说”的人。然后让智能体做那些艰难的工作来维持这个管道。过去你实际上需要雇一个人来做，现在有智能体为你做：谁需要跟进？我该说什么？他们公司自上次联系以来发生了什么变化？这就是它真正酷的地方。

如何安装？你需要安装 **bun** 和 **Docker**。基本设置是：克隆仓库（链接在节目笔记里），然后运行：

```bash
cd CRM
cp .env.example .env
bun install
docker compose up -d
bun run db deploy
bun run db seed
bun run dev
```

它会在本地运行，通常在 `localhost:3000`，API 在 `localhost:3001`。你需要设置一些环境变量，尤其是认证：如果要登录、使用邮件或日历集成，你需要 Google 或 Microsoft 的 auth 客户端，我猜你会想要。这不是那种一键搞定、一切美化的东西，但它是真实的，是一个“产品形态”的仓库，我觉得非常有意思。

我认为这类东西更大的机会在于：每个人都有 CRM 问题，只是从不这么叫。他们会说“我忘了跟进”“我忘了该给谁发邮件”“我们的线索一团糟”，或者有种“天啊，我在把钱留在桌上”的感觉——我也常常有这种感觉。这些都是同一种痛苦，而这个仓库正好指向了解决办法。更大的想法是：**如何创建真正与你协同工作的关系系统？让智能体实际去做。** 我觉得它很有意思，所以把它放进了清单。

## 3. browser use 的 video use：让编码智能体帮你剪视频

第三个仓库来自 **browser use**，叫做 **video use**，这是我最喜欢的一个，因为你马上就能明白它是做什么的。它让你用编码智能体来编辑视频。你把原始素材丢进一个文件夹，然后让像 Claude Code 或 Codex 这样的智能体去编辑它：它会去除填充词、剪掉空白、添加字幕、调色、构建覆盖层，然后渲染视频，还能检查输出。

现在已经有很多 AI 视频编辑软件了，但这个仓库真正酷的地方在于，**编辑工作流变成了你的智能体能够理解和重复的东西**。想一想：大多数创作者或做内容的人会重复同样几种剪辑；他们有同样的字幕风格。即使你看我的 YouTube 频道，也能看到每个视频风格非常相似：同样的节奏、同样的停顿剪切方式、同样的开场，以及把长对话变成 Shorts 和 Mid 视频的方式。通常这些技能存在于人的大脑和肌肉记忆里。但有了这个仓库，它变得更加显性，智能体可以读取转录文本、查看时间戳、提出剪辑策略、渲染并检查剪辑点。这多酷啊！

因为如果你是创作者或创始人，内容可能是你最大的瓶颈之一。你也知道，就算产品很棒，如果没人看到，你依然会输。所以我认为这个仓库能缩短“原始素材”到“发布内容”之间的距离。

如果我来用它，我不会在第一天就尝试自动化整个 YouTube 频道；我认为那要求太多，很多人使用这类仓库第一天失败，正是因为他们要得太多。我会先做一个小型可重复的格式：比如把一个创始人的 Loom 视频剪成 60 秒的发布视频；或者拿一段播客录音，对自己说“我需要从中剪出三条爆款片段”。这样起步就够了。一旦你有了一个格式，就能把它变成一套系统；一旦成为系统，你就可以自己运行，或者把它卖给其他人。创业想法就在这里，对吧？每个利基市场都需要内容，而且几乎没有人真正喜欢剪辑。房地产经纪人需要房源视频，SaaS 厂商需要产品视频，教练需要精彩片段，广告代理需要不同的广告变体。所有这些公司都有不同的内容创建流程。创作内容常常很有趣，但实际的剪辑工作真的很难。

如果你想尝试，怎么试？它的安装对智能体非常友好。你只需把设置提示粘贴到 Claude Code 或 Codex（或任何有 shell 访问权限的工具）里，例如说：“设置这个 GitHub 仓库，先读 install.md，安装这个仓库，配置 FFmpeg，向我正在使用的智能体注册这个技能，然后在需要时向我要 11 Labs 的 API key。”你也可以手动安装：`git clone`、`ln -sfn` 等等。但对正在收听这个节目的 95% 的人来说，不如让智能体帮你安装。这个很有意思，我觉得你可以试试，看是否适合你，然后告诉我你的想法。

## 4. NVIDIA 的 Skill Specter：在把 AI 技能装进智能体之前先扫描

第四个仓库来自 **NVIDIA**，叫做 **Skill Specter**。这是一个无需多想的安装，因为人们已经开始直接从 GitHub 安装 skills、MCP 服务器、插件和智能体工具。这很令人兴奋，因为它会给你的 AI 增加新能力，但也带来了一个问题：**技能不只是一段文本**，它可以包含指令、脚本、依赖、工具访问权限，基本上可能是改变智能体工作方式的行为；在某些情况下，它还能接触文件、调用工具、连接服务。因此，在从 GitHub 安装随机能力之前，你应该先问一下它是否安全。这正是 Skill Specter 的作用：它可以扫描 AI 智能体技能中的安全问题，比如提示注入、数据外泄、供应链风险、隐藏指令、任何恶意模式，以及 MCP 相关风险。Skill Specter 都会帮你看护。

我考虑它的方式是：**在把你的 AI 交给一个新工具之前，先扫描这个工具。** 这现在之所以重要，是因为 AI 工作流正变得越来越模块化。大多数人今天只使用一个聊天机器人，但构建者已经在组装自己的 AI 工作环境：编码智能体、研究技能、设计技能、可能一个浏览器工具、一个视频工作流。到了某个时候，你的设置开始看起来像一个为你工作的小型操作系统。一旦发生这种情况，安全就不再只是企业问题，而会变成普通构建者或创始人问题。所以我认为这是非常重要的一项。

我和 NVIDIA 没有关联，但如果你想尝试，可以使用 UV 工具。快速安装命令是：

```bash
uv tool install get-plus
```

然后粘贴 GitHub 链接。之后可以扫描一个技能目录：

```bash
skill-specter scan ./my-skill
```

或者直接扫描 GitHub 仓库：

```bash
skill-specter scan <GitHub链接>
```

如果你想要更快的静态扫描，并且不想把文件内容发送给大语言模型服务商，就加上 `--no-lm` 参数。对于扫描敏感文件或私人文件，这个参数很重要。如果你不想在本地安装 Python，也有 Docker 选项。

我一直在想这件事：如果团队要安装 AI 技能和 MCP 服务器，就需要有人帮他们判断什么安全。这可能是一个可信赖的市场、一个安全扫描器、一个公司级别的安装门槛，或者内置在每一个智能体平台中的功能。我很喜欢 NVIDIA 与这个项目有关联，这也是我把它放进清单的原因——它给了整个类别可信度，同时也承认：很多这类技能和插件可能是恶意的，你必须小心。所以我必须把它放进来，必须跟你们说实话。去看看吧。

## 5. Phone Harness：让智能体真正控制你的手机

第五个仓库叫做 **Phone Harness**，它让 AI 智能体可以真正控制你的手机。大多数 AI 智能体工具都是围绕浏览器和终端（也有桌面应用）构建的，这当然合理，因为很多工作都在那里发生。但想想看，现在有大量工作发生在手机上：银行应用、消息、社交、外卖等等。有大量工作流很难自动化，因为唯一真正的界面就是手机屏幕。

Phone Harness 可以把 Codex 或 Claude Code 这样的智能体连接到一台真实的 iPhone 或 Android 手机上。它在 iPhone 上使用 Mac 的 iPhone 镜像功能，在 Android 上使用 ADB。你不需要越狱——我当时想的是“天哪，我什么都不想越狱”——完全不用越狱，不需要 Xcode，也不需要在手机上安装特殊应用。基本上，**智能体能看到屏幕上发生了什么，可以点击、输入、滚动、打开应用，然后验证结果**。

我知道有人会在想：“为什么？为什么这很重要？”如果你正在构建移动应用，想想 QA 测试：你可以让智能体在真实设备上测试引导流程、注册、结账。如果你在构建任何形式的自动化，它可以打开那些没有 API 的移动应用。如果你是创作者，甚至只是运营者，它最终也可以处理 TikTok、Instagram 等平台上的重复性移动工作流。

如果你想尝试，第一件事是测试一个移动端注册流程。非常简单：打开应用，创建账户，点击完成引导，尝试结账，截图，然后告诉我哪里让人困惑或出了问题。这非常宝贵，每个移动团队都应该持续这样做，但大多数团队没有，因为这很无聊，或者他们不想雇人来做，或者他们自己也会犯错。所以这个仓库会帮到你。

想试用的话，仓库会给你一段设置提示，粘贴到 Codex 或 Claude Code 中。基本内容是：“帮我设置 phone harness，克隆这个 GitHub 仓库，读 install.md，安装它，让 phone harness 出现在我的 PATH 中，把它注册为智能体技能，然后读 onboarding.md，带我完成设置。”对于 iPhone，你需要 macOS Sequoia 或更高版本，使用 iPhone 镜像，并授予终端辅助功能和屏幕录制权限。对于 Android 朋友：打开开发者选项，通过 USB 使用 ADB 连接，实际上也支持无线连接。然后运行 `phone harness --doctor` 来检查设置。

这个项目还比较早期，也有局限。有些手机流程无法完美运行，比如锁屏手机会需要你介入，Face ID 和相机流程也比较棘手。但方向是显而易见的：**智能体正在从回答问题走向操作工具，而手机是世界上最大的工具界面之一。** 如果你能搞定其中一些工作流，这里面就有创业想法，对吧？如果你能把移动端 QA 产品化，会有人愿意每月付 100 美元或 500 美元吗？你需要多少客户才能做到每月 1 万美元？

总的来说，这些 GitHub 仓库有趣之处在于：你可以（1）安装它们；（2）然后跑一个小的流程，让它运转起来，增加价值；（3）然后决定是把它产品化给其他人，还是继续用自己的流程去提高生产力、赚钱和创造价值。
