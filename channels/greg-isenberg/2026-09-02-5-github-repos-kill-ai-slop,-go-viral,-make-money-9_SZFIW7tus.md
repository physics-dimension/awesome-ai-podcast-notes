## 第二部分：五大仓库深度解析

### 仓库一：No AI Slop Skill —— 让你的写作告别“AI味” `[段落 1-3]`

**核心观点**
这个仓库是一个“编辑器”，用于去除 AI 写作中常见的“套路感”，保留作者的真实声音。它的意义不在于让文字更漂亮，而在于让你的沟通更可信、更有人味，从而在信息洪流中真正脱颖而出。

**深度阐述**

第一个仓库来自 Greg 的朋友 Peter Yang，名字就叫 No AI Slop Skill（“去AI味技能”）。Greg 说他一看到就觉得“这就是我需要的”，因为每一个用 AI 写过东西的人都经历过那种难以言说的别扭感。

你让 ChatGPT 或 Claude 帮你写一条推文或 LinkedIn 帖子，乍一看，语法没错、文字通顺，但就是有一种奇怪的气味。Greg 试图精准地形容这种感觉：“它听起来可能太完美了，太对称了，太公式化了。” 他举了几个典型的例子：
- 文案里总会出现那种“**不是 X，而是 Y**”的句式；
- 动不动就爱用“**quietly**”（悄悄地）这个词；
- 总而言之，读起来就像在听一场由某个“假 SaaS 大会”上的主题演讲。

这就是如今你在网上到处都能闻到的那种“AI味”。Greg 坦言：“你一旦注意到它，你就没法再无视它了。” 而现在，已经有很多人能秒识别这种味道——当你用 AI 写出来的内容带有这种味道时，读者不一定会明确说“这是 AI 写的”，但他们就是会本能地不信任你，然后默默划走。

这个仓库的奇妙之处在于，它就像一个**专门寻找“AI味”的编辑**：它会主动追踪那些让文字感觉像 AI 生成的模式，并将它们移除，同时努力保留你真正的个人风格。Greg 特别强调“保留个人风格”这一点有多重要，因为很多 AI 写作工具虽然会让你的文字更干净，但同时也会“磨掉你所有有趣的部分”，让所有人听起来都一样。如果你的目标是建立个人品牌或为自己的产品发声，**“听起来和 AI 一样”本身就是一种灾难**——没有人会关注一个没有记忆点的账号。

那怎么用呢？Greg 指出，这个仓库可以作为 Claude 的一个“技能”直接安装。他建议的命令是 `npx skills add` 加上仓库链接（所有链接都会放在视频描述栏中）。安装后，你可以在任何智能体工作流中使用它——只要你手头有一个草稿（draft）。

Greg 给了我们一个非常实用的工作流建议：

> 先不要用 AI 从零开始生成内容。你应该自己先写一个粗糙的草稿——哪怕逻辑混乱、句子不通——把你的人类观点写下来。然后，再让 AI (这个 skill) 帮你去掉那些“AI味”的打磨痕迹，同时保留你的声音。**顺序应该是：人类想法在前，AI 清理在后。**

这与他观察到的如今大多数人的内容生产方式正好相反。很多人习惯让 AI 一次性写出所有内容，如果不好看就再来一次——这就像“咒语式”的赌博。而 Greg 更推崇这种“人机混合”工作流：你先贡献最核心的“血肉”，AI 只负责做外科手术式的清理。

**个人感受**

Greg 在讲这个仓库时，情感上是很有共鸣的。他几乎以“受害者”的身份在描述 AI 写作的通病——毕竟他自己每天都在写推文、写落地页、写冷邮件、写发布文章和产品更新。当你几乎所有的对外沟通都依赖文字时，“AI味”不仅影响美观，更直接影响客户的信任和转化。他不希望自己像一个“读着假 SaaS 大会主题演讲”的机器人。

**延伸思考**

“AI味”的本质是什么？是模型通过概率统计得出的“最安全、最平庸”的表达。它们确实挑不出语法毛病，但也因此失去了人性中的“不确定感”和“个性”。再深入一点，这其实反映了这个时代最核心的矛盾：AI 让内容生产变得前所未有的容易，但**有价值的从来不是“生产”，而是“观点”**。那些在 AI 时代仍然能吸引眼球的创作者，必然是那些拥有独到见解、并且懂得如何用“人类方式”表达的人。

**精华收获**

- 别再做“AI 生成、人类删改”的低效循环，要反过来：**人类负责想法，AI 负责去味**。
- 这个工具的核心价值不是“让文字更好看”，而是“让你的话更可信”。
- 如果你是个创始人或要在网上发声的人，消灭“AI味”是在信息洪流中站住脚的第一步。

### 仓库二：CRM by trycompai —— 让 AI 帮你维护关系的“活”客户系统 `[段落 4-8]`

**核心观点**
这是一个专为 AI 智能体构建的开源 CRM (客户关系管理工具)。它不像传统 CRM 那样只是一个“文件柜”，而是一个“工作台”：AI 可以自动研究人、补充公司信息、安排跟进、更新记录，帮你维护那张最容易被忽视的“关系网络图”。

**深度阐述**

第二个仓库的名字听起来有点技术又有点“无聊”——CRM (客户关系管理)。但 Greg 强调，请千万别被这个名字劝退，它可能是你未来生意的“隐形提款机”。

首先，让我们理解传统 CRM 为什么总是让人心累。一个正常的 CRM，其实就是个数据库：你存下客户的姓名、邮箱、备注，有时候再加个销售阶段。**问题在于，几乎所有 CRM 都依赖“手动输入”**——你必须在每次沟通后自己去更新状态、记住上次聊到哪了、谁冷了、该给谁发封邮件。Greg 用自嘲的方式形容这种体验：“如果你和我一样，你曾经也用过某个 CRM，最后它变成了一片‘墓园’，你开始彻底停止更新它。一开始你充满动力，几周后数据就发霉了，备注一团乱，然后你干脆不打开它了。”

结果就是：**那些真正可能让你赚到钱的人，躺在了一个没人想打开的工具里。** 这简直是现代商业中最常见的“慢性自杀”。

而这个来自 trycompai 的仓库，逻辑上完全变了：它**把 CRM 从“你的文件柜”变成了“智能体的工作台”**。它不是让你去维护信息，而是让 AI 代理去主动干活——比如：
- 查看记录，**研究**客户；
- **丰富**客户的公司信息；
- **安排**后续跟进；
- **随时更新**记录。

那些你不爱干的、重复性的“填表工作”，AI 全接手了。更超前的是，Greg 提出一个概念：**AI CRM 的目标不是“存信息”，而是替你自动维护“关系图谱”**。这意味着它不只是被动记录，而是主动让关系保持活络。

这个工具对创始人来说尤为关键。Greg 一针见血地指出：“大多数公司不是死于缺乏机会，而是死于机会散落各处。” 他举例：你半年前收到一个热情的引荐；一个客户说“过段时间再联系你”；一个潜在合作方让你“圣诞节后再聊聊”……这些都有可能变成真金白银，但它们全都散落在你的邮箱和记忆里，直到被彻底遗忘。

但 Greg 也不太建议你用这个去直接“干掉 Salesforce”，他更推荐一个更现实的切入点。比如，假设你是在为自己的播客找赞助商，你可以用它跑通整个赞助流程；或者用它管理代理机构的线索；用它维护投资者月报；甚至是**跟进所有注册过你“随便 vibe code 出来的产品”的等待名单用户**。对于一个小型 SaaS 公司，它甚至可以完全接管客户成功。

想试试看？Greg 给出了非常具体的入门路线：先从一个小的“工作流”开始，比如建立一个名为 **“我不能忘记的的温暖线索”** 的管道，然后把你接触过的每一个“有购买意向但还没买的人”放进去——比如回复过你邮件的人、约过电话的人、问过价格的人、说“45 天后再联系我”的人。接下来，就让 AI 去努力维持这条线的温度。Greg 总结了一句很有力量的话：“过去，你需要雇一个人来做这件事；现在，你有了一个代理来替你完成。”

技术上，安装它需要具备 bun 和 docker。Greg 贴心地列出了基本安装步骤（亦可看视频画面）：`git clone` 仓库、`cd crm`、复制 `.env.example` 为 `.env`、`bun install`、`docker compose up -d`、`bun run db deploy`、`bun run db seed`、最后 `bun run dev`。它通常跑在 `localhost:3000`，API 则是 `localhost:3001`。你需要自己配置环境变量，尤其是登录用的 Google/Microsoft OAuth 客户端和邮件/日历集成。

**个人感受**

Greg 在讲到“CRM 沦陷为墓园”时，那种自嘲感非常有共鸣。几乎每个创业者都有过这种经历——一开始积极地管理客户关系，后来渐渐发现维护成本太高，最终放弃。但他的情绪里也有巨大的兴奋感，因为他看到这个工具真正解决了“懒人的痛点”：你不需要改变自己，让 AI 去“卷”就行了。

**延伸思考**

这个仓库让人想到一个更深层的问题：在”微信“和”邮件“里，其实藏着大量未被挖掘的商业价值。它们就像一座金矿，但传统工具根本没办法自动采矿。如果 AI 可以主动帮忙维护关系图谱，那么很多“小公司”就能第一次拥有像大公司那样的“关系运营能力”，而不必养一个庞大的销售运营团队。也许，未来每个人都会拥有一个“关系操作系统”来替代今天的名片和通讯录。

**精华收获**

- 传统 CRM 的痛点不是工具不好用，而是“维护成本”太高——AI CRM 的出现，正是为了消灭这种维护成本。
- 用“我不能忘记的的温暖线索”这个小概念开始，让你不再遗漏任何可能带来收入的人。
- 让 AI 做“关系维护的杂务”，你专注在真正需要人类智慧的部分：决定说什么、和谁说、何时说。

### 仓库三：Video Use —— 用“代码”当你的视频剪辑师 `[段落 9-13]`

**核心观点**
这个来自 browser use 团队的仓库，允许你用编码智能体（如 Claude Code 或 Codex）来编辑视频。你只要把原始素材丢进一个文件夹，就能让 AI 替你完成去废话、剪停顿、加字幕、调色、渲染、检查输出等一系列工作。它最大的价值，是让你把“剪辑风格”变成一套能被 AI 理解和重复执行的“系统”。

**深度阐述**

第三个仓库由 browser use 团队推出，名字叫 Video Use。Greg 说这是他的最爱之一，因为你一看就懂它在解决什么问题：**让 AI 智能体帮你编辑视频**。

它的工作方式听起来就像魔法：你把原始录像放进一个文件夹里，然后向 Claude Code 或 Codex 这样的编码代理发出指令，它就能完成一堆剪辑行为：去掉“嗯”“啊”之类的填充词、剪掉冷场、添加字幕、调色、制作视觉叠加，甚至渲染视频并检查输出质量。

市面上确实已经有不少“AI 视频编辑软件”了，但 Greg 认为这个仓库真正的独特之处在于——**它让编辑工作流成为可以被智能体理解和重复的东西**。

这怎么理解？让我们看看内容创作者的真实状态。大多数创作者（或者说任何生产内容的人）其实翻来覆去都在做同样的几种剪辑操作：同样的字幕样式、同样的节奏、同样的卡点方式、同样的开场，甚至是从一小时的直播里“掐出”几条 60 秒的高光短片。Greg 以自己为例：“你看我的 YouTube 频道，每期视频的风格是不是都差不多？” 这些看似“风格”的东西，过去一直存在于创作者的**大脑和肌肉记忆**里，很难被复制和外包。

但是通过这个仓库，你的“剪辑风格”变得**显性化**了。AI 代理可以读取视频转录稿、查看时间戳、提出剪辑策略、渲染成片，并检查剪切点是否合适。这就相当于你雇了一个不仅知道你风格、而且永远不会累的剪辑师。

Greg 特别强调了内容创作在商业中的重要性：“如果你是个创作者或创始人，内容创作很可能是你最大的瓶颈之一。你可能拥有极好的产品，但如果没人看得到，你依然会输。” 他认为这个仓库的价值在于——它大幅缩短了从“原始素材”到“发布内容”之间的距离。

但 Greg 相当务实：**别指望第一天就自动化整个 YouTube 频道**。他说许多人试图一次性做太多事，结果因为没有得到完美的结果，就干脆放弃了。更明智的做法是，从一个**小而可重复的格式**开始：
- 比方说，把一个创始人的 Loom 录屏，剪成一条 60 秒的产品发布视频；
- 或者，把一期播客音频，交给 AI 去产出“3 条够劲的短视频片段”。

一旦你成功跑通了一个格式，你就能把它演变成一套稳定的系统。而当你拥有了一套系统，你就可以自己持续使用，甚至**把它当作一项服务卖给别人**。Greg 笑称：“创业机会就在眼前，对吧？每个细分市场都需要内容，而几乎没有人真正享受剪辑这件事。” 他举了几个例子：
- 房地产经纪人需要房源视频；
- SaaS 商家需要产品演示视频；
- 教练/顾问需要演讲切片；
- 广告代理需要不同版本的广告素材。

这些人都讨厌做剪辑，但他们是愿意为“省时间”付钱的。这个仓库，就是帮你进入这个市场的“入场券”。

如果你想动手试试，安装设置其实非常“对智能体友好”。核心思路是：把那一段设置提示词直接粘贴给 Claude Code 或 Codex（需要 shell 访问权限）。提示词大致是：“帮我设置这个 GitHub 仓库，先读 install.md 安装说明，安装这个仓库，配置 FFmpeg，然后把 skill 注册到我要使用的智能体上，等需要的时候再问我要 11 Labs 的 API key。” 当然，如果你喜欢手动，也可以自己 `git clone` 手动安装，但 Greg 认为：“对 95% 的观众来说，不如让智能体帮你装。”

**个人感受**

Greg 在这里展现了一个“内容人”真实的痛点：剪辑繁重且无聊，可又没有人能替你完成，因为“风格”很难传达给他人。而 Video Use 让这种痛苦变得可解。他说“一看到你就秒懂”时，那种兴奋感就像一个饿了很久的人突然发现了一家深夜还开着的拉面馆。

**延伸思考**

这个仓库预示着“创作流程”正在发生根本性转变：过去，剪辑是“手艺人”的活；现在，剪辑正在变成“提示词的工程”。有趣的是，当每个创作者都能轻松地把剪辑工作外包给 AI 时，**人和人之间的竞争焦点将从“谁剪得好”转向“谁的想法更好、谁的风格更独特”**。这其实是好事——它把创作还原成了思考本身。

**精华收获**

- 将你的“剪辑风格”从大脑中提取出来，变成一种可以被 AI 理解并执行的“系统”。
- 你的第一目标不是全自动化，而是跑通一个“小格式”，然后逐步放大。
- 如果你能帮一个行业/领域解决“剪辑难”的痛点，这本身就是一门好生意。

### 仓库四：Nvidia Skill Specter —— 给 AI 装上“安全门禁” `[段落 14-17]`

**核心观点**
当人们开始从 GitHub 上随意安装 AI 技能、MCP 服务器、插件和代理工具时，安全隐患也随之而来。Skill Specter 正是 Nvidia 推出的一个安全扫描工具，可以在你把新能力“喂”给 AI 之前，先检查它是否安全，是否包含提词注入、数据窃取、隐藏指令等风险。

**深度阐述**

第四个仓库来自 AI 芯片巨头 Nvidia，名字叫 Skill Specter。在 Greg 看来，这是一个**“无脑装就行”**的仓库，因为在不远的未来，它会是每个 AI 重度用户的“安全底线”。

先看背景：随着智能体、MCP（模型上下文协议）服务器、插件、代理工具变得流行，大家开始在 GitHub 上随便安装各种增强 AI 能力的包。这当然很酷，因为这让 AI 拥有了新的超能力。但 Greg 提醒我们一个残酷的事实：**一个“技能”不仅仅是一段文字**。它可以包含指令、脚本、依赖性、工具访问权限，甚至能够改变你的智能体的工作方式。在恶意场景下，它甚至可以**触碰文件、调用工具、连接网络服务**。

换句话说，当你从 GitHub 上安装一个酷炫的新技能时，你实际上是在“让一个陌生人进你家”。所以，**“安装之前，先问一句它安全吗”就变得至关重要**——而这就是 Skill Specter 的用武之地。

简单来说，Skill Specter 可以扫描 AI 智能体的技能，查找以下安全漏洞：
- **提示注入**（Prompt Injection）；
- **数据外泄**（Data Exfiltration）；
- **供应链风险**；
- **隐藏指令**；
- **与 MCP 相关的风险**。

Greg 用一句话概括了使用心法：“**在你给 AI 递一件新工具之前，先扫描一下这件工具。**”

这个道理现在看尤为重要，因为 AI 工作流正在变得高度“模块化”。大多数人现在只用一两个聊天机器人，但走在前沿的构建者已经开始组装自己的 AI 工作环境了——一个编码代理、一个研究技能、一个设计技能、一个浏览器工具、一个视频工作流……这种结构看上去就像给自己搭建了一个**“工作操作系统”**。而当你身处这个“操作体统”中时，安全问题就从“只有大企业才需要担心的事”变成了“每个普通构建者或创始人都要面对的日常问题”。

所以，Greg 认为这个仓库应该放入你的“必备清单”。虽然他与 Nvidia 并无关联，但他明确表示：“我把它放进来，是因为它给整个技术类别带来了信誉——同时也承认了现实：很多技能、插件之类的都可能是恶意的，你必须小心。”

**那么怎么上手用呢？** Greg 给出了快速安装命令。若用 Python 环境，可以用 `uv`：
- 安装：`uv tool install skill-specter`
- 然后，你可以直接扫描一个 GitHub 仓库：`skill-specter scan <GitHub链接>`
- 或者扫描本地技能目录：`skill-specter scan ./my-skill`

如果你希望更快地做静态扫描，而不想把文件内容发送给大模型提供商（比如不想上传敏感代码），可以加 `--no-lm` 参数。不想在本地装 Python 的人，也可以用 Docker 选项。

**个人感受**

Greg 在讲这个仓库时，语气比前面几个要更严肃一点。他说“我一直在想这件事”——如果团队真的都在安装 AI 技能和 MCP 服务器，那么必须有人帮他们判断“什么安全、什么不安全”。这份“忧患意识”在整个轻松愉快的讲解中显得尤为可贵。他像是那个在狂欢派对上提醒你“别乱吃陌生人给的糖果”的朋友，理智且可靠。

**延伸思考**

Skill Specter 背后隐藏的是一个巨大的商业机会：随着 AI 变得更加模块化和工具化，一个**“可信的 AI 技能市场”**或**“安全扫描/安装门禁”**将变成刚需。这就像移动互联网时代的 App Store 和杀毒软件的结合体——你在下载任何 App 之前都会看一眼权限和评价，未来的 AI 工具也需要同样的机制。也许，下一个价值数十亿美元的公司，就是诞生在“为 AI 设置信任机制”这条赛道上。

**精华收获**

- 不要无视“AI 技能”中的潜在威胁，其风险远大于传统的插件。
- 随手扫描，安全第一，尤其在涉及企业敏感数据时。
- 对创业者来说，“AI 技能安全扫描”可能是一个等待被产品化的蓝海市场。

### 仓库五：Phone Harness —— 让 AI 直接操控你的手机 `[段落 18-21]`

**核心观点**
Phone Harness 让 AI 智能体可以真正控制你的 iPhone 或 Android，完成查看屏幕、点击、输入、滚动、打开应用和验证结果等工作。它不需要越狱，也无需在手机上安装特殊 App，为移动端的自动化测试和工作流执行打开了想象空间。

**深度阐述**

第五个仓库名叫 Phone Harness，一句话总结：**它让 AI 智能体控制你的手机。**

目前，主流的 AI 代理工具主要围绕浏览器、终端和桌面应用来构建。这当然合理，因为大量的工作确实是在这些“屏幕”上完成的。但 Gregor 提醒我们一个很容易被忽略的事实：**今天，有大量工作发生在手机上**——银行应用、即时通讯、社交媒体、点外卖……这些东西都已经深度嵌入了我们的生活。这些手机 App 由于封闭的生态或缺少 API 接口，导致很多工作流极难被自动化。**因为你唯一能操作的界面，就是那块手机屏幕。**

Phone Harness 解决的就是这个“最后一英寸”的问题：它把 Agent（比如 Codex 或 Claude Code）连接到一台真实的 iPhone 或 Android 设备上。
- 在 iPhone 上，它利用的是 **Mac 的 iPhone 镜像功能**；
- 在 Android 上，它通过 **ADB**（Android 调试桥）连接。

Greg 特意照顾了一下大家的担忧情绪：“你不需要越狱。你不需要 Xcode。你甚至不需要在手机上安装任何特殊应用。” 智能体可以实时看到屏幕上的内容，然后像真人一样：点击、输入、滑动、打开 App，并且**验证发生了什么事情**。

也许此刻有人会问：“这到底有啥用？” 你觉得做移动 App 测试很轻松吗？你可以让智能体在**真实设备**上跑一遍新用户注册、登录、结账流程。如果你在做自动化，它可以打开那些没有 API 的移动应用。如果你是创作者或运营者，未来它甚至能帮你处理日常在 TikTok、Instagram 上那些重复性的手机操作。

Greg 推荐的最简单的尝试方式：**测试一个移动注册流程**。比如，打开你的 App，创建一个账户，点一遍新手引导，走到结账页，截几张图，告诉它“哪里让人迷惑、哪里会崩溃”。这几乎是每个移动团队都应该做、但大多数懒得做或根本没雇人做的事。这个仓库能帮你轻松跨过这道“懒人门槛”。

安装使用同样很方便。仓库自带提示词，你直接粘贴给 Codex 或 Claude Code：“帮我设置 phone harness，克隆这个 GitHub，读 install.md，安装好让 phone harness 进入我的 PATH，注册为 agent skill，然后读 onboarding.md 并带我完成设置。”

系统要求方面：
- 对于 iPhone：需要 **macOS Sequoia 或更高版本**，支持 iPhone 镜像功能，并给你的终端授予**辅助功能**和**屏幕录制**权限。
- 对于 Android：打开开发者选项，通过 USB 连 ADB（也支持无线连接）。
- 设置完成后，可以先运行 `phone-harness --doctor` 来检查一切是否就绪。

坦率地说，这个仓库还很早期，有局限性。比如，锁定状态的手机需要你本人解锁，Face ID 或相机相关的流程会比较棘手。但 Greg 说：“**方向是明摆着的。**” 智能体正在从“回答问题”走向“操作工具”，而手机，就是世界上最大的“工具操作面”之一。他又提到了那一句贯穿整期视频的核心信号：“如果你能理顺一些这样的工作流，创业点子就在那里，对不？如果你能把‘移动端 QA’产品化，会有人愿意为此每月付 100 美元吗？500美元？你需要多少个客户才能达到月入一万美元？”

**个人感受**

Greg 在解释 Phone Harness 时，有一种“终于等到这一天”的兴奋感。当他提到“不需要越狱”时，你可以感受到他作为普通用户松了一口气。他并没有把自己塑造成技术大牛，而是站在一个“被困在重复性手机操作里的普通创业者”视角，看到了一个解放双手的工具。

**延伸思考**

手机自动化将打开一个全新的“软件即服务”品类。过去，我们有很多 SaaS 是围绕“浏览器工作流”建立的，而下一个浪潮一定会有许多围绕“手机工作流”的自动化产品。更重要的是，这条路径一旦成熟，“数字员工”将真正走进实体生活的方方面面——从帮你订餐到帮你测试 App，AI 的运用边界将被大幅拓宽。

**精华收获**

- Phone Harness 让你第一次可以把“手机上的重复操作”交给智能体。
- 从“测试注册流程”这种简单任务入手，你能立刻获得真实的价值。
- 移动端自动化是尚未被充分开发的蓝海，潜在的创业机会巨大。

## 第三部分：整体思维——从“看懂仓库”到“生成系统” `[段落 22-24]`

**核心观点**
Greg 提醒我们，仅仅安装这些开源仓库是不够的。真正的路径是：把它跑通一个小工作流，获得价值，然后思考是继续自己用，还是将其产品化卖给更多人。这也是他为什么鼓励大家每月都花时间泡在 GitHub 上的原因。

**深度阐述**

视频接近尾声，Greg 把镜头拉远了一点，分享了自己对这一切的整体思考。

“五个 GitHub 仓库，我觉得都很有趣。显然，我不想当一个全职的开源分析师，但 GitHub 是少数几个你能在工具成为主流之前发现它们的地方，所以你真的值得花时间泡在那里。”

他接着给出了一套极其有用的“三幕式”行动策略：
1. **安装它**：即使你并不懂技术，试着安装这些仓库也没关系；
2. **跑通一个小工作流**：让它在你的真实生活/业务里产生一点价值；
3. **问自己一个问题**：我应该为其他人把这个产品化，还是继续用它来提升自己的生产力和金钱能力？

事实上，Greg 是在传递一种“拥抱开源生态”的心态。这些免费的仓库就像乐高积木，单块积木可能不起眼，但当你把它们组装起来，就能造出一个独一无二的“人工智能工作台”。他甚至认为，即便你并不技术，在安装这些仓库的过程中也能学到很多东西——你会慢慢摸清什么工具适合自己、哪些环节缺失、怎么把它用于自己的公司、如何把它交给他人赚钱……更重要的是，“在尝试中，你会把思维里那些分散的点连接起来。”

因此，Greg 半开玩笑半认真地提出，他考虑把“月度 GitHub 仓库推荐”变成持续更新的系列视频，并征求观众的反馈：“我应该每月做一次、每两周做一次、每六周做一次，还是再也不做了？哪种都行。”这种开放态度让整个视频充满互动感和温度。

**个人感受**

在结尾处，Greg 说了一句特别有感染力的话：“如果你一直在听这个播客，你会知道我活在服务之中，我在乎的只有通过想法、工具和框架来增加你在这一时代的成功概率。”这句话放到整个视频上下文里，显得尤其真诚。他没有在卖课，也没有在割韭菜，他只是在把自己最近找到的“宝藏地图”分享出来。他还说：“我为你加油，祝你度过有创造力的一天。”这很符合他个人品牌的调性——友善、慷慨、充满行动力。

**延伸思考**

从“使用工具的猴子”到“构建工具的智人”，差距往往只在于你是选择“消费工具”还是“创造系统”。在智能体时代，每个人都可以成为“拼装者”——你不必写代码，但你可以成为最懂怎么用代码工具的人。Greg 的这期视频，其实是给所有人一个提醒：机会不只存在于你熟悉的领域，有时它就是藏在那些你从未点开的 GitHub 链接里。

**精华收获**

- 安装、试验、跑通小工作流、决定是否产品化——这套行动路径适用于任何AI工具。
- 每个人都可以通过GitHub来“接触未来”，即使你不懂代码，你也能学会使用工具。
- 请保持好奇心，每月花点时间去“开源世界”淘宝，这是成本最低的“未来探测器”。

## 结语：在“智能体时代”快人一步

这期视频本质上是 Greg Isenberg 送给所有想在智能体时代快人一步的“寻宝地图”。从“让人味回归写作”的 No AI Slop Skill，到“让关系管理自动运转”的 AI CRM；从“让剪辑变成一种系统”的 Video Use，到“给AI装上安全门”的 Skill Specter，再到“让智能体长出手脚”的 Phone Harness——这五个仓库共同指出了一个未来方向：**AI 的下一阶段不是更好的聊天，而是更好的行动。**

如果你也在试图用 AI 构建产品、节约时间、甚至创造财富，那么不妨从今天介绍的五件工具里选一件开始“玩弄”它。只要你开始安装、实验，你就在通往“构建者”的路上了。
