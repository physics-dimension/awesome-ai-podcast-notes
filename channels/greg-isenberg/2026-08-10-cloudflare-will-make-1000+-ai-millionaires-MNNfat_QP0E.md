# 详细内容

## 一、互联网的"旧约定"正在瓦解 `[章节 1：旧约定与新现实]`

**核心观点**
过去二十年，互联网的底层交易是"爬虫换来流量，流量换来注意力，注意力换来钱"。AI Agent 正在打破这个链条——内容仍然创造价值，但网站失去了访客，也就失去了一切变现的可能。

**深度阐述**

Greg 用"旧约定"（the old bargain）这个词来概括互联网过去二十年最核心的隐性契约。这个约定听起来简单，却支撑起了整个现代互联网经济：你拥有一个网站，你让搜索引擎的爬虫来爬你的内容，因为搜索引擎会给你送流量。Google 读取你的网站、索引你的页面；当有人搜索时，你的页面有机会出现在结果中；然后，一个真实的人类会点击进来。

**人类落地在你的网站上之后，你才开始变现那份注意力。** 你可以展示广告，可以收集邮箱，可以推销订阅，可以做联盟营销。在这套体系里，每个人各得其所：爬虫拿到了内容，网站拿到了访客，访客拿到了答案。这笔交易"资助了互联网的巨大部分"。

**而现在，AI Agent 正在改写这个故事。** 一个 AI Agent 或 AI 系统可以读取你的页面，提取出有用的答案，直接把它交给用户——而用户可能根本不会访问你的网站。Greg 精确地指出了这个残酷的错位：内容依然创造了价值，但网站失去了访问量；失去了访问量，就失去了广告曝光、邮箱收集、联盟点击——"所有这些都没了"。

这也是为什么大量内容出版商对 AI 感到愤怒。但 Greg 提醒我们，出版商们的抱怨只是"第一局"（the first inning），真正的大戏还在后面。他的前瞻性判断是：**Agent 将会像软件使用基础设施一样使用互联网**——它们会发起请求、调用工具、比较产品、检索数据、购买访问权限、执行动作。这意味着，互联网需要为"机器使用"建立一套全新的定价体系。

**个人感受**

Greg 讲了一个特别生动的个人化桥段来诠释"为什么人类不会为微支付买单"：假如他点开一个食谱网站，页面弹窗说"请支付 1/3 美分以查看酱汁配方"，他会直接合上笔记本电脑，然后赌气去点墨西哥卷饼外卖。这个画面感极强的吐槽背后是一个深刻的洞察：**人类厌恶微支付的心理成本，远远超过了那 0.003 美分的实际价值**。但机器完全不同——机器不在乎支付是否微小、是否自动。只要数据能帮助 Agent 完成任务，Agent 就愿意付费。

**延伸思考**

这套逻辑的深层含义在于：互联网的定价单位正在从"注意力"转向"效用"。注意力经济建立在人类时间的稀缺性上，而 Agent 经济建立在任务完成度上。当一个 AI Agent 为你找到了答案、比价、甚至完成了购买，它的"时间"是廉价的，但它的"成功率"是昂贵的。谁能把自己的资源变成 Agent 完成任务链条上不可或缺的一环，谁就掌握了定价权。

**精华收获**

> "The human web monetized attention and the agent web monetizes useful resources." — "人类网络以注意力变现，Agent 网络以有用资源变现。" `[核心论点]`

这句话是整个视频的题眼。请记住它，后面所有的创业想法都是这句话的展开。

## 二、Cloudflare 在做什么：让"请求即交易"成为现实 `[章节 2：Cloudflare 的产品拆解]`

**核心观点**
Cloudflare 发布了三件套：AI 爬虫控制（AI Crawl Control）、按爬取付费（Pay per Crawl）、以及货币化网关（Monetization Gateway）。后两者的核心是用 HTTP 402 状态码和 X42 协议，让"付费"成为互联网协议的一部分，而非割裂的支付流程。

**深度阐述**

Greg 用"Plain English"（大白话）的承诺，把 Cloudflare 的技术发布拆成了三个可理解的组件。

**第一块：AI Crawl Control（AI 爬虫控制）。** 这给网站所有者提供了对 AI 爬虫的可见性和控制权。你可以看到爬虫活动，可以允许某些爬虫做某些事，也可以屏蔽某些爬虫。一句话：你能知道谁在访问你的内容，并决定是否放行。

**第二块：Pay per Crawl（按爬取付费）。** 这是直接的变现模块，也是"能让人赚到钱的那块"。网站所有者现在可以对 AI 爬虫访问内容收费。流程是两种方式二选一：爬虫在请求中主动声明支付意图（payment intent），或者服务器返回一个带有定价信息的 **402 Payment Required（需要付款）** 响应。

**第三块：Monetization Gateway（货币化网关）**——这是更大的一步。Cloudflare 的潜台词是：这套逻辑不应该只适用于"爬虫读网页"。**任何放在 Cloudflare 背后的资源都可以挂上支付规则**——一个网页、一个数据集、一个 API、一个 MCP 工具调用、一个高级端点、一个文件、一个搜索索引，都可以。而它们使用的支付轨道是 **X42**，一个基于 HTTP 402 状态码的协议。

整个流程是这样的：Agent 请求资源 → 服务器回应"这个东西要花这么多钱，通常不到一分钱" → Agent 支付并带着支付证明重试请求 → Cloudflare 在边缘节点验证支付，然后才把请求放行到源服务器。

Greg 认为，用大白话来说，**Cloudflare 是在让"付费访问"感觉像是互联网的原生组成部分**。没有巨大的结账页面，不需要先创建账户，没有销售电话，没有企业采购流程。"基本上，一个请求本身就变成了交易。"（The request becomes the transaction.）他反复强调这是一个非常大的想法，因为它意味着互联网上那些微小细碎的资源，都能长成一门生意：数据集可以按次查询收费，API 可以按成功调用收费，研究档案可以按答案收费，产品目录可以按比较动作收费。

**视觉/结构信息描述**

Greg 在描述中构建了一个清晰的"资源—支付"对应关系表，我们可以还原为这样的结构：

| 资源类型 | 计费方式 |
|---------|---------|
| 数据集 | 按次查询（per lookup） |
| API | 按成功调用（per successful call） |
| 研究档案 | 按答案（per answer） |
| 产品目录 | 按比较（per comparison） |

这个表格直观地说明：**任何有价值的资源都可以被"颗粒化"定价**。

**延伸思考**

Greg 提前预判了评论区会出现的质疑："Agent 没有钱包怎么办？"他的回应很直接：我们正在走向一个 Agent 拥有钱包的未来——它们会拥有邮箱地址，会进行交易，而且"这已经在发生了"。他提到 Cloudflare 的 AI Index（AI 索引）也指向同一个方向：让网站更容易被 AI 系统使用，包括 MCP（Model Context Protocol，模型上下文协议）、LLM.txt、搜索 API 和批量数据 API。

这里有一个值得深思的技术背景：HTTP 402 状态码其实早在 1998 年的 HTTP/1.1 规范中就预留了，但二十多年一直没用起来。X42 协议是近年来推动"402 复活"的关键力量，它定义了一套轻量级的支付语义，让"服务器报价—客户端支付—验证放行"变成标准握手。Cloudflare 作为全球最大的边缘网络之一，选择押注这条路，意味着微支付可能第一次拥有真正的基础设施级支撑。

**精华收获**

"请求即交易"这个思维转变极具冲击力。旧的支付思维是"销售漏斗"：曝光→点击→注册→付费，漫长而充满摩擦。新的支付思维是：**协议本身就是支付**。当机器成为消费者，交易摩擦必须趋近于零，而 HTTP 402 就是那个让支付融入协议层的开关。这对创业者最大的启示是：你不需要再构建复杂的支付体验，你需要做的是让你的资源"可以被计价"。

## 三、为什么 Agent 需要"干净的门" `[章节 3：网站变成资源层]`

**核心观点**
人类能够忍受混乱的网站，但 Agent 需要结构化的、可信的、可直接使用的信息。互联网正从"供人浏览的页面"变成"供机器调用的资源层"。

**深度阐述**

Greg 讲了一个让所有创业者都应该感同身受的观察：人类是"忍受力很强的生物"——我们可以在烂网站上点来点去，可以放大缩小页面，可以读 2019 年的 FAQ，可以打开 PDF 自己找答案。"We're good at suffering human beings."（作为人类，我们很擅长受苦。）

但 Agent 不行。Agent 需要"非常干净的门"（really clean doors）——信息必须以它们能够信任和使用的格式存在。这解释了为什么 Cloudflare 在推动 LLM.txt 这样的新标准：它是网站为语言模型准备的"说明书"，告诉 AI 你的网站有什么、怎么用、哪些页面最重要。

由此，Greg 提炼出一组精彩的对应关系，描绘了整个行业的结构性迁移：

| 旧互联网 | Agent 互联网 |
|---------|-------------|
| 网站（websites） | 资源层（resource layers） |
| 内容（content） | 索引（indexes） |
| 经验（expertise） | 可规模化（scalable） |
| 数据（data） | 计量化（metered） |
| 工具（tools） | Agent 可访问（agent accessible） |

他特别强调，这是他作为 founder 关注的焦点，因为"我可以在这之上建造"。

**延伸思考**

这个"干净的门"的概念其实触及了 AI 时代一个被低估的问题：**数据的可发现性**。互联网上 90% 的信息对人类可见，但对机器不可用——因为它们隐藏在 PDF、图片、动态加载的脚本、需要登录的页面背后。Agent 互联网的本质竞争，将不再是"谁的网站更好看"，而是"谁的信息更容易被机器理解和信任"。这也意味着，未来十年最值钱的技能之一，可能是"把混乱信息结构化的能力"。

**精华收获**

不要为人类优化，要为 Agent 优化。你的目标用户明天可能是 AI，而 AI 的耐心是零。如果你网站的信息结构混乱，Agent 就会选择你的竞争对手——那个写清楚价格、写好 LLM.txt、提供干净 API 的竞争对手。

## 四、正在形成的新互联网堆栈 `[章节 4：五层堆栈]`

**核心观点**
新互联网的产业链由五层构成：混乱的原始互联网 → 结构化数据 → Agent 可读接口 → 支付规则 → 信任与分析。这个堆栈将催生数千家公司。

**深度阐述**

Greg 认为，围绕这个新互联网，一个完整的产业堆栈正在形成，而且"比我们想象的要简单"。他用一种极具操作性的方式，把这条产业链拆解成了五个环节：

**第一层：混乱的互联网（The messy internet）。** 这里面有什么？PDF、定价页面、老博客文章、YouTube 视频、帮助文档、比价网站，还有那些"人们在还毫无讽刺地说着 Web 2.0 的时代设计的网站"。这就是原材料，是尚未开采的矿藏。

**第二层：有人把它清洗成结构化数据（structured data）。** 混乱的信息需要被整理、标注、关联，变成机器能处理的形态。

**第三层：有人让它变成 Agent 可读的（agent readable）。** 通过 API、MCP 工具、搜索索引、Feed、LLM.TXT 或其他干净的访问点。核心前提是：它必须是"干净"的。

**第四层：有人加上支付规则（payment rules）。** 有些内容保持免费——因为免费能带来大量分发；有些内容收费——因为它们极其有价值；有些内容被屏蔽——因为它们应该保持私密。

**第五层：有人加上信任与分析（trust and analytics）。** 数据新鲜吗？来源可靠吗？哪些 Agent 在使用？哪些请求值得收费？哪些资源真正驱动了结果？

Greg 说，**这个堆栈就是"整个一代、数千家公司"的诞生地**。而在这个堆栈里寻找机会时，最核心的问题只有一个：**"什么资源是 Agent 迫切需要的、高频需要的、可靠需要的，以至于它愿意为此付费？"**

**个人感受**

Greg 在这里特别强调了他作为创始人的直觉——这个堆栈不是理论，而是他每天在思考的战场。他的判断非常笃定：当你在寻找创业想法时，不要问"我能做什么工具"，而要问"Agent 缺什么资源"。

**精华收获**

这五层堆栈是一张极其实用的创业地图。你可以问自己：我要切入哪一层？是想做清洗数据的"炼油厂"，还是做提供访问接口的"管道"，还是做制定支付规则的"收费站"，还是做建立信任的"认证机构"？每一层都有机会，但每一层的商业模式、技术门槛和竞争格局完全不同。

## 五、反驳"创业已死"：最好的时代就在眼前 `[章节 5：创业时代的重新评估]`

**核心观点**
面对"AI 抢走了流量和工具红利、创业已死"的论调，Greg 给出相反的判断：这是史上最好的创业时代——前提是你建造的是"Agent 原生"的生意，而不是能被 vibe coding 取代的小工具。

**深度阐述**

视频进行到这里，Greg 暂时从 Cloudflare 的话题上岔开，回应了一段他在 X（推特）上看到的讨论。知名独立开发者 Levels.io 在讨论：现在创业太难了，很多人的流量和收入都下滑了。Greg 承认这很大程度上是因为 AI Overviews（AI 概览）抢走了搜索流量，而且大量软件不再有用——因为人们自己用 vibe coding（AI 辅助编程）就能造出来。

但 Greg 的态度出人意料地乐观："我的观点是，这是一个不可思议的创业时代。事实上，是有史以来最好的时代。"关键在于，你要创建的不是那种"能被 vibe coding 掉的小工具"，而是**当天就能盈利、有护城河、为 AI 原生互联网而重新设计**的创业项目。

他给那些在 X 上哀叹"创业已死"的人一记清醒的耳光："世界在移动，互联网在改变，你必须随之移动。"他把这个时代类比为 2009 年 App Store 刚上线时——那时候最好的机会看起来也很小，但那一批行动的人后来都成了巨头。

**个人感受**

这段话里藏着 Greg 鲜明的性格底色。他不是一个贩卖焦虑的人，也不是一个盲目乐观的人。他的乐观建立在"结构已经改变，而大多数人还没反应过来"的判断上。他对 Levels.io 的回应不是反驳，而是补充：你说得对，旧的生意在死，但新的生意正在以你还没理解的方式诞生。

**延伸思考**

"创业已死"的论调每隔几年就会出现一次——社交网络兴起时、移动互联网来临时、疫情冲击时。每一次，死掉的都是旧范式的生意，诞生的都是新范式的生意。AI Agent 互联网的独特之处在于：**这一次的交易对手不再是人类，而是机器**。这意味着规模可以更大（机器不会累、不会烦、7×24 小时消费），也意味着进入门槛可以更低（你不需要说服人类注册账号，你只需要让 Agent 觉得你有用）。对个体创业者来说，这可能是历史上第一次，你可以在车库里建一个"只卖给机器"的生意。

**精华收获**

给焦虑者的解药：不是创业没有机会了，而是旧地图找不到新大陆。用旧范式（流量、广告、注意力）的眼光看，世界确实在崩坏；用新范式（资源、调用、效用）的眼光看，世界才刚刚开始。

## 六、创业想法一：利基数据精炼厂（Niche Data Refinery）`[章节 6：想法一]`

**核心观点**
挑一个特定利基市场，把其中混乱、碎片化、持续变化的信息，提炼成 Agent 可用的"清洁燃料"。先人工服务，再产品化，最后变成按调用收费的 API。

**深度阐述**

这是 Greg 最推崇、也最"务实"的一个切入点。他给它起名叫"数据精炼厂"——因为原材料已经存在，互联网上到处都是。它们躺在 Google 地图里、招聘帖里、评论里、本地目录里、PDF 里、定价页面里。你的工作不是创造数据，而是**提炼数据**。

**具体怎么做？他给出了一个保姆级案例：医美诊所（med spas）。**

为什么选医美？因为美国医美行业正在高速增长。一个医美诊所老板想知道：竞争对手在收多少钱？提供什么项目？差评都在抱怨什么？哪些诊所正在招聘？哪些服务在流行？什么优惠有效？本地市场在怎么变化？

今天的这些信息散落在无数地方：Google 评论、竞争对手网站、Instagram、招聘帖、Meta 广告库、甚至老板和员工的脑子里。**如果一个 Agent 能干净地拿到这些信息，它能为医美老板做出惊人的工作。** Greg 给出几个具体的"Agent 输出"示例：

- "你的 Botox 定价高于本地中位数，但你的评论量还撑不起高端定位。"——信息量巨大的战略判断。
- "过去 60 天，附近有三家竞争对手开始推广外泌体（exosome）治疗。"——趋势预警。
- "本地评论中最常见的抱怨是你们的定价混乱，所以你的营销应该主打简单透明。"
- "增长最快的竞争对手正在招聘注射师，这可能意味着他们在扩张产能。"

这些信息的价值来自**数据本身**，而不是一个通用的 AI 包装。这个区分极其重要。

**楔子（Wedge）怎么打？**

Greg 给出了极其具体的操作手册：选择一个利基、选择一个城市、追踪 100 家商户，一开始手动做。做一个电子表格，字段包括：商户名称、网站、服务、价格、评论数、评论评分、最常见差评、Instagram 链接、近期发帖、可见广告变化、招聘信号、预订流程。然后从这个表格产出 10 种输出物：本地定价地图、竞争对手差距报告、优惠创意清单、服务与广告匹配建议、差评摘要、招聘信号报告、月度市场动态报告……现在你手里有可以卖的东西了。

**第一个客户是谁？——一个反直觉的关键洞察。**

Greg 提醒道，早期第一个客户往往不是最终消费者，而是**那些已经在向这个行业卖东西的人**。与其向一个医美老板推销"Agent 可读的竞争分析"——这句话普通人根本听不懂——不如把它卖给医美营销代理公司、咨询顾问、自由职业者、软件公司，甚至 AI 落地服务商。你的销售话术变成："我建了一个医美诊所本地市场情报系统，你拿它就能给客户做出更好的审计、更好的方案、更好的落地页、更好的 campaign，你可以收更贵的服务费。"一家医美营销代理可能向客户收 5000 美元/月的增长打包服务，而你的数据能帮他们多签一个客户或提升服务质量——那么他们付你 300 到 800 美元/月，完全合理。

**演进路径：爬、走、跑。**

先是一份报告（report），然后是一个仪表盘（dashboard），然后变成 API，再然后变成 MCP 工具，最后当支付轨道成熟时，Agent 可以按次查询付费。"所以你做的基本上是一个爬、走、跑的战略。"

**更多利基方向。** Greg 自己也住在迈阿密，所以选了医美做例子。但他随即给出了一个可以无限套用的"配方"：

- **屋顶维修（roofing）**：追踪暴风雨事件、许可证数据、保险信号、本地评论、竞争对手报价和广告角度。
- **房地产投资**：追踪分区调整、许可证、产权记录、租金对比、税务欠缴、保险变动。
- **电商**：追踪竞品 SKU、价格变动、评论抱怨、网红报价、UGC 钩子、Shopify 应用、配送承诺。
- **律师事务所**：追踪本地竞争对手、业务领域定位、广告文案、评论、接案流程。

**筛选数据的五条标准：**

1. **有价值（valuable）**——更好的决策能赚钱或省钱。
2. **可重复（repeatable）**——客户需要一次又一次地获取，不是一次性买卖。
3. **在变化（changing）**——新鲜度很重要。
4. **碎片化（fragmented）**——一个人很难轻松收集齐全。
5. **令人恼火（annoying）**——正因为恼火，才会有利润空间。

Greg 最后用一句口号式的话总结这个想法："把一个利基市场的混乱互联网，变成 Agent 的清洁燃料。"他特意叮嘱观众不要忘记"清洁燃料"（clean fuel for agents）这个短语。

**延伸思考**

这个想法最妙的地方在于它的"反 AI 焦虑"属性。当所有人都在担心 AI 会取代工作时，这个生意恰恰是把 AI 变成客户的生意——你不是在和 AI 竞争，你是在为 AI 供血。而且，"数据精炼"这个生意具有天然的时间壁垒：早期手动收集的数据关系、领域知识、清洗流程，后期都会变成竞争对手难以复制的资产。AI 不会替你完成"知道迈阿密哪家医美诊所在招聘注射师"这种脏活——至少在短期内不会。

**精华收获**

不要想着"造一个新东西"，“数据精炼厂"的核心是"把已有的东西变干净”。世界上最有价值的资源不是信息，而是**有序的、可信的、即时的信息**。谁能持续提供这种信息，谁就能向 Agent 收"过路费"。而且这个生意的启动成本极低——一个电子表格就够了。

## 七、创业想法二：Agent 就绪服务（Agent Readiness for Businesses）`[章节 7：想法二]`

**核心观点**
这就是"Agent 互联网时代的 SEO"：帮助企业变得容易被 Agent 理解、信任、比较和推荐。先做付费审计，再卖改造服务，最后沉淀为按月复购的测量产品。

**深度阐述**

第二个创业想法，Greg 把它定义为"Agent 互联网时代的 SEO"——但他紧接着警告：AI SEO 已经变成一个模糊的空词，他要用更精确的方式定义它。真正的业务是：**帮助企业变得容易被 Agent 理解、信任、比较和推荐。**

**先理解 Agent 眼中的购买流程。** 以 B2B SaaS 公司为例。一个人类买家会：落地首页、读 hero 文案、点来点去、看定价页、读文档、预约 demo、看案例研究、问朋友。而 Agent 把整个过程压缩了：当用户问 AI 助手"帮我找一家适合加州 15 人公司的最佳薪资服务商"时，Agent 必须自己理解市场。它会问（或者说，它的判断依赖于）：这个产品是给谁用的？多少钱？替代了什么？有哪些集成？有什么风险？实施流程什么样？客户怎么说？与竞品比如何？

而大多数网站让这一切变得更难：隐藏定价、文档深埋、信息陈旧、比价页面常年不更新、关键信息藏在 PDF 里、政策页面极其难找——还有大量的营销黑话，比如"解锁运营卓越"（unlocking operational excellence）这种云山雾罩的表述。Agent 面对这些内容，根本无法提取有效信息。

**楔子：付费审计。**

Greg 建议选择一个垂直行业——B2B SaaS 是显而易见的选择，但 Shopify 应用、律师事务所、医疗诊所、财务顾问、保险经纪人、本地服务商都可以。然后，在主流 AI 工具里跑 **20 到 50 个买家意图提示词（buyer intent prompts）**，例如：

- "这个用例的最佳软件是什么？"
- "把这家公司与顶级替代方案比较一下。"
- "这家公司收费多少？"
- "这个产品最适合谁？"
- "选择这家供应商有什么风险？"
- "对一家 20 人的公司，你会推荐这个产品吗？"
- "它支持哪些集成？"

然后，把答案拿给客户看。**这就是销售时刻。** 你可能会给一个创始人看："当买家向 AI 询问你的品类时，你根本没出现。"或者"你出现了，但 AI 把你的价格搞错了——你的网站写的是每月 20 美元，AI 却告诉人家 8 美元。"或者"AI 推荐了你的竞争对手，因为他们的文档更干净。"或者"你的网站其实有答案，但埋在一份 2002 年的 PDF 里。"——尤其是配合 cold email 使用，效果更佳。

**卖出修复方案：Agent 可读的"真相源"（source of truth）。** 包括：干净的 LLM.txt 文件（帮助大模型爬取你的网站）；更好的文档结构；Agent 能解析的定价页面；诚实且具体的比价页面；用平实语言写的用例页面；按客户细分整理的用户证明；围绕真实买家问题的结构化 FAQ；Schema 标记（结构化数据标签）；产品 Feed；变更日志（changelog）；以及——如果公司有足够多有用内容——一个轻量级 MCP 服务器或搜索端点。如果没有足够内容，那这部分就不必做。

**复购产品：测量循环。** 每个月重新跑一遍那些提示词，看变化：AI 的回答是否更准确了？公司是否更频繁地出现？竞品对比是否改善还是恶化？网站还需要补充哪些结构化证明？——这构成了一个持续的、按月付费的服务。

**定价与演进。** 起步阶段，审计加清理可以收 3000 到 10000 美元；对更大的 B2B 公司，可以收到 10000 到 20000 美元。当你服务完同一个利基的 10 个客户，你会发现大量重复性工作——同样的文档缺失、同样的定价页不清晰、同样的问题被问到、同样的结构化文件需要创建、同样的月度报告需要交付。**这就是你把服务变成软件的时刻。**

**销售方法论：**

> "You're not selling the future. You're selling the screenshot." — "你不是在销售未来，你销售的是截图。" `[销售心法]`

你给客户看的不是某种未来的愿景，而是**AI 今天是怎么说你的**——这张截图本身就是全部销售材料。

**按行业延伸的终局形态：**

- 本地商户 → "让 AI 助理能直接跟你预约"
- 电商 → "让你的产品目录容易被购物 Agent 比较和购买"
- B2B SaaS → "让你的产品容易被采购 Agent 评估"
- 出版商 → "让你的档案容易被 AI 系统理解和授权"

Greg 指出，VC 支持的横向产品已经出现，但机会在于**极度垂直化**。B2B SaaS 这个池子太大、太泛，你应该选一个具体利基深扎下去。这个生意"第一天就有现金流"，可以产品化，未来还能卖掉。

**个人感受**

Greg 特别提到自己在播客里与 Corey Ganham 讨论过"付费审计"的打法，强调这是他亲身验证过的路径。他的语气里带着一种过来人的笃定：这个需求不是他想象出来的，而是企业正在真实感受到的疼痛——"你就把它解决掉"。

**延伸思考**

"Agent 就绪"这个概念的深层含义是：信任将由机器来执行。过去，品牌靠设计、文案、公关来建立人类心智中的信任；未来，品牌还要在机器心智中建立信任——而机器心智的建立方式是结构化、可验证、无歧义的信息。这会产生一个有趣的结果：**诚实会变成一种技术优势**。那些定价透明、文档完备、承诺明确的企业，会天然被 Agent 优先推荐。继续玩"藏价格、等询盘"老套路的企业，会在 Agent 经济里被系统性淘汰。

**精华收获**

"销售截图"这四个字值得所有创业者刻在脑子里。它揭示了一个普遍有效的销售原理：不要卖概念，卖证据。如果你能证明"现状正在让你流血"，改变的价格就变得无足轻重。在 Agent 互联网时代，这句话的杀伤力会被放大——因为 AI 的每一次"推荐错误"，都在真实地杀死企业的订单。

## 八、创业想法三：专家档案变 Agent 工具（Expert Archive → Agent Tools）`[章节 8：想法三]`

**核心观点**
创作者、媒体公司、分析师、顾问手里有多年积累的内容档案，这些内容目前靠广告、赞助、订阅变现。把它们包装成"完成特定任务的 Agent 工具"，是 Agent 互联网时代最性感的变现方式。

**深度阐述**

第三个创业想法，Greg 说"可能是创作者、媒体公司、分析师、顾问和研究人员最有意思的机会"——这些人坐在多年的宝贵内容资产上。什么是有价值的内容？YouTube 视频、播客、新闻通讯、模板、社区帖子。

**现在，这些内容怎么赚钱？** 广告、赞助、有时是订阅、有时是社区、有时是咨询。但 Greg 提出了一个极具想象力的 remake：**在 Agent 互联网里，档案库（archive）本身可以变成一个工具。**

他给出三个画面感极强的示例：

- 想象一个"创始人 Agent"，它可以访问某位创业专家的完整档案，为你点评创业想法；
- 想象一个"销售 Agent"，它使用某位销售教练的框架，帮你重写 cold email；
- 想象一个"健身 Agent"，它基于某位教练的训练哲学，为你生成个性化训练计划。

**这个想法的本质是：Archive to API（档案变接口）。** 拿一个人的专业经验，打包成 Agent 可以调用的形态。

**核心执行纪律：从一个具体任务开始。**

Greg 警告了一个最常见的错误：你跑到创作者面前说"我们要把你的整个大脑变成 AI"——这听起来既吓人又含糊，而且老实说，像是一个"应该被法律禁止的 SaaS 落地页"。[他原话的幽默感十足] 你必须说得极其具体：

- "你有 300 条关于销售的视频，我们把它变成一个让你的粉丝改进 cold email 的工具。"
- "你有 500 集关于创业的播客，我们把它变成一个创业想法反馈工具。"
- 对设计师说："你有十年设计拆解内容，我们把它变成一个落地页点评工具。"

一个档案，一个痛点任务，一个工作流。

**建造流程四步法：**

**第一步：选人。** 找一个拥有深度档案和明确受众的专家。Greg 个人偏好 B2B 领域的专家——因为"普通商业创作者"太泛了。但适合的人选可以是：以 cold email 闻名的人、Shopify 增长专家、本地企业收购专家、税务策略专家、健身编程专家、设计拆解博主。

**第二步：收集档案。** 转录视频和播客、搜集新闻通讯、清洗文档。

**第三步：打标签。** 按任务、主题、受众、案例、框架、结果来标注档案。Greg 格外强调这一步的重要性，并给出了一个犀利的批评："很多人在这步偷懒，把所有东西扔进向量数据库，然后就收工了。那通常只会给你一个'带自信的搜索框'（a search box with confidence），但真正的产品需要结构。"

具体怎么打标签？销售档案：按开发客户、主题行、报价、异议处理、跟进、个性化、送达率、成交来标注。创业档案：按想法、市场、切入点、分发、定价、MVP、社区、护城河、案例来标注。**"最好的工具一定是极其具体的。"**

**第四步：构建一个有用的工作流。** 对销售专家：用户粘贴 cold email → Agent 用该专家（他举了 Alex Hormozi 的例子）的原则点评 → 引用原始课程出处 → 重写邮件 → 打分 → 给出一个可以立刻跑的测试。产品到此为止，不需要更多功能。对创业专家：粘贴你的想法 → Agent 告诉你切入点、目标客户、第一版报价、第一个分发渠道、本周要验证什么。（Greg 在这里提到他正在做的 IdeaSeer.com——他最受欢迎的功能之一就是接入 MCP，把自己的数据做成"让 LLM 变得更好"的燃料。他说："我在这里是在实践我所宣扬的。"）对房地产专家：粘贴一笔交易 → Agent 检查假设、识别风险、对照专家标准、告诉你该不该追问经纪人。

**为什么这个生意能成？** 因为创作者已经拥有分发渠道和信任积累，你不需要操心营销和获客。受众想要的是专家的专业能力，而专家不可能对每个人做一对一咨询——"这个产品让这种能力民主化了"。

**商业模式怎么设计？** 可以收 19 到 50 美元/月；可以打包进付费社区；可以作为咨询业务的漏斗前端；也可以授权给代理公司或软件公司。而当 Cloudflare 式的支付轨道成熟，档案成为资源、Agent 按请求付费时，**创作者在知识被使用的那一刻就能收到钱**。

Greg 用一句极具杀伤力的话总结了这种新模式对比旧模式的优越性："这比指望有人在一个七年前的 47 分钟访谈视频前面看完贴片广告要好得多。"

**他观察到的最大误区：** 市面上已经有不少"与专家聊天"（chat with an expert）类的产品，但都太宽泛了。"与销售创作者聊天"没有意义，有意义的是"使用这套销售系统重写你的 cold email"。**具体场景、结果导向，才是正确的产品形态。**

**个人感受**

这一段是 Greg 情绪最高昂的部分。他不再只是在描述一个机会，而是在描述他自己正在做的事——IdeaSeer 就是"档案变工具"的实践。他的语气里有一种"我找到了答案"的兴奋感，同时对"扔进向量数据库就完事"的粗糙做法毫不留情。

**延伸思考**

"档案变工具"背后有一个关于知识产权的深刻命题：在一个 AI 可以无限复制知识的时代，**独家的、有结构的、有品味的专业判断反而更值钱了**。专家们的真实壁垒从来不是信息本身，而是从信息到判断的那个"加工过程"。如果你能把那个加工过程变成产品——哪怕只是某个极其狭窄的任务——你就把一个人的大脑变成了一项可扩展的资产。这对于百万级的独立创作者来说，是一个从未有过的机会：他们第一次可以不靠流量分成，而靠"知识被使用时"直接获得收入。

**精华收获**

"不要做'与专家聊天'，要做'用专家的方法完成一件具体的事'。" 这个教训可以外推到所有 AI 产品设计：用户不为"对话"付费，用户为"结果"付费。把专家的档案变成"结果的生成器"，而不是"聊天机器人"，这是从工具到产品的分水岭。

## 九、贯穿三条路的主线：Agent 需要的四样东西 `[章节 9：统一框架]`

**核心观点**
三个创业想法共享同一个底层逻辑：Agent 需要干净、可信、有用的资源才能做好工作。资源可以是数据、结构、访问权、专家知识、工具或支付规则。

**深度阐述**

Greg 在讲完三个想法后，特意停下来做了一个"收束"动作，把三者的共性指了出来。他说："连接这三个想法的共同点是——Agent 需要干净、可信、有用的资源来做真正好的工作。"那个资源可以是数据，可以是结构，可以是访问权，可以是专家知识，可以是工具，也可以是一条支付规则。

Cloudflare 的新闻之所以重要，是因为它在建设**访问层和支付层**——这是巨大的事。但 Greg 随即给出了一个非常解放的判断：**你完全不必等 Cloudflare 的 Agent 互联网成熟了再动手。**

- 你现在就可以开始做手动版；
- 你现在就可以把"人类版"卖出去；
- 你现在就可以开始积累数据；
- 你现在就可以打包产品。

等到 Agent 支付普及的那一天，你不是在仓促追赶，而是早就准备好了。"你是早到的人。没有多少人在谈论这件事。"

**他给出了五个自问的过滤器，作为寻找机会的地图：**

1. 什么决策是昂贵的？（What decision is expensive?）
2. 什么信息是混乱的？（What information is messy?）
3. 什么东西在频繁变化？（What changes often?）
4. 谁已经愿意为帮助付费？（Who already pays for help?）
5. Agent 需要什么才能把工作做得更好？（What would an agent need to do the job better?）

用这五个问题扫描市场，未来 6 到 18 个月的行动方向就会浮现。Greg 尤其强调"提前积累"的战略意义——在数据变得超级竞争之前，先把它 curation（策展）好。

**个人感受**

这是 Greg 最真诚的时刻之一。他反复说"我真心相信互联网正在从'人类访问的页面'转向'Agent 使用的资源'——我不觉得这么说很疯狂。你已经看到这里了，也许你也同意。"这是一种创作者与观众之间罕见的信任姿态。

**延伸思考**

"最好的机会现在看起来都很小"——Greg 在结尾不断重复这个判断，里面藏着一种历史感。2009 年，App Store 刚上线时，没有人知道那些小小的 app 会定义下一个十年。2026-2027 年，这一批"Agent 互联网原生"的生意，会不会就是下一批巨头？他提到的"付费的小门"（tiny paid doors）意象特别动人：**未来的伟大互联网公司，可能就是一扇扇 Agent 每天穿过无数次的小小付费门**——门后的资源如此微小，单价不到一分钱，但流量是机器级的、7×24 小时不停歇的。你拥有的不是流量，是"必经之路"。

**精华收获**

行动时间表比什么都重要。Greg 的信号极其明确：现在动手，做脏活、积累数据、卖人工服务、建立行业 know-how。当支付轨道成熟时，你已经拥有了别人需要花两年才能追上的数据资产和客户关系。**正确的时间点是"管道铺好之前先占住水源"。**

## 十、结语：为 2026-2027 年做好准备 `[结尾]`

**核心观点**
Agent 正在成为买家，网站正在成为资源。下一批伟大的互联网公司，可能就是你拥有的那些"Agent 整天穿行的小小付费门"。

**深度阐述**

Greg 用一个深邃的总结收束全片：当人们在 X 上看到 Cloudflare 的新闻，可能会想"哦，有点意思"或者"出版商现在可以给机器人开账单了"。但他要求观众想得更远。**Agent 正在变成买家，网站正在变成资源。** 而下一批伟大的互联网公司，可能就是那些"Agent 全天候穿行的、你拥有的小付费门"。它们现在看起来微不足道——就像 2009 年的 app 一样——但那正是机会的形态。

他最后留下了一句温暖的叮嘱："这是一个资产。我等不及想看到你建造什么、做出什么。如果这期内容对你有帮助，或者让你脑洞大开，给我留个评论、点个赞、订阅一下。我每一条评论都会读。"

**个人感受**

视频结尾有一个极其可爱的瞬间：Greg 说"下次见"，然后发现自己已经说过了，于是支支吾吾地说："呃……我已经说了下次见了。所以……我只是已经开始想你了，你知道的。我等不及下一次录制。再见。"——这种笨拙的真诚，与视频开头"I just want to see you win. I'm rooting for you."（我只是想看到你赢，我为你加油。）遥相呼应。他不是在做一个"知识付费"式的布道，他是真的在给每一个可能在 AI 浪潮中迷失方向的人递上一张地图。

**延伸思考**

回顾整期视频，Greg 真正讲透的其实是一个认知升级：**一切商业都在从"人类决策"转向"机器决策"**。当机器成为消费者，商业世界的物理定律就变了——交易成本趋近于零、规模不再受人力限制、信任变成结构化数据、品牌变成可解析信息。这个转变会碾碎无数旧生意，也会让一群提前布局的人成为新贵。Cloudflare 或许会让 1000 多个 AI 百万富翁诞生，但更准确地说，是"那些理解了 Agent 经济的人"会被浪潮托起。

**精华收获**

请记住这三个动词：**理解**（Agent 到底需要什么）、**积累**（现在就建立数据资产）、**占位**（在支付轨道成熟前，先成为 Agent 世界不可或缺的供应商）。当 2026、2027 年回望时，你会庆幸自己在这个看起来"太早"的时刻就动手了。
