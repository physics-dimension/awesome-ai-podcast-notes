# ChatGPT Agent 实战：八个自动化工作流，让你的 ChatGPT 强大 10 倍

今天，我们要把 ChatGPT 从一个需要你输入提示词的工具，变成一个**24/7 在云端为你自动工作的 Agent**。本视频将是一份完整的指南，教你如何直接在 **ChatGPT 桌面应用、网页应用或 iOS 应用**中设置 Agent，让它们在云端自主完成你的工作。

在**第一部分**，我会解释 ChatGPT 中与 Agent 任务相关的各个模块。在**第二部分**，我会展示我设置过的 **8 个最喜欢的 Agent 工作流**——这些工作流为我和我的业务带来了最大的帮助——以便你也可以创建类似的工作流来帮助自己。

无论你使用的是和我一样的桌面应用、ChatGPT 网页应用（chatgpt.com），还是 ChatGPT 的 iOS 应用，都可以创建这些在云端工作的 Agent。

## 第一部分：ChatGPT Work 基础概念

在深入了解之前，你需要理解几个基础知识。

### 什么是 ChatGPT Work？

ChatGPT 已经进化了，现在有一个新设置叫 **ChatGPT Work**。在这里，聊天机器人变成了一个真正的 Agent——这个 AI Agent 可以访问一台计算机，拥有**文件**和**浏览器**权限，变得越来越像一个真正的员工。你可以在网页应用、桌面应用（ChatGPT Work）以及 iOS 应用中使用它，随时从聊天模式切换到 Work 模式。

### 插件：Agent 的“眼睛”与“双手”

在我看来，ChatGPT Work **最有用的部分是插件（Plugins）**。

举个例子，我可以使用 Notion 插件，然后输入这样的指令：

> 请创建一个名为「承诺与截止日期」的数据库。请查看我的 Gmail 和 Slack，找出过去一周里任何承诺或截止日期相关的内容，把它们放进这个数据库。哦，再看看我在 Whisperflow 上的会议笔记，因为它们现在内置了会议笔记功能。

然后运行这个提示词。

插件之所以如此有用，主要有两个原因：
1. **上下文（Context）**：插件让 Agent 能够获取 Notion、Gmail、Slack 以及 Whisperflow 会议笔记中所有数据的完整上下文。
2. **行动（Actions）**：它不仅能从这些平台提取数据，还能在这些平台中**执行操作**——比如，它真的会在 Notion 里创建一个数据库。

### 案例：4 分钟完成的跨平台分析

注意看，4 分钟后，GPT Work 就完成了任务。你可以想一想，这个任务你自己做需要多久？尤其是当结果是这样的时候：

在 ChatGPT 浏览器或桌面应用里打开它，就能看到它创建的数据库。它浏览了 Notion、Gmail、Slack 和所有会议笔记，找到了所有这些信息：添加了承诺事项、相对方、证据、负责人、来源，还分析了四个不同平台，最后创建了一个全新的 Notion 数据库。**这一切只用了 4 分钟。** 这就是它的强大之处。

对我来说，这总共大约 5 分钟的工作量：其中 1 分钟用来输入提示词，4 分钟等待它的响应。

### 调度（Scheduled）功能

不过，ChatGPT 应用里还有一个功能，就是**「已调度（Scheduled）」标签页**。利用它，我们可以做这样的事情：

## 第二部分：8 个 Agent 工作流详解

基于上述基础功能，下面是我最常用的 8 个 Agent 工作流，它们每天都在自动运行，为我的业务创造价值。

---

### 工作流一：承诺与截止日期管理（Commitments and Deadlines）

> **核心功能**：每天早上自动分析邮件、Slack、会议笔记中的承诺与截止日期，更新 Notion 数据库，并向指定人员发送问责邮件。

这是我最喜欢的 Agentic 工作流之一。我只需点击「更新承诺数据库」，然后进入「已调度」标签页，就能看到「更新承诺数据库」这个任务，设置为每天早上 **8:00** 运行。

为了让这些承诺有人监督，我还添加了一个操作：

> 嘿，我需要你发一封邮件给 agentnative.inc 的 Emily。请把这数据库的链接发给她，这样她就能查看了。你新增的那些内容也请一起加上。邮件里要提到：这是 Riley 已同意的所有承诺和截止日期的完整清单。这封邮件也要每天发送。

你还可以补充说“这应该属于这个自动化流程的一部分”。

**效果**：每天早晨，AI 都会通过插件分析所有这些内容，将它们放进 Notion 数据库，然后以我的名义发一封邮件给 Emily，让她查看并监督这些待办事项。

这就是第一个自动化流程——**每天早晨 8 点**自动运行。

---

### 工作流二：招聘数据库自动化（Hiring Dashboard）

> **核心功能**：自动监控招聘邮箱，将应聘者信息录入 Notion 数据库，并在夜间自动研究每位应聘者的背景。

第二个自动化流程涉及招聘。我之前发过一条推文：

> “如果你想使用或测试 Agent 平台，并把你的学习心得写成文章换取报酬，请给我发邮件。我正在 agentnative 招聘。”

我把邮箱地址附在了上面。现在，我可以非常轻松地让 AI 分析我的邮箱，把所有发过邮件的人添加到一个数据库里。事实上我已经这么做了。

这是我的**招聘看板（Hiring Dashboard）**。里面有很多字段，因为涉及敏感信息，我不方便全部展示。我希望这个看板**每天更新**。

设置方法是：找到你的 Notion 数据库，然后说：

> 嘿，我一直在招聘这个职位。

然后我给出一张这条推文的截图，仅此而已——他们正往上面列出的邮箱发邮件，所有的申请条目都在这个数据库里。接着我把 Notion 链接粘贴进来：

> 请创建一个自动化流程，把所有这些人都添加到那个数据库里。再创建另一个晚上的自动化流程，用来研究这些人，并把相关信息添加到备注中。每天早上添加他们，晚上研究他们。

发送这条提示词后，它会直接在 chatgpt.com 中创建这个自动化。

43 秒后，两个自动化任务就设置好了，都是每天自动运行。

**核心技巧**：如果你把邮箱（或任何你想连接到 GPT Work 的邮箱）发布到互联网上收集信息，就可以直接使用 GPT Work 监控该邮箱，并将其转化为一个仪表盘。

### 工作流三：Twitter 数据抓取（Twitter Scraping）

> **核心功能**：自动搜索 Twitter 上与 Agent 相关的高质量热门推文，存入 Notion 数据库，为内容创作提供素材。

接下来的两个 Agent 工作流涉及社交媒体，具体是针对我新品牌账号 **Agent Native** 的推文。我在 Twitter 上已经做得不错，大概有 **233,000** 名粉丝。但我想要发展我几个月前创建的新账号 Agent Native（也是我正在创建的公司的名字）。我想做两件事：第一，为推文做**研究**；第二，实际**排定推文日程**。

为此，我们使用 **Typefully** 来做排程，用 **Scrape Creators** 来做数据抓取。

这是**自动化流程三：Twitter 抓取**。我使用的提示词是：

> 我想发展我的品牌 Twitter 账号 Agent Native。我专注在 Agent 领域，制作高质量内容，围绕开放 AI Codex 及类似工具。请查看相似工具。你也可以看一下账号 @agentnative。请在 Twitter 上搜索那些超过 100 个赞、与 Agent 发展相关的重要更新、新产品发布、新模型发布的热门推文。我们要使用 Scrape Creators。在下方描述中，我附了一份抓取社交媒体的指南。请在 Notion 中创建一个新的数据库，用另一个叫 scraped tweets 的插件。请立即执行，抓取最新内容。

然后我让它开始抓取。**8 分钟后**，它完成了，我可以直接在浏览器中打开：

里面拉取了所有推文。这里有链接 URL，媒体 URL 也会自动被拉取，我们能看到所有回复、转发等数据。非常酷。这还只是第一步。

接着我补充设置自动化：

> 嘿，请创建一个自动化流程，每天早晨 9:00 自动完成这件事，更新这个数据库。

**效果**：每天早上 9 点，它都会自动运行，更新这个数据库。

### 工作流四：推文草稿自动生成（Commentary Post Drafting）

> **核心功能**：基于抓取的热门推文，在 Typefully 上自动生成 10 条带评论的推文草稿（不直接发布），等待人工审核。

这是**自动化流程四：从我的 Agent Native 账号生成评论型推文**。

这一步我使用 **Typefully**。Typefully 允许你登录多个 Twitter 账号。在设置 → API 中，可以获取 API Key。我已经设置好了，把这个 API Key 给了 GPT Work，现在它可以使用一个叫做 **Typefully Drafts** 的技能。

我的提示词是：

> 请从你刚刚收集的最好的推文里，创建 5 条草稿——不，还是创建 10 条草稿推文吧。这些推文要么是引用转推（quote tweets），要么是附上视频。请查一下如何做到这一点。请在其中的 10 条上操作，发到 Agent Native 账号。**不要真正发布，只在 Typefully 上创建草稿。**

**工作流程**：我们把所有推文收集到巨大的 Notion 数据库里（我们甚至不会去看它，AI 只负责存储数据），然后它把最近或前一天最好的推文添加到 Typefully。之后我就可以过去审核、排程它们。

**3 分钟后**它就完成了。右键点击，在外部浏览器打开，可以看到它创建了所有这些推文，**10 条推文全部准备就绪**。它很好地使用了引用转推，处理视频发布也做得很棒。

> 示例推文：*“语音正在成为编码 Agent 的真实输入层。Gemini 现在可以将你的语音与代码、文件名称、变量和屏幕上的内容进行对照。你不仅会向 Agent 输入提示词，还可以在工作时直接指挥它们。”*

不过我仍然会做一些手动编辑，因为我不希望 AI 完全代替我发推。我相信如果每天投入 10 分钟人工打磨，这些内容会好上 10 倍——毕竟我在 Twitter 上有相当多的经验。

然后我设置自动化：

> 我希望你每天这样做，每天添加 5 条帖子。始终注意我在 Agent Native 上发布的以往推文，从我的语气中学习，尤其是那些表现好的内容。以这些成功的推文作为你今后创作时的范例。

**效果**：每天 9:00，这个自动化流程就会运行。

### 工作流五：播客嘉宾筛选（Podcast Guest Research）

> **核心功能**：使用 YouTube Researcher 技能深度分析 YouTube 转录文本，寻找合适的播客嘉宾并录入数据库。

接下来的四个流程会更快一些。

这是**自动化流程五：寻找播客嘉宾**。我的指令是：

> 请使用 Youtube Researcher 技能做深度分析。这会用 Scrape Creators，以一种特定的方式分析 YouTube 转录文本，为我的播客寻找好的嘉宾。请把它们添加到这个数据库。

这里有一个桌面应用中的小技巧：当你在输入提示词时，可以打开 Notion，找到「播客嘉宾」数据库（这是我之前手动创建的），然后**同时按下两个 Command 键**——它会自动把当前页面作为上下文添加到提示词中。

然后我设置：

> 这也应该做成一个自动化流程，每天上午 11 点运行。

它会做一些研究、往数据库里添加更多人，然后创建自动化。如果之后想修改任何细节，都可以直接点击这个自动化任务进行编辑。

### 工作流六：赞助邮件自动转发（Sponsorship Email Forwarding）

> **核心功能**：在手机上即可创建，自动识别品牌赞助相关的邮件并转发给团队，每天运行两次。

第六个流程我直接在手机上操作。你可以直接在手机应用里创建这些定时任务。

这个需求其实非常普遍，如果你有多个邮箱，我强烈推荐使用。我连接的主力邮箱是 Agent Native 的主邮箱，但有很多人联系我是关于品牌赞助的。所以我希望做**邮件转发**：

> 当有人给我发关于品牌赞助的邮件时，请把它转发到 riley@raugoddia.com。这样我的团队就能看到。每天做 2 次。设置好这个自动化。

这个非常简洁，但很多人会用得上。在已调度任务里可以直接看到「daily forwarded sponsorship leads」（每日转发的赞助线索），如果需要修改可以直接编辑。

---

### 工作流七：短信内容导入（Text Message Ingestion）

> **核心功能**：通过 Codex 的 Messages 集成，读取并总结 iMessage 短信内容，并将业务相关聊天记录存入 Notion 数据库。

第七个自动化有点特殊：这是我唯一在 **Codex** 里操作的流程，因为 Codex 默认拥有更多权限。

这里我们使用新的 **Messages 集成**，它允许我直接从短信中拉取数据。我可以这样说：

> 请用文本总结一下今天 Adam D 给我发的所有消息。

这让 Codex 能直接进入存储 iMessage 的数据库，并准确回答我的任何问题。它甚至可以总结你发过的每一条短信——不过这会消耗大量 token，可能比较贵，但确实可以做到。关键是，你在 Codex 中可以**完全访问自己的短信内容**。

比如，我让它把时间范围改为最近 5 天，它就非常简洁完美地总结了我们的对话。

**我的具体用法**：我可以把与任何人的短信记录导入 Codex，然后存入数据库。对于赞助相关的短信，我就是这样做的。我的内容经理有一个完整的团队，我和他们所有人都有聊天记录。为了让我的 Agents 拥有完整的上下文，它每天早上 **8 点**读取我与 4 个不同联系人的短信记录。如果这些是群聊，它也会一并读取，并将数据存储在 Notion 中——和前面几个流程一样。

**为什么重要**：因为我大量沟通都是通过短信完成的，如果你的 Agent 要有效地执行任务，它就需要拥有你所有的上下文。这是我运行了**很长时间**的一个自动化，价值巨大。

---

### 工作流八：月度全盘总结报告（Monthly Mega Summary）

> **核心功能**：每月末自动调用最强模型，跨所有已连接平台深度分析全部业务数据，生成详细报告存入 Notion 并发送邮件。

最后一个我强烈推荐的自动化，是每月运行一次的**月度总结报告**。

我一直在打磨这个流程。上个月我运行了一次，结果**出奇地好**。这一步我们使用最强的模型 **5.6 soul extra high**，让它可以进行真正的深度分析，写出史上最详细的总结。

我的指令是：

> 现在先不要执行。把这个安排在每个月最后一天，持续接下来 12 个月。

**逻辑**：让 AI 回顾过去一个月，涵盖 Notion、Gmail、Slack、日历、Whisperflow、Google Drive、Scrape Creators 以及它能访问的一切——因为我整个公司的所有上下文都在这些插件之中。它可以用最强的模型分析所有数据，而且**每月只执行一次**，帮助你真正聚焦。

还可以告诉它：

> 把这个报告创建在 Notion 里，并通过邮件发送给 Emily。

这样每个月底，它会自动生成并发送这份报告。你等于在云端部署了一整个智能系统。

这些流程完全可以直接在手机上创建——你只需对着 ChatGPT Work 说出指令就行了。

## 总结：八大自动化一览

以上就是我创建并运行的 **8 个 Agent 工作流**，它们全部通过 ChatGPT Work 自动运行：

1. **承诺与截止日期管理**：分析邮件和 Slack 消息中的承诺与截止日期。
2. **招聘数据库自动化**：自动化招聘数据库。
3. **Twitter 数据抓取**：抓取 Twitter 数据。
4. **推文草稿生成**：撰写推文草稿。
5. **播客嘉宾筛选**：为播客寻找嘉宾。
6. **赞助邮件转发**：邮件转发。
7. **短信内容导入**：导入所有短信（唯一使用 Codex 的流程，可以在本地计算机上运行）。
8. **月度全盘总结**：使用全部上下文进行月度大型总结。

你可以在桌面应用、网页应用或 iOS 应用中查看所有这些自动化任务。
