## 第一部分：基础篇——理解 Cursor 的核心逻辑

### Cursor 到底是什么？`[视频 00:00-05:00]`

**核心观点**

Cursor 本质上是一个"AI 编程代理"——你通过对话告诉它你想做什么，它就能在你的电脑上帮你构建应用。它不只是自动补全代码的编辑器，而是一个能理解意图、主动拆解任务、甚至反问你的智能体。

**深度阐述**

Riley 用了一个非常简单、但极其直观的演示来回答"Cursor 是什么"这个问题。他输入了一条提示词："I want to build a little app that lets me track my calories. Simple app, run it locally, very minimal, make it simple."（我想建一个卡路里追踪小应用。简单应用，本地运行，保持极简。）他特意把需求压缩到最简单，就是为了证明一个核心观点：你完全可以把自己的想法用自然语言"打字"给 AI 代理，它就会帮你实现。

有趣的是，Cursor 没有机械地开干，而是反问了一个问题："What should the app be called?"（应用应该叫什么名字？）Riley 回答说叫 "CalTrack"。1 分 12 秒后，Cursor 完成了构建，显示 "CalTrack is built and running locally"——应用已经在本地跑起来了。Riley 在浏览器里打开它，输入"pizza 100"，点击添加，一个卡路里记录就存了下来。整个过程就像和一个懂技术的朋友聊天，而这个朋友的手速快得惊人。

Riley 对 Cursor 的定义是："Cursor is a tool that allows you to communicate with an AI agent so that it can build apps for you."（Cursor 是一个让你与 AI 代理沟通、让它为你构建应用的工具。）这一定义的点睛之处在于"communicate"——沟通。它不是命令，不是指令，而是对话。这解释了为什么 Cursor 会反问、会澄清需求、会在不确定时征求你的意见。它把你从"写代码的人"变成了"产品经理 + 审阅者"。

**延伸思考**

"用对话构建软件"这个理念正在重塑软件的创作门槛。过去，一个想法要变成应用，需要产品设计、前端、后端、部署等环节，每道环节都有专业壁垒。而 Cursor 把所有这些环节压缩成一个对话框。这不是说程序员会失业——而是说，程序员的价值将从"写代码"转移到"定义问题"和"把关质量"。Riley 在后面的视频中会反复证明这一点：他的大部分工作就是打字、看效果、提修改意见、再打字。

**精华收获**

- Cursor = AI 编码代理，你通过对话让 AI 为你构建应用
- 不要把 Cursor 当成"自动补全"工具，要把它当成一个可以对话的开发伙伴
- 一个最简单的应用，从想法到跑起来，可以在 1 分钟多内完成

### 下载与界面导航 `[视频 05:00-08:00]`

**核心观点**

安装 Cursor 只需要去 cursor.com 下载，登录账户后你会看到两个核心界面：IDE（编辑器）窗口和 Agents（代理）窗口。视频的教学重点在 Agents 窗口。

**深度阐述**

下载流程本身没什么特别的：访问 cursor.com，点击下载按钮，安装后打开，用 Cursor 账户登录。但登录后，Riley 特意解释了一个新手容易困惑的地方：界面有两个窗口。

第一个是 IDE 窗口（编辑器窗口），长得像 VS Code——有文件树、代码编辑区、终端等。第二个是 Agents 窗口，这是 Cursor 相对较新的核心交互界面。两个窗口之间通过顶部的按钮切换。"This video we're going to be talking about the agents window."（这期视频我们主要讲 Agents 窗口。）

刚打开 Cursor 的 Agents 窗口时，你会看到几个区域：New Agent（新代理）、Search（搜索）、Automations（自动化）、Customize（自定义）。Riley 提醒我们，如果你是新用户，这里不会有任何钉住的（pinned）会话，也不会有工作区（workspaces），因为你还没创建过任何东西。

在 Agents 窗口里，你创建的每一个"Agent"本质上就是一个独立的聊天会话（chat session）。Riley 现场演示：他创建一个新会话，问了一句"Hello, what model are you?"，Cursor 自动给这个会话命名为"model inquiry"。如果会话多了（Riley 说他一周可能同时处理 20 个会话），你可以重命名、可以钉住（pin）——就像浏览器的书签一样，把重要的会话固定在左侧。他能用 `Cmd+N` 快速新建会话。

**个人感受**

Riley 对界面讲解的方式很轻松，但他特意花时间解释"会话钉住"和"工作区"这两个概念，说明即使是基础功能，理解透彻了也能极大提升效率。他反复强调一个词：organization（组织方式）。他让你把 Cursor 理解成一间办公室——会话是桌面上的文件夹，工作区是不同的办公桌。

**精华收获**

- 在 cursor.com 免费下载 Cursor，用账户登录
- Agents 窗口是主要交互界面；IDE 窗口适合代码审阅
- 用 `Cmd+N` 新建会话，重命名和钉住功能帮你管理多个并发项目
- 工作区 = 一个文件夹，存放项目的所有文件

### 工作区与 Plan Mode：到底要不要用？ `[视频 08:00-12:00]`

**核心观点**

工作区（Workspace）就是电脑上的一个文件夹，Cursor 在这个文件夹内创建项目的所有文件。Plan Mode（规划模式）是 Cursor 帮助用户在动手前理清思路的模式，但 Riley 的个人观点是：既然 Cursor 已经是一个通用代理，你直接向它要方案就行，没必要专门进入 Plan Mode。

**深度阐述**

Riley 演示了一个完整的建站流程。他按下 `Cmd+N` 新建一个会话，然后点击"Create Workspace"（创建工作区），在桌面上创建一个名为"agent native"的文件夹——这是他品牌、播客和即将推出的移动应用的名字。注意，在真正创建会话之前，工作区不会显示在左侧列表中。当你输入第一条提示后，工作区才会出现。

有趣的是，Riley 一开始的提示词触发了 Plan Mode（规划模式）。Cursor 默认开启了 Plan Mode，然后它输出了一堆问题，想要 Riley 回答——比如关于品牌定位、目标用户等。Plan Mode 的设计初衷是：当你脑子里的想法还不完整时，让 AI 帮你把需求梳理清楚，避免吭哧吭哧建了一半才发现方向错了。

但 Riley 的观点非常直接：他很少用 Plan Mode。"Personally, I don't use this mode very often. In fact, if I ever want it to create a plan, I'll just say, 'Hey, can you create a plan?'"（说实话我不常用这个模式。如果我真想要计划，我就直接说'嘿，能给我一个计划吗？'）他的理由很充分：Cursor 现在是一个通用代理，你问它要什么它就给什么——问计划给计划，问歌词给歌词。Plan Mode 是旧时代的产物，那时候 Cursor 更像"一个只能建应用的 AI"，而不是"一个能对话的代理"。

不过 Riley 也展示了如何进入 Plan Mode：输入 `/plan`，或者点击加号选择 Plan。如果你喜欢这种结构化的方式，它仍然可用。但他给的建议是："I just speak to the agent like it's a human."（我就把代理当人一样说话。）这意味着，不要被模式束缚，直接把你的需求说清楚就行了。

**延伸思考**

Plan Mode 的存在本质上反映了 AI 工具设计的一个趋势：从"功能开关"走向"对话即功能"。早期的 AI 工具有各种按钮、模式、配置项，但现在的趋势是——所有能力都应该通过自然语言访问。Riley 的观点很先锋：当 AI 足够聪明时，这些"模式"反而成了人机交互的障碍。你不需要进入"规划模式"，你只需要说"帮我规划一下"。

**精华收获**

- 工作区 = 项目文件夹，所有文件都在里面
- 每个项目建议用独立的工作区
- Plan Mode 对新手可能友好，但直接向代理要计划更高效
- `/plan` 或加号菜单可以快速进入规划模式

### 模型选择、图片输入与代理工作流 `[视频 12:00-16:00]`

**核心观点**

Cursor 内置了多个 AI 模型供选择（如 Grok、Fable 5、GPT 5.6 等），你可以在设置中添加更多模型。更重要的是，你不仅能用文字提示，还能粘贴图片作为设计参考，AI 会照着图构建。

**深度阐述**

Cursor 的一大特点是可以随时切换底层模型。Riley 的默认选择是 "GPT 5.6 6 Soul"（视频中提到的模型名），但他也会根据任务改用 Fable 5（更贵更强）或 Grok 4.5（更快更便宜）。模型切换器就在输入框附近，和任何 AI 工具一样，点一下就能换。如果列表里没有你要的模型，可以进入设置 → Models → 添加模型。他还提到有一个"View all models"开关，能看到 GPT 5.6 Luna、GPT 5.4 Nano 等旧型号——但 Riley 的提醒是："most likely these models under this toggle are models that you don't necessarily need"（这些开关下面的模型大概率是你不需要的），因为它们在性能、价格上都已不具备优势。

接下来是他展示的一个关键技巧：图片输入。Riley 想为 Agent Native 建一个和某个参考网站风格一致的落地页。他的做法是：截图参考页面 → 复制（Cmd+C）→ 在 Cursor 的提示框中粘贴（Cmd+V）。此时提示框里同时有文字和图片。这个能力看起来简单，但对"用 AI 开发"的体验提升是巨大的——你不再需要费尽口舌描述"我想要一个什么样的页面"，直接给图就行。

他给出的完整提示词是："Please just create a site like this. Run it locally on my computer. I want that to say Agent Native. And I want it to be horizontally moving from left to right on the screen."（请创建一个类似这样的网站，本地运行。标题写 Agent Native，并希望文字从左到右水平移动。）AI 开始工作后，你会发现一个 UX 细节：提示词会被"收起来"，避免遮挡工作界面。同时你能实时看到 AI 正在做什么——正在编辑 4 个文件、探索了 2 个文件、执行了 1 次搜索、运行了 3 条命令，甚至能看到每一行代码的增删。这种透明感让用户对 AI 的工作状态了如指掌，而不是一个让你干等的黑盒。

构建完成后，Riley 打开 Finder（Mac 的文件管理器），在桌面上的 agent native 文件夹里看到了 AI 生成的所有项目文件。而应用本身已经"run locally"——在本地运行了。你点击输出信息里的链接，就可以在外部浏览器打开它。Riley 对此的评价是："I mean, look at this. This is actually kind of cool. I like the graphics that it created for it."（你看这个，真的挺酷的。我喜欢它做的图形。）语气里带着一种"我什么都没干，AI 就给我做了一个网站"的惊喜感。

**个人感受**

Riley 展示的"图片粘贴进 Prompt"这个功能，其实改变了 AI 编程的交互范式。过去是翻译——把你的视觉想象翻译成文字再翻译成代码；现在是直通——图像直接进入 AI 的视野。这尤其适合非设计师出身的人，你可以从 Dribbble、Behance、任何网站上截图，让 Cursor 照着做。这是"提示工程"升级为"演示工程"的典型例子。

**精华收获**

- 按需切换模型：强任务用 Fable/GPT 系列，日常任务用 Grok 系列
- 在设置 → Models 中添加或查看所有模型
- 直接把截图粘贴进输入框，AI 会以图为参考构建应用
- 用 `Cmd+S` 在模拟器中截图、`Cmd+Shift+4` 截屏（Mac），剪贴板图片可直接粘贴到 Cursor

### Cursor 内建浏览器与排队 vs 操控 `[视频 16:00-20:00]`

**核心观点**

Cursor 内置了一个浏览器，你可以直接在 Cursor 里预览和交互你的应用，甚至可以在浏览器里继续对 AI 发指令。此外，理解"排队（Queue）"和"操控（Steer）"的区别，是高效使用多任务的关键。

**深度阐述**

外部浏览器虽然能用，但 Riley 透露了他的习惯：他几乎不用外部浏览器预览应用，而是用 Cursor 内置浏览器——右键点击运行链接，选择"Open in Cursor Browser"。在这个内建浏览器里，你可以全屏预览、关闭侧边栏，而界面底部有一个输入框，按下 `Cmd+I` 就能随时唤起。这意味着：你在浏览应用的同时，就可以直接给 AI 提修改意见——所见即所得，发现问题立刻说。

Riley 现场演示了他的迭代工作流。他对着首页右上角一张带"AI"字样的图说："I don't like that. I kinda like the vibe that you have with the other ones. They're more colorful. Can you please change that one?"（我不喜欢这张，我喜欢其他图的风格，更彩色一些。能换掉它吗？）为了速度，他把模型切换成 Grok（更快）。几乎同时，他又说："Can you please make the subscribe button at the top like a blue color instead of red? It's too jarring."（能把顶部订阅按钮从红色改成蓝色吗？红色太刺眼了。）一个浏览器窗口，两个连续提示，AI 按顺序处理——订阅按钮变蓝了，底部图片也换新了。

Riley 在这里抛出了一个非常独到的概念："a really underlooked thing when it comes to learning these super apps"（学习这些超级应用时一个非常容易被忽视的点）——排队与操控的区别。所谓"排队"（queue），就是你输入一条提示并确定，它会排在当前任务后面，等 AI 手头的工作完成后自动执行；所谓"操控"（steer），就是在 AI 还在工作时，你按下发送键，把新提示"插队"进去——相当于打断它当前的工作，转向新指令。这两个按钮在 Cursor 输入框附近，Riley 认为理解它们能让你的操控感提升一个档次。

他还提到一个让非程序员很安心的细节：几乎所有代码类 AI 工具（Codex、Claude Code 等）都有类似的设计。学会一种，就掌握了这类工具的思维模型。

**个人感受**

Riley 的演示让人感受到一种"与 AI 协作"的节奏：不再是一问一答的回合制，而是"我在浏览，它在改；我继续浏览，它继续改"的并行流动。他是那种会不断对 AI 输出反馈、把 AI 当成一个坐在旁边改稿的设计师的人。这种交互方式，比传统的"写需求文档 → 交给开发 → 等待交付"要自然得多。

**延伸思考**

排队和操控的设计，其实反映了 AI 工具正在从"纯执行"走向"任务管理"。多个提示并行、优先级排序、打断和恢复——这些概念来自操作系统，现在被移植到了 AI 对话中。未来，AI 工具的使用效率可能不取决于模型有多聪明，而取决于这些"操控层"的设计有多顺手。

**精华收获**

- 用 `Cmd+I` 在 Cursor 浏览器中随时唤起 AI 输入框
- 把截图反馈直接粘贴给 AI，它能精准理解你的视觉问题
- 排队（Queue）：在任务完成后按顺序执行新提示
- 操控（Steer）：立即打断当前任务，优先处理新指令

### 设计模式与技能导入 `[视频 20:00-24:00]`

**核心观点**

设计模式（Design Mode）是 Cursor 中最炫酷的功能之一：你可以像点击网页元素一样直接选中页面上的任何部分，然后针对它发出修改指令。此外，Cursor 支持"技能"（Skills）——可复用的指令文件，你甚至可以从 Codex、Claude Code 等其他 AI 代理平台导入技能。

**深度阐述**

Riley 花了不少笔墨介绍 Design Mode。当你在 Cursor 浏览器中打开应用后，点击"Design Mode"开关，此时网页上的元素变得"可点击可选中"。他演示了一连串精确操作：选中一个标题 → "Please make this a little smaller font."（字体调小一点）；选中一个被截断的字母 G → "The G here is cut off on bottom. Please fix."（底部字母 G 被切掉了，请修复）；选中一个箭头图标 → "Please put a different icon than the arrow here. Something that makes sense."（换一个比箭头更合理的图标。）每次修改都准确命中，Riley 的点评是："This design mode allows us to get a little bit more precision."（设计模式让我们的操作更精准。）

随后，Riley 聊到了一个对"老手"极其重要的功能——技能（Skills）。技能本质上是一个 Markdown 指令文件，存放在你的电脑上，描述了一个特定的工作流程。你可以按下 `/` 呼出技能菜单，选择"YouTube Researcher"让 AI 去研究 YouTube 相关内容，选择"YouTube Thumbnail"让 AI 生成特定风格的缩略图。技能里写的就是"当你做 X 时，请按照这种风格做"的规则。

### 成本控制：别让你的钱包被 Fable 烧穿 `[视频 58:00-60:00]`

**核心观点**

在 Cursor 中，模型选择直接决定你的花费。Riley 的建议是：默认使用 Auto 模式或 Grok 4.5，只在必要时才用 Fable 5 或 GPT 5.6 等高端模型。

**深度阐述**

Riley 在这段给了一个非常实在的省钱策略。他的原话是："If you only use Fable, you're going to spend so much money on this."（如果你只用 Fable，你会在这上面花掉太多钱。）

他的建议是：
1. **Auto 模式**：Cursor 会根据你的提示自动判断用哪个模型，在质量和速度之间动态平衡。Riley 说："It'll basically take your prompt and decide what the best model is. And it will basically balance between quality and speed. And this is recommended for most tasks."（它会根据提示词自动决定最佳模型，在质量和速度之间取得平衡。这是大多数任务的首选。）
2. **Grok 4.5**：Riley 对 Grok 的评价极高："Grock is an incredibly affordable model for how good it is."（就它表现出的质量而言，Grok 便宜得不可思议。）而且他认为 Grok 会变得聪明得多："I expect Grock is going to get 10 times more intelligent."（我预计 Grok 会聪明 10 倍。）

他总结自己的实用主义观点："So I would avoid using Fable 5 and GPT models, right? And I would use the Grock models in auto if you want to keep the costs down within cursor. And they're also much faster."（所以我建议避免使用 Fable 5 和 GPT 模型。如果你想在 Cursor 里控费，就用 Auto 模式 + Grok。它们还快得多。）简而言之：日常任务用便宜快速模型，创意探索或生产交付再动用高配模型——就像你不会天天开跑车去买菜。

**精华收获**

- Grok 4.5 是目前性价比极高的选择
- 只有重要任务（如应用最终交付）才用 Fable 5 / GPT 5.6
