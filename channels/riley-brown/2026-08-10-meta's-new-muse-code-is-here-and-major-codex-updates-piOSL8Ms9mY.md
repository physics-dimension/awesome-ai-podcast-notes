## 章节 1：两周风暴的开场——AI 代理世界正在发生什么？ `[章节 1]`

### 核心观点

过去两周，AI 代理领域的新闻密集程度堪比过去一个季度：Meta 入局、OpenAI 迭代、Cursor 转型、中国模型冲击、Anthropic 承压，以及新的协作范式出现。

### 深度阐述

视频一开始，Riley 就用一种“憋了很久终于可以开讲”的语气说：“The last two weeks in the world of AI agents have been very interesting.”（过去两周 AI 代理世界非常非常有意思。）他不是在客套——他随后列出的清单几乎涵盖了所有前线平台：Meta 发布了 Muse Code，一个用来和 Claude Code、Codex 竞争的命令行代理；DeepSeek、Kimmy、Qwen 来自中国的新模型同时登场；OpenAI 的 Codex 获得了一系列大更新；Cursor 正在从“开发者工具”向“超级应用”转变，和 Claude、Codex 正面竞争；Google 则似乎渐渐被边缘化；还有一个叫 Buzz 的新平台，专门用来创建和调度 AI 代理团队。

Riley 特别强调了一个概念：这个视频是 **“agent-native update”**——不是泛泛的 AI 新闻，而是聚焦于“前沿 AI 平台和模型”的最新动态，目的是让观众能够用 AI 代理提升生产力。这显示了他的内容定位：不追逐花哨的模型参数，而是关注真实工作场景中的工具能力。

### 个人感受

### 延伸思考

**为什么 agent 突然成了所有巨头的必争之地？** 因为 ChatGPT 这类聊天机器人的形态已经证明：对话本身不是终点，能替用户完成实际任务才是价值所在。当每一家都在做 agent，竞争焦点就从“谁来回答”变成了“谁来执行”。Google 的暂时缺席，在 Riley 眼中几乎是一种“出局信号”，这在本章结尾他还会提到。

### 精华收获

不要再用“哪个模型聪明”来挑选工具，而是看**哪个 agent 能在真实工作流中替你完成更多环节**。未来两周的每一次更新，都是在重构这个答案。

## 章节 2：Meta 入局——Muse Code 发布与价格碾压 `[章节 2]`

### 核心观点

Meta 发布 Muse Code，一个运行在终端里的通用软件工程代理，由 Muse Spark 1.2 模型驱动。其基准测试成绩介于 OpenAI 的 Opus 级模型和 GPT-5.6 Terra 之间，而 API 价格比 Top 级模型便宜 5 到 6 倍——这可能是它最致命的武器。

### 深度阐述

Riley 一上来就感叹：“The first agent native update comes from Meta, which is very rare. They don't usually do that many things on the frontier.”（第一条更新来自 Meta，这非常罕见。他们通常不怎么在前沿发力。）但这次是 Mark Zuckerberg 本人在 Twitter 上亲自宣布：

> "Releasing Muse Code in beta today. It's a terminal coding agent that takes on complete software engineering tasks across large repos, planning changes, writing code, validating the results powered by Muse Spark 1.2, the model, a coding focused model update."
> （今天发布 Muse Code beta。它是一个终端编码代理，能够在大规模代码库中承担完整的软件工程任务：规划变更、编写代码、验证结果，背后由 Muse Spark 1.2 模型驱动，这是一个专注编码的模型更新。）

Riley 解释，根据 Zuckerberg 公布的基准测试，Muse Spark 1.2 的能力正好落在 **Opus（大概是 Claude Opus 4.x/5）和 GPT-5.6 Terra** 之间。GPT-5.6 Terra 是指 OpenAI 的“中间档”模型，介于更强大的 Soul 和更轻量的 Luna 之间。这样一来，Meta 选择了一个非常聪明的切入点：不求最顶尖，但求“够用且便宜”。

接着，Riley 给出了一个很直观的价格对比表（他在画面上展示了输入和输出价格）：

- GPT-5.6（具体应为 GPT-5.6 Soul？这里他说 GBT 5.6，但全文语境是 GPT-5.6）：输入+输出成本合计约 **$35**
- Claude Opus：约 **$30**
- Meta Muse Spark（顶级型号）：只需 **$5.50**

这个差距是 5 到 6 倍。换句话说，你用 Meta 的模型完成同样数量级的编码任务，成本只有 OpenAI/Anthropic 顶级模型的六分之一左右。而且，这里还没有算上 OpenAI 正在降低其他模型价格的事实——Riley 说后面会谈到 GPT-5.6 Terra，因为 OpenAI 已经给新 Codex 模型降价了，使得它和 Meta 的价格“有可比性”。也就是说，Meta 并不是唯一在打价格战的人。

### 个人感受

Riley 对价格相当兴奋，但他也给出了一个诚实的忠告：“every single update that I talk about is best understood by actually testing it out, not just looking at some charts.”（我聊到的每次更新，最好的理解方式是亲自测试，而不是只看图表。）这句话既是方法论，也带着一种“别被营销冲昏头脑”的冷静。

### 延伸思考

**为什么 Meta 突然愿意在 agent 领域抢跑？** 因为 META 已经拥有庞大的开源生态（Llama），而 Muse Spark 1.2 看起来是“编码专用”的垂直模型。它不必在通用智能上战胜 GPT-5.6，只要能以极低的成本解决真实工程任务，就足以从开发者手里抢走大批 API 调用。更重要的是，Muse Code 是**终端工具**，它说明 Meta 在争夺“开发者工作流入口”而不是“聊天入口”——这是比 UI 更深的绑定。

### 精华收获

选模型时，“性能排行榜”只是表面，**单位任务成本**才是决定商业落地的关键。Muse Code 的出现，标志着“可以闭眼用的便宜 agent”正式进入主流。

## 章节 3：两分钟安装 Muse Code——让 Codex 帮你下载竞争对手 `[章节 3]`

### 核心观点

Muse Code 的安装非常简单：Riley 直接打开 Codex，让 Codex 帮他把 Muse Code 下载到本地，然后在终端里运行 `muse` 命令，用 Meta 账号登录即可开始使用。

### 深度阐述

Riley 强调 Muse Code 是终端编码代理，所以安装思路和传统安装完全不同——你不需要去官网找安装包，而是可以**让另一个 AI agent 帮你安装它**。他在视频里演示：

打开 Codex，然后输入：

> “Hello there, Codex. Can you please download the latest Muse code by Meta? Mark Zuckerberg announced it yesterday. The terminal coding agent. Please download it now so I can use it in my terminal.”
> （你好，Codex。你能下载 Meta 最新的 Muse Code 吗？Mark Zuckerberg 昨天发布了它，这是一个终端编码代理。请现在下载它，这样我就可以在我的终端里使用。）

然后 Codex 运行了一串命令，几秒钟后就完成了下载。Riley 说：“So all we have to do is run this and we will wait a few seconds and it's going to download it to our computer.”（我们只需要运行它，等几秒，它就会下载到我们的电脑上。）

接下来演示运行。在 macOS 上，Riley 要么打开“终端”App，要么在 Codex 桌面应用里按 `Command + J` 呼出内置终端。在终端里输入 `muse`，会看到首次运行提示：`Trust and continue` 或 `Quit`。点击“信任并继续”后，进入登录界面，可以选择“浏览器登录”或“设置 API Key”。Riley 选择“浏览器登录”，浏览器自动打开 Meta 平台登录页，登录完成后，终端就变成了 Muse Code 的交互界面。

他立刻问了一句：“Hello, what model are you?”（你好，你是什么模型？），Muse Code 回答：“I am Musecode powered by Meta's Muse Spark.”（我是由 Meta 的 Muse Spark 驱动的 Musecode。）整个过程不超过两分钟，所以视频标题才会强调“2 分钟设置完成”。

### 个人感受

Riley 的演示充满了“agent 吃 dogfood”的幽默感：用 OpenAI 的 Codex 安装 Meta 的竞品。这本身就是 AI 时代的一个隐喻——工具之间的边界是松动的，安装成本被压缩到了“一句话”。

### 延伸思考

当“安装软件”从“搜索—下载—安装—配置”变成“让另一个 agent 远程执行”时，**分发渠道的价值正在转移**。Meta 不需要在终端里做推广，只需要在社交网络上发布一条消息，然后所有 agent 都会自动知道如何安装它。未来的工具安装，很可能是 agent 之间的互相推荐。

### 精华收获

利用已有的 Agent（如 Codex）去安装、配置另一个 Agent（如 Muse Code），是当前最快速的“吃螃蟹”方式。不必等待教程，直接命令你的智能体去执行。

## 章节 4：Muse Code 实战——创建 Wii 保龄球游戏与 YOLO 模式 `[章节 4]`

### 核心观点

Muse Code 可以快速创建并运行一个保龄球游戏，但默认的沙箱模式会阻止持久服务器，必须通过 Codex 设置让 Muse Code 默认进入“YOLO 模式”，它才能自动运行所有终端命令。

### 深度阐述

Riley 想实际测试 Muse Code 的能力，于是下达了一个趣味任务：

> “Hey, I want you to create a bowling simulator game. Like it should be like wee bowling. I want you to make a wee bowling and then I want you to run it locally so I can play it.”
> （嘿，我想让你创建一个保龄球模拟游戏。应该像 Wii 保龄球那样。我想让你做一个 Wii 保龄球，然后把它运行在本地，这样我就能玩了。）

Muse Code 开始并行处理：规划、写代码、启动本地服务器。Riley 在画面上展示了终端输出：各种进度日志、创建文件的步骤，最终完成了游戏。他试玩了一下，可以调整旋转（spin），把球转向左侧，然后击倒球瓶。虽然球瓶看起来不是特别精美，Riley 笑着说：“This isn't the greatest game ever created, but that's probably a problem of prompting.”（这不是史上最好的游戏，但这大概是提示词的问题。）

但这个例子的重点不在于游戏是否好玩，而在于**默认安全限制**。Riley 注意到 Muse Code 默认会提示：“This sandbox blocks persistent servers.”（这个沙箱会阻止持久服务器。）为了让它能自动运行应用程序，需要让 Muse Code 进入 **YOLO 模式**（You Only Live Once，即“什么都不问，直接执行”）。

他在 Codex 里输入：

> “I need you to set it so that Muse Code always defaults to yolo mode. Please just do that right now for every session.”
> （我需要你把 Muse Code 设置为始终默认 YOLO 模式。请现在就对每个会话执行。）

这个操作实际上修改了 Muse Code 的配置文件。完成之后，新开一个终端会话，输入 `muse`，界面会显示 `YOLO mode`，意味着这个 agent 现在拥有对电脑的完全控制权——可以运行任何命令、修改任何文件、启动任何进程。Riley 提醒，这样你就不用再为每个操作手动授权。

### 个人感受

Riley 展示了日常使用的真实状态：一边开着终端让 agent 干活，一边在 Codex 里调整配置。他没有刻意回避“YOLO 模式有风险”，而是轻描淡写地给出“让你拥有完全控制权”的建议，这种“工具人”心态很符合“agent-native”的先行者身份。

### 延伸思考

YOLO 模式是“代理自主性”的光谱末端。默认沙箱是为了安全，但真正的生产力来自“完全自主”。这引出一个深层问题：当 AI agent 能自由操作你的电脑时，信任边界在哪里？未来系统可能需要“分级自主授权”——按任务重要性和环境隔离来动态分配权限，而不是非黑即白。

### 精华收获

- 想让 Muse Code 运行持久服务，必须开启 YOLO 模式。
- 你可以在任何 agent 的配置中全局设定默认模式，避免每次手动确认。
- 试用新工具时，先运行一个简单但完整的任务（如一个小游戏），能快速暴露它的行为模式。

## 章节 5：Codex 桌面端更新——活动面板与革命性应用内浏览器 `[章节 5]`

### 核心观点

OpenAI 的 Codex 桌面应用（也就是 ChatGPT 桌面版）在过去两周获得了两个重大更新：全新的“通知/活动”侧边栏，以及重构后的应用内浏览器，后者可以让用户以全屏沉浸方式预览网页，并随时呼出底部聊天栏进行修改。

### 深度阐述

Riley 首先展示桌面端的侧边栏。以前这里的项目视图比较固定，现在新增了一个“通知栏”（notifications bar），本质上是一个“活动面板”（activity pane）。它会显示最最近完成的任务，并标注每个任务运行的**具体文件夹路径**，让你一眼就知道这个 agent 在哪个目录下工作。Riley 用了个词：“really intuitive to use”（非常直观），并且说“它更像通知，显示最近完成的那个”，这正是他个人最常用的视图。

第二个更新是他声称“很久以来最喜欢的设计更新”——应用内浏览器（in-app browser）。Riley 之前已经在做网站了，我们看到他打开了一个略显粗糙的网页，这正是 agent 生成的。他点击底部一个按钮，将网站全屏化，让 agent 聊天区域隐去。随后他从底部滑出一个很小的输入条（上面有 ChatGPT 的 logo），直接对着仍在运行的 agent 说：

> “The line that goes beneath episodes. I don't really like that very much. Can you also please make the dark purple behind the logo at the top better? The whole top bar is pretty ugly. Can you please fix that?”
> （episodes 下面的那条线我不太喜欢。你能把顶部 logo 后面的深紫色改一下吗？整个顶部栏都很丑。请修复一下。）

agent 在浏览器里实时修改网页，Riley 则能在底部看到它正在做什么。这个输入条还可以固定到页面底部，变成一个浮动按钮，点击展开、再点击收起。这样一来，用户可以完全沉浸在网站预览中，随时发号施令，而无需切回开发界面。

不过有一个小坑：如果你同时使用 **Whisper Flow**（一个语音或翻译类悬浮工具），它会挡住这个底部按钮。Riley 演示了如何把 Whisper Flow 拖到屏幕右侧，然后将 OpenAI 的编辑入口放在左侧或某处，两者兼容，互不遮挡。

### 个人感受

Riley 说“this is my favorite design update that they've made in a very long time”（这是他们很久以来我最喜欢的设计更新），并且特意演示了怎么处理 Whisper Flow 干扰。这段体验描述很有个人色彩——他显然每天都在用这些功能，而且真的享受这种“在成品上直接提需求”的感觉。

### 延伸思考

应用内浏览器的意义不止于“预览”。它把 agent 的反馈循环从“终端输出”升级为“视觉网页”，让非开发者也能参与调试。这种“所见即所得”的 agent 交互，是未来超级应用的雏形——就像 Figma 之于设计，Codex 的浏览器之于 AI 开发。

### 精华收获

- Codex 的活动面板能快速定位任务所在目录，适合多项目并行。
- 应用内浏览器支持全屏 + 底部呼出编辑栏，这是“在成品上改需求”的最佳体验。
- 如果你使用 Whisper Flow，需要手动挪动悬浮窗，避免遮挡 OpenAI 入口。

## 章节 6：Codex 的 Chrome 扩展与 Chat/Work 切换——从聊天到“工作台” `[章节 6]`

### 核心观点

Codex 发布了 Chrome 浏览器扩展，与桌面应用无缝同步，让用户直接在网页上让 agent 操作浏览器并生成内容；同时 ChatGPT/Codex 应用顶部新增了“Chat/Work”切换，Work（GPT Work）将成为云端“超级工作台”，可以手机控制邮件、日历和所有插件。

### 深度阐述

Riley 进入了 Codex 的“插件”面板，搜索 “Chrome”，下载扩展。安装后在 Chrome 工具栏会出现一个 ChatGPT 图标，你可以把它放到显眼的位置。接着，他直接选定页面上的文本，对扩展喊话：

> “Please prepare a tweet based on the recent memories that you have of me based on what we did today. Come up with the best possible tweet and I can fire this off, control this browser and make the tweet, but don't post it, just cue it up.”
> （请根据你对我最近记忆——也就是今天我们做的事——准备一条推文。想出最好的推文，并控制这个浏览器填写推文，但不要发布，只是准备好。）

扩展接管浏览器，自动打开推文编辑框、填入文字、但没有点击“发布”。Riley 很幽默地说：“Okay. Well, we need to work on the tweet, but it queued it up.”（好吧，我们还得改改这条推文，但它已经准备好了。）

更重要的是，Chrome 扩展里的所有对话会话都会同步到 Codex 应用。在 ChatGPT/Codex 应用侧边栏里，可以看到一条名为 “draft tweet from today” 的会话。点击会话右侧的三个点，选择“Open in app”，即可在完整桌面应用中继续编辑。这意味着浏览器只是一个前端入口，所有任务状态都在同一个 agent 内存中。

紧接着，Riley 介绍了 ChatGPT/Codex 顶部的**新开关**：Chat 和 Work。他说“Chat/Work toggle”，现在用户可以轻松切换。然后他坦诚地承认：

> “I was wrong about Codex. I said that I wish they didn't split up Codex and GPT work. I was wrong. GPT work is insanely useful. It's completely cloud-based and it is... I use it every day.”
> （我过去对 Codex 的判断是错的。我曾说希望他们不要把 Codex 和 GPT Work 分开。我错了。GPT Work 极其有用。它完全基于云端，而且我每天都在用它。）

GPT Work 不但可以处理文档、表格等，还能在手机端控制所有在 ChatGPT 里集成的插件——邮件、日历、云端存储，等等。Riley 直接表示：“I hardly ever use chat anymore. I just use work.”（我几乎不再用聊天模式了，我只用工作模式。）

### 个人感受

这段是 Riley 罕见的“自我打脸”时刻，而且他解释得非常自然：他从怀疑到真香，完全是因为亲身体验。他提到自己刚发布了一部关于 ChatGPT Work 的深入指南视频，说明他对这类“从聊天到工作”的转变投入了很多精力。

### 延伸思考

“Chat/Work”两个字的差异，本质上是“对话式交互”和“任务式执行”的分野。Chat 适合询问，Work 适合交付。当 agent 可以从云端直接操作你的邮件、日历和浏览器时，它就是你的“数字分身”。这种形态将重新定义个人助理的定义——不再只是回答问题，而是**替你完成一天的工作**。

### 精华收获

- Chrome 扩展让浏览器成为一个“可被 agent 操作的画布”，你只需说一句“帮我发推”。
- 所有会话在 Chrome 扩展与桌面应用间同步，大大缩短了上下文切换。
- GPT Work 是云端的一体化工作台，手机上就能遥控一切；如果你还没开始用，值得立刻试一试。

## 章节 7：Cursor 转型前夜——从编码工具到超级应用，连接 Google Workspace `[章节 7]`

### 核心观点

Cursor 的 CTO 公开承认，公司内部大量使用场景已经与编码无关；Cursor 正在经历“revamp”（彻底整改），计划成为一个“完整超级应用”，第一个信号是连接 Google Workspace，让 agent 能直接操控 Google Docs、Sheets、Slides。

### 深度阐述

Riley 引用了一条推文（可能是他自己的，或者他转发的）：

> “ChatGPT desktop app or formerly known as Codex. Their biggest competitor right now is Cursor, not Claude desktop.”

他说这是“我有可靠消息来源”（I have it on good authority）：Cursor 正在经历重大变化，会变成和 Codex 一样的“超级应用”。第一个公开信号就是 Cursor 现在可以连接到 Google Workspace。

> “Everyone thinks of Cursor as a tool for coding. We thought so too. But inside the company, many of our use cases aren't coding at all. Research, data analysts, bug triage, and project management, just to name a few. As it turns out, coding agents are pretty good foundation for all kinds of work.”

### 延伸思考

### 精华收获

- Cursor 即将进行大改版，其目标是与 Codex 全面对标，不仅仅是代码编辑器。
- 在 Cursor 中连接 Google Drive 后，agent 可以直接创建和修改 Sheets/Docs/Slides。
- 使用便宜模型（如 DeepSeek V4 Flash）完成简单任务，成本几乎可忽略不计；重要任务再切换昂贵模型，这是高效的模型路由策略。

## 章节 8：三款中国新模型——Kimmy K3、DeepSeek V4 Flash 与 Qwen 3.8 Max `[章节 8]`

### 核心观点

中国三款新模型集体发布：Kimmy K3 综合最强但价格偏贵；DeepSeek V4 Flash 以极低成本提供惊人性能，部分基准任务成本仅为“Fable”级模型的 1/105，但官方宣布即将大幅涨价；Qwen 3.8 Max 也有可圈可点之处。

### 深度阐述

Riley 这一节的信息密度特别高，我们来逐条拆解。

**第一：Kimmy K3**。Riley 说：“Kimmy K3 is the best out of all three of the new models, but it's also the most expensive.”（Kimmy K3 是三款新模型中最好的，但也最贵。）很多人对模型质量兴奋，但对价格失望：“It's like almost as expensive as Sonnet for certain tasks.”（在某些任务上几乎和 Sonnet 一样贵。）尽管如此，他还是推荐大家试一试，因为“I highly recommend trying it out”。

**第二：DeepSeek V4 Flash**。“Probably the most interesting”（可能是最有趣的）。因为它“for certain tasks, it is 105 times more cheap than Fable 5”（对于某些任务，它比 Fable 5 便宜 105 倍）。“Fable”是 Riley 对 Anthropic 新模型的称呼（可能是 Claude Fable？实际上应该是“Anthropic 的模型”，可能是他给 Claude 起的代称，或者是字幕听错，但这里是“Fable”）。不管怎样，意思是这个模型便宜到令人咋舌。

Riley 随后引用了 DeepSeek 官方的一条公告：

> “We plan to raise the overall pricing for Deepseek API services in the near future with a significant increase expected. Please plan your usage accordingly.”
> （我们计划在不久的将来提高 DeepSeek API 服务的整体定价，预计涨幅会很大。请合理规划你的使用。）

这消息让很多人担心。但 Riley 引用了开源圈名人 DAX（来自 OpenCode）的解读：

> “On the upcoming DeepSeek price increase, we've been able to reproduce their current prices even on rented GPUs. So, this likely isn't because they're losing money. It's traffic shaping because they're overloaded.”
> （关于即将到来的 DeepSeek 涨价，我们已经在租用 GPU 上复现了他们目前的价格。所以这可能不是因为他们在亏钱，而是因为超载，在为流量塑形。）

也就是说，涨价不是成本驱动，而是需求太旺盛。DAX 认为，后续会有美国公司可以以类似当前价格托管这个模型，所以价格下降是迟早的事。

Riley 还引用了 Klein（Klein 可能是某个博主）的担忧：

> “While Deepseek V4 Flash is significantly cheaper on price per token, this could be misleading if the overall cost per task ends up being higher due to more turns being made. However, Artificial Analysis reports DeepSeek completing the same benchmark tasks as Fable at 105 times lower cost, which is absolutely insane.”
> （虽然 DeepSeek V4 Flash 的每 token 价格便宜得多，但如果在同一任务中需要更长的多轮对话，最终单任务总成本可能更高。然而，Artificial Analysis 的报告显示，DeepSeek 在相同基准任务上以比 Fable 低 105 倍的成本完成了任务，这绝对疯狂。）

这里其实是在说“单价便宜”可能不等于“总成本便宜”，但至少基准上确实便宜了 105 倍。

Riley 给出了个人判断：“I believe that DeepSeek V4 Flash may get more expensive in the future. Maybe it'll get three times as expensive. Maybe it'll get five times as expensive in the short run because there's so much traffic... But I think over the long run, like over the next two months, this model will get significantly cheaper or a model just as good as it will get as cheap as the model is now.”（我相信 DeepSeek V4 Flash 未来可能会更贵：短期可能涨 3 倍甚至 5 倍，因为流量和需求实在太大。但从长期看，未来两个月内，这个模型会大幅降价，或者出现另一款同等质量的模型，价格和现在差不多。）所以他现在给出的建议是：在接下来一两周内，抓紧时间好好测试这些模型，因为价格窗口很短暂。

**第三：Qwen 3.8 Max**。Riley 没有展开，只说“we also have Quen 3.8 Max”并称“all good in their own way”，但视频中主要聚焦前两者。他特别在 Cursor 中演示了如何把 DeepSeek V4 Flash 设为默认模型——在模型选择里就能切换。

### 个人感受

Riley 对于中国模型的态度不是“忧患”，而是“机会”。他像电商分析师一样计算着每 100 万 token 的价格，对短期涨价无所谓，因为“每过几周，新的开源模型就会发布，成本只会持续下降”。他说：“The truth of the matter is every few weeks new open models are released and the costs are simply going down.”（事实是，每隔几周就有新的开源模型发布，成本就是一直在下降。）

### 延伸思考

当某一款模型便宜到几乎零成本，你唯一需要做的决策就是：**什么任务值得用“贵模型”，什么任务用“便宜模型”就够了**。这种“模型路由”能力将成为个人生产力优化的关键技能。同时，DeepSeek 的涨价警告也提醒我们：流量洪峰下，任何云服务的价格都可能短期波动，所以不要将核心流程绑定在某一个单一供应商的定价上。

### 精华收获

- 新模型三选一：Kimmy K3 最强但贵；DeepSeek V4 Flash 极致便宜，但官方已预告大幅涨价；Qwen 3.8 Max 同样值得关注。
- 在成本问题上，用“任务完成成本”而不是“token 单价”来衡量。
- 未来两个月的窗口期，适合用 DeepSeek V4 Flash 批量做低价值、高频次任务。

## 章节 10：Buzz——你的第一个“AI 代理团队”即将出现 `[章节 10]`

### 核心观点

我们正进入“AI 代理团队”时代。Buzz（Jack Dorsey 的新平台）本质上是一个为 AI 代理设计的“Slack 克隆”，你可以在里面 @ 提及不同的 agent（如 Claude Code、Codex），让它们互相协作完成任务；还能配置新的 agent（如 Cursor + Kimmy K3）。Riley 认为这将是未来 4–6 个月最值得关注的方向。

### 深度阐述

Riley 先总结了今年上半年：“The first half of the year was kind of the open-claw personal agent movement.”（今年上半年像是“OpenClaw 个人代理”运动。）OpenClaw 是早期让普通用户也能运行个人 AI 助手的开源项目。而现在，他认为：“I believe that we're moving into the team of AI agent movement.”（我们正进入“AI 代理团队”运动。）

然后他介绍了 Buzz：“This is Jack Dorsey's new platform where it is a Slack clone basically except it's made to be used with AI agents.”（这是 Jack Dorsey 的新平台，基本上是一个 Slack 克隆，但它是为 AI 代理准备的。）

Riley 在 Buzz 的工作区里已经运行着现有的 Codex 和 Claude Code 两个 agent——它们以频道成员的形式存在。他在一个频道里发消息：

> “Hey Claude and Codex, work together to build an app that lets me use DeepSeek.”（嘿，Claude 和 Codex，一起协作构建一个能让我使用 DeepSeek 的应用。）

两个 agent 都“已读”，并显示正在工作。Riley 强调：“I can message them as if they were just humans and they will actually work together to get it done.”（我可以像对待真人一样给它们发消息，它们真的会一起合作把事做完。）

在“Agents”标签下，可以看到完整的代理团队列表。你可以添加 Cursor、Devin 等，并且可以指定任意模型作为默认模型。Riley 现场演示创建一个新 agent：选择“Cursor”作为执行器，然后选择“Kimmy K3”作为模型（这样就是由 Kimmy K3 驱动 Cursor），给它起名 “cursor with Kimmy”，并设置系统指令：“You are a content agent.”（你是一个内容代理。）创建后，这个新 agent 开始运行。Riley 让 Codex 把 “cursor with Kimmy” 添加到所有频道：

> “Hey Codex, please add cursor with Kimmy to this channel and all other channels.”

Codex 随即执行，而 “cursor with Kimmy” 也回应：“I handled it myself. I joined all seven channels: content, visual, coding, general, research, management, and notes.”（我自己处理了，我加入了全部七个频道：内容、视觉、编码、通用、研究、管理和笔记。）

在界面底部，你可以看到“谁正在工作”的状态指示器——某个 agent 正在处理，另一个要求审批。这就是一个微型的“团队协作看板”。Riley 说，这类平台现在还很初期，就像一个早期的开源项目：“It's not super easy yet. The same way that OpenClaw wasn't very easy early on.”（现在还不算简单，就像 OpenClaw 早期一样。）

但他相信演进速度会很快：GPT Work 已经把个人代理做成了云端服务，而 Buzz 代表的“团队代理”将在 4–6 个月内成型。他对大公司员工的建议是：

> “I highly recommend if you work at a large company to be the person who can build a team of agents for your team or create an agent that everyone on your team can access to get things done.”
> （如果你在大公司工作，我强烈建议你成为那个“能为团队构建一组代理”的人，或者创建一个所有团队成员都能访问的 agent 来完成任务。）

他预测未来会有更多的“Slack agents”出现，让配置代理变成像拉群一样简单。

### 个人感受

Riley 在这一段表现出强烈的“未来学家”兴奋，但也透露出对“早期阶段”的清醒。“我认为这还处在非常早期的阶段”，他说得简单，但背后是他在亲自试用 Buzz 后的真实体验。“真的很酷”与“还不成熟”这两种感受并存，也是所有新技术早期的真实状态。

### 延伸思考

“团队 agent”这个概念可能比“个人 agent”更具变革性：当多个 agent 共享同一个频道、互相协作时，**组织结构本身**开始变成软件。传统公司里的“团队”是由人和汇报线组成的，而 Buzz 让 agent 可被创建、添加、授权、监督。这不只是效率提升，而是组织形态的一次抽象——未来的项目管理可能是“管理一个 agent 网络”，而不是“管理人”。

当然，这也带来了控制和责任问题：如果两个 agent 联手把事情搞砸了，谁来承担？随着这种协作范式普及，企业需要新的“代理治理”机制。

### 精华收获

- Buzz 是观察“多代理协作”最好的窗口，它让 Claude、Codex、Cursor 等 agent 可以像同事一样协同。
- 创建定制 agent 只需三步：选择执行器（如 Cursor）、选择模型（如 Kimmy K3）、设定指令。
- 未来 4–6 个月，团队级 agent 平台将快速成熟；先掌握“让 agent 管理 agent”能力的人，将在职场中占据先机。

## 终章：两周之后，我们站在哪里？

Riley 在视频最后并没有做出长篇总结，他只说了一句：“那些是过去两周真正让我感兴趣的东西。希望你喜欢这个视频。”但如果我们把他全部的叙述拼在一起，会看到一条清晰的时间线：

- **个人代理**已经成熟：Codex 的云端 Work、GPT Work 手机遥控、Chrome 扩展，都让“个人 AI 代理”变成日常可用。
- **基础设施**正在发生价格革命：Meta Muse Code 用 1/6 的价格杀入市场，DeepSeek V4 Flash 以近乎免费的成本提供可用能力，OpenAI 也相应降价。
- **竞争格局**正在重塑：Cursor 正在变成超级应用，Anthropic 陷入混乱，Google 暂时缺席。
- **下一幕**是团队代理：Buzz 让多个 agent 像团队一样协作，这可能是未来几个月最大的增量机会。

对于普通用户、开发者或企业管理者，最大的启示可能是：**不要只盯着一款模型或一款工具**。这个领域正以“周”为单位进化，真正的高效来自快速试错、灵活组合和持续跟踪。用 Riley 的话说——一切更新，只有亲自测试才能真正理解。
