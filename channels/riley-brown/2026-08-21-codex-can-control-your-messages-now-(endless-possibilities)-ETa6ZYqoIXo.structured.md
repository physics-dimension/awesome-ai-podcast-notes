## 一、Codex 新功能：完全控制 iMessage

本周第一个代理更新是 Codex 中的全新功能，刚刚在几小时内发布。如果我在 Codex 中键入 **@messages**，界面会看起来像 Apple Messages。

### 示例 1：发送单条消息

我输入：“请给 Emily 发一条消息，说：‘嗨，你买到日用品了吗？’”

Codex 显示：“我正在使用消息发送工作流，找到 Emily，发送确切文本并验证结果。”

然后会出现一个批准确认：“发送给 Emily Lambert。嗨，你买到日用品了吗？——来自 Codex”。我可以删除那个签名，也可以编辑消息，然后点击“继续”。就这样，消息发送给了 Emily。我拿出手机，可以看到确实发送了“嗨，你买到日用品了吗？”。接着我再发一条，说“我真的很饿”。

这只是一个展示。需要注意的是，必须开启 **“请求批准”** 选项，它不会未经批准就发送。

### 示例 2：分析群聊并给出建议

我是在 Codex 中完成上述操作的。当我使用 ChatGPT 桌面应用时，大部分操作都在 Codex 里完成，但我们随时可以切换到 ChatGPT 模式。然后新建一个聊天，选择 **Work（工作模式）**。

接着我可以要求：“请翻阅我和 An Vashall 的对话，我们有一个群聊。我希望你深入分析，基本上是我们聊过的所有事情，然后给我一条总体建议，关于如何改进我的沟通风格和团队协作能力。然后基于此给出一条消息建议，作为我接下来应该对他们说的话。”

所以，如果你有一个超长的群聊，比如和团队的群聊，你可以让 AI 完整分析所有这些对话，无论持续了多久。

注意：这里我没有提到 @messages，所以我可以直接 @messages 确保它能调用该工具。它找到了精确的群聊线程，并显示：“该线程内容很庞大：5月14日至今，跨该群的两个版本，共 3,251 条消息。”它分析了 3,251 条消息，这太疯狂了，而且很可能是真的。

然后它给出反馈：“你最强的沟通特质是创造能量、迅速把混乱的想法变成清晰定位的能力。你也不吝鼓励、乐于助人、情感坦诚且有能力，等等等等。有一点我会改变：要让人明确地知道你是在头脑风暴、征求输入，还是做决定。你经常用同样的强度传达这三种不同状态。一个临时想法出现时，就成了‘我们需要尽快做这件事。’”

我无法完整展示这些，但这确实是分析你在群体中行为的好方法。我觉得，用 Codex 刚添加的这个消息功能来做这种练习，相当残酷但有用。它给出反馈后，我说：“好，发送吧。”然后完全批准，消息就发出去了。你可以在我的真实 iMessage 中看到已发送。我甚至给朋友们发了一张反馈截图，他们说：“靠，真有用。”这就是来自 Codex 的消息。

## 二、Grockbot 的崛起与评价

接下来要讨论的是 **Grockbot** 的兴起，它是 **Cursor** 的超级应用。请记住，**SpaceX 已经收购了 Cursor**，所以它实际上是 SpaceX 的超级应用。许多人认为 Grockbot 是 AI 的又一个“Claude Code 时刻”，但我觉得这么说还为时过早。

- **Bridgemine** 说：“我已经用 Grockbot 替换了我所有的 Hermes 代理。Grockbot 开箱即自带远程计算机，这让设置简单得多，也省去了购买其他 Mac mini 的需要。”
- **Lenny** 说他提前拿到了 Grockbot 的使用权，已经完全入迷。
- **Preston** 说，Grockbot 证明，某些想法只有在完美执行之前，才算真正被尝试过。

我们还有来自 SpaceX 某位人士的消息。而在我看来，阻碍 Grockbot 的恰恰是 **模型**。Grockbot 的用户界面是世界最好的，iOS 应用的配置易用性也是世界最佳。我会说 **Grock 4.6** 并不是一个很好的模型：它不擅长写作，也不太擅长任何知识型工作任务。如果你让它创建一个文档，与 **GPT 5.6 Soul** 甚至 **Anthropic 的 Fable 模型** 相比，它做得并不好。在知识型工作方面还差得远。然而，SpaceX 的人说，**Grock 4.7 在写作方面会更好**，无论是在 bot 中（即 Grockbot）还是总体上。我很期待。

目前我的建议是：给你自己的 Grockbot 喂一些你以前手写内容的例子。它会随着时间学习并适应你的风格。Grockbot 会记住这些并随着使用而改进，这很令人鼓舞。所以，Grock 4.7 大概会在两到三周内发布，我听说会更好。我确实认为这个平台如果拥有像 5.6 Soul 那样好的模型，它真心会成为我从事所有代理工作的首选工具。

## 三、超级应用平台对比

接下来快速谈谈这些不同平台之间的差异，以及我认为每个平台的强项。首先是我的使用量排序：**Grockbot、Codex、ChatGPT，然后是 Claude**（无论是 iOS 应用还是桌面应用）。这就是我使用它们的大致比例。

### 1. 易用性：Grockbot 胜出

Grockbot 有各种各样的小机器人（bots）。你可以创建新 bot，或者直接使用自己的赞助内容 bot/内容 bot，让它检查视频、Slack、Notion 等，然后告诉你下一步该做什么。这种为特定任务准备的小机器人体验非常好。它的 iOS 应用配置极其简单，并自动与桌面应用连接，无需任何远程设置。而且每个代理都有自己的**例程（routine）**——在 iOS 应用里点击内容代理，就能看到它的例程。

相比之下，ChatGPT 应用很难说清该去哪里完成工作：去 Codex？ChatGPT 和 Work 的区别是什么？很多人会困惑。GPT Work 非常强大，有很好的应用内置浏览器，但比 Grockbot 更令人困惑。Grockbot 是独立产品，很容易理解。

### 2. 内置浏览器：Codex 无人能敌

**Codex 的桌面应用内置浏览器**。当要求 Agent 访问网站或创建 Notion 文档时，它会在侧边浏览器中打开。我认为理想的超级应用 UI 是：左边是 Grockbot 这样的代理列表，右边能打开浏览器，那会非常棒。

### 3. 模型：ChatGPT 与 Claude 接近，Grockbot 掉队

在模型方面，除非你是拥有巨额预算使用 Fable 的大公司，否则 ChatGPT 略胜一筹，因为 **GPT 5.6 Soul 比 Claude Opus 5 好得多**（我个人并不认为 Opus 5 很好）。如果你能负担得起 Claude，那么 Claude 的模型最好；但平均来看，两者大概不相上下。

而 **Grockbot 的模型是最大缺点**（大红色圆圈，扣三分）——远远比不上 ChatGPT 和 Claude 的最佳模型，这也是我使用 Grockbot 少于 ChatGPT/Codex 的原因。

### 4. 知识工作与文档：Anthropic 有明确优势

在电子表格、演示文稿、前端设计等**知识工作与文档**领域，Anthropic 的模型明显更好，有巨大优势。

### 5. iOS 应用：取决于你想要什么

如果你想要最简单的 iOS 应用，选 **Grockbot**（配得上半分）：容易配置，像一个小型代理团队。如果你想要最强大的，选 **ChatGPT 应用 + Codex Remote**：可以远程连接 Codex，并使用**实时语音**。不是普通实时语音，而是远程部分里的实时语音，它可以实际启动 Codex 会话。

我在演示中要求它：“启动一个 Codex 聊天，制作一个比较 Grockbot、ChatGPT 和 Claude 的落地页。”然后它真的在 ChatGPT 里创建了一个新的代码会话，显示：“构建一个精美、响应式的单页落地页，比较 Grockbot、ChatGPT 和 Claude。”这很酷。所以这一项 Codex 值得分。

### 6. 小结与我的选择

大体格局如下：**Grockbot 正在赢得易用性和上手速度**（无论桌面端还是 iOS 端）；ChatGPT 和 Claude 在模型上并驾齐驱，但 Grockbot 的模型是最差优势。iOS 应用我认为 ChatGPT 最强，浏览器也是 ChatGPT 最强。每当我创建 Notion 文档、Google 文档时，我都直接在 Codex 浏览器中打开，所有账号都登录在 Codex 浏览器里。

但我仍使用 **Claude** 的主要原因，是它能创建更好的**知识工作文档**——所有类型的文档都更好。而且 **Opus 和 Fable（尤其是 Fable）** 在创建高质量 PDF 方面表现出色。这就是我使用 Claude 的原因。

## 四、Anthropic 系列更新

### 1. Claude Code 中的设计模式（/design）

第一个更新是：在 **Claude Code 桌面应用**中，直接输入 `/design` 可以调用 **设计模式（Design mode）**。设计模式原本是 Claude 的一个独立产品，非常受欢迎，拥有庞大受众。现在 Anthropic 正在把 Claude Design 的一些功能直接加入 Claude Code。

演示视频中，输入 `/design` 后，界面提示“根据用户最常使用的功能重新设计 composer”。由于连接了 Claude Code，它会把 Claude Design 当作一个技能来使用，在侧边草拟设计稿。它不会直接修改你的应用代码，而是查看你的应用，创建草稿，然后让你选择要实施的设计，并且可以完全自定义。最关键的是，你可以输入设计想法，在类似迷你 Figma 的界面中调整，然后说：“我制作了一个新画板，带一些变化，请把它实施到实际应用中。”这样就给你提供了更多的设计控制权。我非常喜欢这个更新。

### 2. Claude Co-work 登陆移动端和网页端

几天前，Anthropic 让 **Claude Co-work** 在所有付费计划的**移动端和网页端**可用。Claude Co-work 更加类似于 **ChatGPT Work**，因为它是运行在云端的代理。此前 Co-work 只限桌面应用，你无法在手机上访问云端版本；现在手机和网页都可以用了。

- **网页端**：通过切换 **Co-work 标签** 访问，类似于 OpenAI 的 Chat/Co-work 模式。桌面应用也同样，在主页标签中有 Chat 和 Co-work。
- **iOS 端**：略有不同，没有 ChatGPT iOS 应用那样的 Chat/Co-work 标签。你需要点击侧边栏，才能看到 Co-work。然后可以创建新任务，在项目中工作。

说实话，这有点令人困惑：怎么才能判断自己处于 Co-work 模式？此外，Claude Co-work 和普通 Claude 聊天会话有什么区别？界限仍然模糊，这和 OpenAI 在 ChatGPT 与 ChatGPT Work 之间的困惑非常相似。但现在你可以访问云端 Co-work，它本质上是云端运行的代理，可以完成更复杂、持续更久的任务。最酷的是，你可以使用世界上最好的模型：**Fable 5**。

### 3. 终端输出风格自定义

最后一个小更新：给喜欢在终端使用 Claude 的用户。运行 `claude` 命令后，输入 `/config`，在设置中搜索 **输出风格（output style）**，按右键，就可以在 Claude Code 的不同说话方式中进行选择，例如 **主动型（proactive）、解释型（explanatory）、学习型（learning）** 等。这是新功能，让你精确自定义 Claude 与你交流的方式。

## 五、Slack Code：代理进入协作频道

最后一项更新是 **Slack Code**，我认为它有点被低估，尽管已经获得 200 万观看。Slack 今天发布了 Slack Code，初期代理来自 **Anthropic、GitHub、Cognition 和 Vercel**。这是 Slack 的直接公告。

视频演示中：如果用户需要帮助，可以直接在 Slack 中标记一个编码代理（如 Claude），而无需离开 Slack。例如要求它更新网站上的最新设计。Slack 不再把代理放在常规频道中，而是为它创建一个**专用代码频道（code channel）**。

这呼应了我几周前和 **Buzz**（为 AI 代理开发的 Slack 克隆）讨论过的话题：我不喜欢 Slack 的一点是，在 Slack 内使用的代理（如 Claude Tag）无法创建新频道。现在，新的 **Slack Code 代理可以创建新的代码频道**，非常有趣。不过，这个功能目前还不适用于通用代理用例，更多是为开发者准备的。但我认为，这是 Slack 允许代理在频道中大展拳脚的开始，也是未来在 Slack 中更多使用 AI 代理的开端。

该代码频道拥有正确的队友和来自之前对话的上下文，让代理立即投入工作。这不是传统的编码体验（一个人和一个代理在孤岛中独自工作）。在代码频道中，**整个团队和代理一起构建**，不需要专门工具，全部在 Slack 内完成。

核心价值在于：编码——尤其是 **vibe coding（随性编码）** 或使用 AI 代理构建应用——过去是独自完成的：代码在本地运行，AI 代理修改应用，你在电脑上测试，然后提交 PR。现在，你可以和 Claude 在群组环境中提示，其他人都能看到你对代理的提示，然后代理构建应用，这变成了一个**协作过程**。

我不认为这只会局限于编码。我相信这是所有代理工作的未来：与 AI 代理和其他人类协作，以最高水平完成工作。因为与 AI 代理交流本身就是一种技能，与他人一起做是很有价值的——别人可以告诉你“你不应该这样提示，应该那样提示”。我认为这是**代理原生公司**的下一次迭代。

正如演示所说：“团队共同引导代理开发，这是一个全新的、真正的多人体验。”**多人代理（Multiplayer agents）** 就是当前趋势。我在上一期说过：2026 年上半年是关于个人代理；今年下半年则是从个人代理过渡到为个人创建代理团队，最终走向多人体验——许多人类与许多代理互动，共同目标是发展业务。我认为这非常令人兴奋和有趣。
