# Opus 5 发布了，但新的 Claude 语音模式更重要

本视频来自 Riley Brown 的 YouTube 频道 Agent Native，他详细解读了 Anthropic 和 OpenAI 的最新发布，并分享了如何从这些 AI 工具中获取真正价值。

## 引言

Anthropic 刚刚发布了 Opus 5，它在许多方面优于 Fable，而成本仅为一半。我们先来聊聊这个。但在我看来，比模型发布更酷的是，Anthropic 刚刚在其 iOS 应用中推出了语音模式，可以与 Opus 5 结合作为实时语音代理，并且可以将此语音代理连接到我们现有的所有应用和工具。然而，在这次语音发布前 10 分钟，OpenAI 也在 Codex（OpenAI 的 AI 代理平台）中发布了语音功能，允许你通过语音实时控制 Codex。所以，今天我也会谈谈这些更新。我们还会覆盖 Anthropic 和 OpenAI 在过去几周内发布的所有先前产品。最后，我会告诉你我计划如何在我的初创公司中使用所有这些功能——因为这就是我们在 Agent Native（一个专注于 AI 代理的播客）上讨论的内容。

## Opus 5：一半成本，接近前沿的模型

在我录制本视频时的大约 5 小时前，Claude 推出了 Opus 5（Anthropic 最新发布的 AI 模型）。他们将 Opus 5 描述为一款**“深思熟虑且主动的模型，接近 Fable 5（Anthropic 的前沿模型）的前沿智能，而价格只有一半”**。有趣的是，他们使用了“接近”这个词，但发布的模型对比卡却显示，Opus 5 在除四个类别之外的所有方面都更好。他们在卡片中写道：Opus 5 在**代理性编码**、**知识工作**、**新型问题解决**、**代理性搜索**、**计算机使用**、**代理性编码**、**商业工作流**方面表现最佳，**生物学**也更优。只是**多学科推理**稍弱，**法律**和**健康**领域未达到最佳。但实际使用中，我感觉这款模型和 Fable 差别不大，只是似乎差了一点。

早期访问者 **Dan Shiper**（我信任其 AI 模型评测意见的人）给出了公正评价。他说：“这个模型很难让人喜欢。我们花了整整一周测试它的编码、写作、知识工作以及内部代理。它对抗指令，在工作完成前就停止，并且一般不能很好地与我们现有的技能和插件（如复合工程）配合。我们的第一反应是：‘他们把我的宝贝怎么了？’然后，我们删除了现有技能，从头开始。”——这正是我认为许多企业主、经理、运营人员和知识工作者在测试最新模型上浪费大量时间的原因。如果每次新模型发布都要重做所有技能，那完全是浪费时间。Dan 最后总结道：Opus 5 是“穷人的 Fable”，它拥有 Fable 的很多性格怪癖，却没有 Fable 真正的天才。

现在，当你打开 Claude 桌面应用，无论是使用聊天、Co-work（协作工作模式）还是 Claude Code，都能看到新模型 Opus 5，并且可以亲自测试。Anthropic 实际上将 Opus 5 定位为企业、知识工作者和开发者的**日常模型**。在营销材料中，他们提到“知识工作”的次数远多于“编码任务”。因此，我认为测试它的最佳方式可能是在 Home 标签中使用 **Claude Co-work**。

具体测试如下：我切换到 Opus 5，然后输入提示词：“请提取 course.com 网站的内容。这是为了获取品牌信息。你可以用 Firecrawl（一个提取网站品牌信息的工具）来提取任何网站的品牌。然后给我制作一份专业幻灯片，面向投资人用于 A 轮融资。数字可以虚构。它必须是一份能搞定工作的最终版幻灯片。让它惊艳。”接着我使用 Co-work 提交了该提示。我承认，我后悔了——我输入这个提示 41 分钟后它还在运行。不过最终，40 多分钟后它完成了演示文稿。我必须说，这份演示文稿质量极高，是我见过最好的 PowerPoint 之一。如果你对比 chorus.com 的首页和生成的幻灯片，会发现品牌风格非常接近，幻灯片本身极其出色，甚至包含了各种 Logo，我非常喜欢。它只是耗时太久。所以，这款模型真的很强，我推荐在 Claude Co-work 或 Claude Code 中试用它。但我不会在它身上花太多时间，因为我想引出我认为更重磅的更新——**Claude iOS 应用中的全新语音模式**。

## Claude iOS 语音模式：实时语音代理

就在昨天，Anthropic 在 iOS 应用中推出了语音模式。现在，你可以按下应用中的白色语音按钮。而且至录制时，该功能甚至已经可以和 Fable 搭配使用了。当然，你也可以选择 Opus 模型进行对话。为了演示，我使用 Opus 语音进行了一场实时对话：

我问道：“怎么样，老兄？”
Claude 回答：“没什么，正往你视频里实例化呢。听起来你正在演示点什么？你在那边忙什么呢？”
我说：“嗯，我正在构建点东西。有一个 Notion 文档，叫做 ‘Agent Native Weekly’。我在 22 号创建的它，现在正在拍摄，视频里会讲到 Opus 5、Anthropic 的语音模式。我们视频里还谈了其他什么？你能去 Notion 里搜索一下告诉我吗？”——可以看到 Claude 正在搜索 Notion。
Claude 回答：“找到了。除了 Opus 5 和语音模式，你还有关于 Codex 和 Claude 互相复制、中国模型是否会被封禁、Kimi K3 发布、软件是否已死、我们是否已经处于奇点等方面的章节。”
我说：“对，多谢。实际上，你能编辑这个 Notion 文档吗？”
Claude 回答：“可以，我有 Notion 页面的更新工具，可以添加章节、调整措辞等。你想改什么？”
我说：“好。你注意到 ‘Anthropic / OpenAI 语音模式’ 那一节里面有个叫 ‘Claude 语音’ 的子标签吗？现在是空的。请你针对新的 Claude 语音功能做些研究，然后写出七到八条简洁的要点，涵盖它的功能和用例，并附上你所用来源的链接。就在它标注 ‘Claude 语音’ 的地方，我刚刚移除了原有要点，请你直接添加进去。”——Claude 立即添加了信息，做得很好。
我继续说：“在文档最下面，那里有 ‘这对企业意味着什么’ 的部分。在它下面，我想你帮我新增一个章节，用标签页形式列出你觉得我应该在视频里涵盖的内容。”
Claude 完成并告知：“已添加一个名为 ‘本周你的行动’ 的章节，包括四个标签：周一这样做、关注什么、我的观点、结语。”
我说：“哇，太酷了。接着，你能告诉我一点我的邮件情况吗？给我个最新摘要。不要说出公司或人名，只告诉我邮件里发生了什么。”
Claude 回答：“当然，保持匿名。真正需要你处理的有：两张订阅工具的付款失败或逾期，可能是一张存卡过期了。另外，有个人今天见过面后发来跟进邮件，想下周在纽约喝咖啡。”
我接着要求：“你能不能起草一封邮件给 emily@notanumber.com？只是创个草稿，这样我回到电脑前就能发送，告诉她视频已完成，我们在录制，且这与 Notion 文档对应。”
Claude 回应：“已完成，存放在你的草稿中。邮件主题是 ‘Agent Native Weekly 录制完成’，并附上了 Notion 大纲的链接，方便她对照。”
最后，我提出了一个创意要求：“嘿，我想让你为我自己 —— Riley Brown —— 创建一个小型 landing page（个人主页），然后部署到 Vercel（一个云部署平台）。”
Claude 回答：“哦，有趣的一转。我先问一句，有什么风格偏好？” 我说：“我希望它体现出 ‘Agent Native 播客 —— 学习 AI 代理的第一去处’，要非常酷。” Claude 表示明白，随即使用部署工具开始构建。过了一会儿，它告诉我页面已上线。但我发现，在语音模式中，Claude 无法给出链接，我需要退出语音模式才能获取。所以我退出了对话，问道：“链接呢？”，然后它输出了可分享的链接。

这个演示展示了：你可以在 Claude 上通过实时语音进行“语音编程”（vibe coding）。但要点是，你能用语音实时创建东西。

## OpenAI Codex 语音与远程控制

Anthropic 并不是唯一一家发布新颖语音功能的公司。OpenAI 也在他们整合后的 **ChatGPT Codex 应用**中发布了语音功能。你现在可以在其中创建新的语音聊天。

我在 Codex 桌面应用上开始了语音对话：“嘿，伙计。我需要你查看我邮箱里的草稿。我大约一分钟前创建了一封发给 Emily 的邮件。请你在 Codex 浏览器里把它调出来。”
Claude 回答：“好的，我会找到那封 Emily 草稿并给你拉上来。”
我看到它已经完成。我接着说：“好，谢谢你。你把它拉上来了，我现在就发送它。”

Codex 还能直接在类似 Canva 的设计画板（本演示中使用了名为 **Paper** 的工具）上进行设计。我先确认了它是否能看到我的 Paper 画板，上面写着“Hello, monkey”。我要求：“请你使用 MCP（模型控制协议）工具。在画板上添加一个小型 landing page。实际上，你在之前的对话中应该有一个我们昨天创建的 Agent Native 网站，请把它添加到画板上，我想重新设计它。” Codex 立刻操作，我亲眼看到代理在画板上编辑。我继续要求：“再创建两个不同风格的变体。” Codex 表示理解并开始并行任务。我又说：“因为你本身不是太强的模型，你可以把这两个变体委托给更强大的模型吗？比如再启动两个对话来做这件事。” Codex 回答：“我在看看能并行什么。杂志风格和终端风格的方向已经放在画板上了，我保留了你原来的。同时我会启动两个高推理任务来创造更多变体。” 我继续要求调整其中一个设计，它立刻进行了修改，效果很好。我感叹：“我们正在用语音自由地创造，这就像在跟 Jarvis 说话。太酷了。”

除了桌面语音，OpenAI 还允许你从手机端使用 Codex 的实时语音。你可以点击远程控制（Remote），用手机控制桌面上运行的 Codex。过去我只能用远程控制打字聊天，现在有了实时语音。我演示了：在手机上开启实时语音，连接后说：“嘿，伙计，你在吗？” Codex 回答：“在，我就在这里。” 我命令：“我需要你查看今天我所有的对话会话，然后启动一个新任务，总结我今天涉及的所有内容，并加入日历。我只想要一个我今日的摘要。你去遍历我所有的 Codex 聊天记录。” Codex 回答：“好的，我来看看。” 我看到它在桌面上运行。我接着说：“再启动一个新对话，给我一份当天邮件摘要。只包含赞助相关的，不要包含产品类邮件。” Codex 确认并创建了一个单独的一次性任务。我接着问：“你看到我现在 Mac 上有什么工具或技能吗？” Codex 回答：“看到了。你的可用 Mac 技能和已连接工具有：Paper、Gmail、日历、Drive、Notion、Slack、浏览器控制、图片和视频处理、社交媒体发布、PDF、文档和表格。另外你的 7 月 24 日复盘摘要也已准备好——你在 Notion、研究、音频设置、Agent Native 设计和自动化方面取得了进展。”

可以看到，我可以通过手机实时语音完全控制我的 Mac。当我下班回家但把电脑留在公司时，我可以通过这个远程控制访问，而现在可以直接用语音操作。即使我身在异地，也能用实时语音和电脑对话，这确实惊人。

## 超级应用之争：Claude 与 Codex 互相模仿的四大功能

Claude 和 Codex 正在相互竞争，它们似乎在进行 Feature 竞赛，互相抄袭。但对那些想在业务中有效使用 AI 代理的人来说，这是好事。我总结出四个典型的“复制”领域：

### 浏览器集成

在 Claude 应用中（仅限于 Claude Code 标签），你可以点击按钮打开一个完整功能的浏览器，并支持多标签页。同样，在 Codex 中也可以打开浏览器、访问任何网站、开启多个标签页，并让代理帮你操作。Claude 在 OpenAI 推出此功能后很快跟进了。

### 三大任务标签

Claude 应用内有三个主要标签：Chat（聊天）、Co-work（协作工作）和 Code（代码）。Codex 应用则可以在 Codex 模式和 ChatGPT 模式间切换，后者包含 Chat 和 Work 标签。本质上它们都是相同的三个类别：**聊天式快速任务**（一次性对话）、**工作式任务**（创建文档、研究、控制邮件和 Notion 等）、**代码式任务**。两家公司都在尝试优化这三个标签的布局，并且不断相互借鉴，几乎每周都在变化。

### iOS 模拟器

在 Claude 应用中，如果你让它创建一个 Swift 应用，它会直接打开 iOS 模拟器，运行应用并在模拟器中显示。在 Codex 应用中，也有一个对应的 **Build iOS App（构建 iOS 应用）** 技能，自动完成同样的工作流，应用会在浏览器中打开模拟器。这是创建 iOS 应用的简易方式。

### 录屏制作技能（Record & Replay）

在 ChatGPT 或 Codex 中，你可以使用“Record & Replay（记录与回放）”技能：让 AI 录制你的屏幕，然后将其转化为可重复使用的技能。Claude 现在也提供了类似功能。在 Claude 的 Home 标签（或 Co-work 中）点击“+”号，选择“记录技能”，即可开始录制屏幕。它会捕捉步骤，然后你可以要求 Claude 分析录制内容并创建一个技能，例如“上传 YouTube 视频”。直接向代理演示操作并让它记住步骤，远比手动编写步骤高效。Claude 桌面版在这个工作流上略优一些。

## 意义与建议：聚焦工作流而非工具

这一切意味着什么？我想引用 Greg Brockman（OpenAI 联合创始人）的一条推文：**“ChatGPT Work 的最佳特性之一是它在云端运行，因此可以从手机端和合上笔记本电脑时使用。”**

这些公司的终极目标是：将 Claude Code 或 OpenAI 这些强大代理的力量赋予每个人，打造一个超级应用，让数百万用户能有效使用 AI 代理。它们通过构建类似 Co-work 或 GPT Work 的环境来实现，你可以在这些环境中直接使用所有工具。我知道的一件事是：使用这些 AI 代理工具将变得极其简单。你只需要懂得如何设置技能或工作流，而它们能在任何设备上访问。

在手机上，ChatGPT 也有一个“Work”切换键。这个“Work”本质上是 Codex 的轻量版，每次使用都会启动一个小电脑。你可以用它执行编码任务、部署到 GitHub 或 Vercel、控制邮件、创建文档等所有操作。很多用户没有意识到这一点。Claude 也支持类似的移动端体验。

所以我的核心建议是：**不要纠结于选择正确的工具或模型**。今天 Opus 发布了，我们讨论它是有益的，但不必在工具选择上耗时过多。无论你使用 Claude 还是 OpenAI 的 ChatGPT 应用，只管深入使用，专注于你的工作流。你不会找到完美的工具，因为它根本不存在。更不用说 Cursor 即将发布其知识工作版本、Gemini 也会推出竞品（不管是 AI Studio 还是其他），还有中国公司在做很酷的事，例如 Z Code（它的超级应用与 Codex 惊人相似）、Kimi K3 也有 Kimi Code。因此，选择哪个平台远不如专注于工作流重要。

如果我能留给你一句话，那就是：**弄清楚如何用 AI 让你的生活变得更好。** 这意味着把你每天做的任务做得更快、更多、更好。使用 AI 来做得更多更好。如果你没有做到这一点，那 AI 对你而言只是昂贵的娱乐 —— 这些 token 可不便宜。所以，尽管我们讨论了这么多模型和更新，我希望根据情景让你认识到：最终你需要学习技能。这就是我制作其他视频的原因 —— 提供想法和实例，展示我如何从这些工具中获取价值，因为那才是你真正要做的事：弄清楚如何从工具中获取价值，然后只专注于价值本身，而不是工具。那才是所有价值的来源。
