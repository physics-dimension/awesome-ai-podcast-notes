# 详细内容

## 一、Grok 4.6：xAI 终于站上牌桌 `[段落 1-2]`

### 核心观点

Grok 4.6 是 xAI 首次真正意义上"追平甚至反超"OpenAI 与 Anthropic 的前沿模型。它的领先领域是**经济价值高的工作、长程专业任务和法律工作**，而非编程基准测试——这背后是 xAI 有意为之的战略选择：让 Agent 服务每一个知识工作者，而不仅仅是程序员。

### 深度阐述

Riley 开门见山地给出了 xAI 官方的发布声明："Introducing Grok 4.6. It delivers frontier intelligence and is a significant improvement over Grok 4.5 at the same price."——**Grok 4.6 带来了前沿水平的智能，且相比 Grok 4.5 在同一价位上实现了显著提升** `[段落 1]`。

但真正值得注意的是它领先的领域。Riley 特别指出，Grok 4.6 在三个方向上的基准测试中拔得头筹：

1. **经济价值高的工作（economically valuable work）**
2. **长程专业任务（long professional tasks）**
3. **法律工作（legal work）**

而它的**编程基准测试并没有领先**。Riley 认为这不是缺陷，而是 xAI 刻意为之的战略选择——"They are focused on general agent tasks because this is simply their priority."（他们专注于通用 Agent 任务，因为这就是他们的优先级）`[段落 1]`。这个判断与随后发布的 Grok Bot 形成了完美呼应：xAI 想要的不是"更好的编程助手"，而是"让公司里每个人都能通过 AI Agent 完成工作"的超级平台。

在如何使用 Grok 4.6 的问题上，Riley 给出了自己的第一推荐：**直接通过 Cursor 使用**。更新 Cursor 后，它会默认切换到 Grok 4.6 Fast 模式，无需任何额外配置。这既是 Cursor 与 xAI 深度合作的体现，也说明对绝大多数开发者而言，Grok 4.6 已经是一个可以无缝嵌入现有工作流的"开箱即用"模型。

### 个人感受（案例还原）

Riley 坦言自己还没有时间对 Grok 4.6 做深度测试，但他分享了 Twitter 上一个让他惊叹的真实案例——**DHH 的两次"神迹"对比** `[段落 2]`：

> 上周，DHH 用 Claude 的 Fable 模型，以 **1100 万个 token** 一次性（one-shot）完成了"将终端文本效果 Python 库用 Rust 重写"这个极难的任务。如果你不懂这意味着什么，完全没关系——简单说，这是一件非常、非常难的事。

> 而今天，DHH 发推说：他用 xAI 的 Grok 4.6，**只给了几次微调提示（a couple of nudges），在一个半小时内复现了同样的壮举**。

更关键的是成本：**Grok 4.6 只花了 55 美元**。Riley 强调："That was about 1/10 of the cost of Fable implementation for the same work."（同样一份工作，成本大约是 Fable 实施方案的十分之一）`[段落 2]`。

### 详细定价分析

Riley 随后将 Grok 4.6 与三个顶级竞争对手做了价格对比（按每百万 token 的输入+输出价格合并计算）`[段落 2]`：

| 模型 | 输入+输出合并价格（每百万 token） |
|---|---|
| **Grok 4.6** | **$8** |
| Opus 5 | $30 |
| 5.6 Soul | $35 |
| Claude Fable 5 | $60 |

这意味着：
- **Claude Fable 5 是 Grok 4.6 价格的 7.5 倍**
- **5.6 Soul 是 4.4 倍**
- **Opus 5 是 3.75 倍——而且 Grok 4.6 在综合能力上"straight-up better"（就是比 Opus 更强）** `[段落 2]`

Riley 的结论掷地有声："This is a very good model, and it is a reasonable price, and it is legitimately on the frontier."（这是一个非常好的模型，价格合理，而且实打实地站在前沿）`[段落 2]`。当"前沿"不再意味着"天价"时，整个市场的竞争逻辑都会改变。

### 延伸思考：Elon 的豪言与"训练语料"护城河

在这条关于 Cognition 测试的帖子下方，Elon Musk 亲自下场评论。Riley 转述了他的两条核心表态 `[段落 2]`：

> "Grok 4.7 will exceed all current models, which includes Fable."

> "That said, Anthropic is a great company and will probably release improved models soon. However, the SpaceX training corpus is so awesome and unique that I would be shocked if any model is better at real-world engineering than 4.7."

这段话信息量很大。Elon 一方面承认 Anthropic 是"伟大的公司"、很快就会发布更强的模型，展现出对竞争对手的尊重；另一方面，他押注的是 xAI 独有的**训练语料库**——真实世界的工程数据（此处字幕再次写成 SpaceX，结合上下文应指 xAI）。Elon 的意思是：模型架构可以追赶，但独有的高质量语料是别人难以复制的护城河。Riley 没有对此做更多评判，但他显然认为这是一个值得关注的信号。

## 二、Grok Bot：把"会话"变成"你的 AI 员工" `[段落 3-6]`

### 核心观点

Grok Bot 是 xAI 联合 Cursor 团队秘密打磨四五个月后的"超级应用"。它最大的创新不是更强的模型，而是**产品范式的切换**：不再让你创建一堆容易丢失的聊天会话，而是让每个会话都变成一个**有名字、有职责、有专属例行公事（Routines）的 AI Agent**。每个 Agent 还自带一台云端计算机，你可以教它做事、看它干活、检查它的文件。

### 深度阐述

Riley 对模型发布一向保持克制，他真正兴奋的是 Grok Bot 这个平台。他给出了一个背景信息：Grok Bot 的桌面版和 iOS 版，**是由 Cursor 团队实际开发完成的** `[段落 3]`。

"Cursor was working on this platform for many months. I think like four or five months and this was going to be their general knowledge worker platform."（Cursor 团队为这个平台工作了四到五个月，它本来会是他们的通用知识工作者平台。）`[段落 3]`

更有趣的是它的"身世"：这个平台在 Cursor 内部代号 **Sand**，而 Riley 相信他们原本打算把它命名为 **dot**——因为 Cursor 已经花了约 **700 万美元**买下了 dot.com 域名。但最终，xAI 决定使用 **Grok Bot** 这个名字。一个价值 700 万美元的域名被搁置，换来的是与 Grok 品牌的高度统一——这笔账孰轻孰重，市场会给出答案。

#### 核心设计：会话即 Agent

Grok Bot 与 GPT Work、Claude Co-work 最根本的区别，Riley 用一句话概括：

> "Instead of creating new sessions all the time... What Grok bot did is they just said each session, each one of these sessions is like its own agent."（与其一直创建新会话，Grok Bot 的做法是：每个会话就是一个自己的 Agent。）`[段落 3]`

在 Claude Co-work 或 GPT Work 里，左侧面板会不断堆积大量聊天记录，大多数你永远不会再打开。而 Grok Bot 的做法是：当你点击"新建 Bot"时，它不会默默给你一个空白对话框，而是**立刻尝试判断这个会话的目的，并主动为你命名这个 Agent**。

Riley 演示了实际交互过程。创建后，Agent 会打招呼：

> "Hi Riley, I'm here. What do you want me around for? Could be email, content, code, a specific workflow, or something else entirely. Weekly agent updates, look at my YouTube and Notion to get context. Your job is to help me with these every week." `[段落 3]`

（嗨 Riley，我来了。你想让我负责什么？可以是邮件、内容、代码、某个具体工作流，或者其他任何东西。每周 Agent 动态更新——去看我的 YouTube 和 Notion 获取上下文。你的工作就是每周帮我处理这些。）

你甚至可以直接对它说"Name yourself weekly update"（给自己取名叫 weekly update），它就会修改自己的名字和标题标签。每个 Agent 都可以配置：
- **插件（Plugins）**：如 Gmail，与其他平台类似
- **技能（Skills）**：Riley 就配置了自己的"Scrape Creator"技能
- **描述（Description）**：实际上就是一个迷你系统提示词（mini system prompt）
- **例行公事（Routines）**：即自动化任务，但**归属于 Agent 自己，而非全局**

Riley 演示了一个真实场景：他对 Weekly Update Agent 说"每个工作日早上 10 点给我推送当天的 AI 新闻"，Grok Bot 自动创建了一条 Routine，显示为"10:00 AM 在聊天中推送每日 AI 新闻简报"。这条 Routine 被收纳在 Weekly Update Agent 的专属空间里，而不是淹没在一个全局的"定时任务"列表中。

#### 与 Claude Co-work 的关键差异

Riley 特意打开 Claude Co-work 做了对比 `[段落 4-5]`：

在 Claude Co-work 里，如果你说"每天早上 9 点执行某个任务"，它确实会创建定时任务，但这个任务被归入**全局的 Scheduled 设置**，与当前会话没有太大关系。当你创建了大量定时任务后，它们全部堆在顶部的"Scheduled"分区里，和你聊天的上下文完全割裂。而你的聊天列表里，塞满了永远不会再回去的会话。

Grok Bot 的做法则完全不同：**Routines 活在 Agent 内部**。Riley 的 Partnership Bot 有自己的 Routines，Content Bot 也有自己的 Routines——比如每天早晨 9:16 自动抓取他所有关注创作者的更新。每个 Bot 的自动化任务和它自己的上下文、插件、技能绑定在一起。

更有意思的是快捷键 **Command + K**：按下后，你会得到一个所有 Routines 的俯瞰视图，每条 Routine 都会显示**它属于哪个 Agent**。比如：
- Weekly Update Agent → 每周更新流程
- Developer Routine → 开发相关
- Partnership Bot → 合作关系处理
- To-Do List Bot → 每天打印最重要的任务提醒

Riley 认为这个设计让"定时任务"第一次有了清晰的归属感——你不再需要记住"我到底在哪里设了这个自动化"。

#### 每台 Agent 都有一台云端计算机

Riley 还特别提到了一个他差点忘记介绍的重要功能：**每个 Agent 都自带一台运行在云端的完整计算机** `[段落 5]`。

这意味着：
- Agent 拥有自己的云浏览器，你可以**登录你自己的账号**
- 你可以**教 Agent 完成任务**（Teach a Task）——录制你的操作过程，类似于 Codex 的 Record & Replay
- 但关键区别是：**这一切发生在 Agent 的虚拟计算机里，而不是你的本地电脑上**
- 你还可以**完整查看这台云端计算机的所有文件**——它有完全的可视性

Riley 强调："It's its own thing that you have full visibility into, which is a very new and interesting thing, especially in a platform like this."（这是它自己的一套系统，你拥有完全的可见性，在一个像这样的平台里是非常新鲜、有趣的事情。）`[段落 5]`

#### 视觉/界面描述

Riley 在视频中实际演示了 Grok Bot 桌面端的界面：

- **主界面**采用类似 ChatGPT 桌面版的布局，但左侧边栏不是一堆聊天标题，而是一个个"Bot 卡片"，每个 Bot 有独立的名称、标题标签和描述
- 每个 Bot 内部可以展开若干 **Routines** 子条目，形成树状结构
- 右上角或侧边栏有 Plugins 和 Skills 的管理入口，且这些配置是**所有 Agent 共享**的
- Command + K 呼出的全局搜索面板，以"Agent 名称 + Routine 名称"的层级方式展示所有自动化任务
- 云计算机界面可以打开浏览器、文件管理器，让用户直接观察 Agent 的"工作现场"

### 个人感受

Riley 对这个平台的态度从怀疑到"真香"，他的自白非常坦诚：

> "This is something I would have never thought I wanted, but once I used it, I was like, 'Okay, this actually makes more sense.'"（这是我从未想过自己会想要的东西，但一旦用过之后我就会想：好吧，这确实更有道理。）`[段落 13]`

他的核心顿悟是：**自动化任务不应该活在全局层面，而应该活在 Bot 内部**。当一个系统里有上百个自动任务时，按 Agent 来组织它们远比一个巨大的全局列表更直观。

### 延伸思考：为什么说这是"范式级"设计？

Riley 认为 Grok Bot 的拟人化设计戳中了一个更深层的产品问题：**人脑如何理解"多个 AI 同时为你工作"这件事**。

过去，我们需要在一个对话框里不断切换上下文、回忆"我上次做到哪里了"。Grok Bot 把这个问题变成了"我有很多个员工，每个员工负责一件事，我只需要去找对应的人"。这个心智模型几乎不需要学习成本——每个有团队协作经验的人都能秒懂。

当然，Riley 也坦承 Grok Bot 在功能完备性上**落后于 GPT Work 和 Codex**——"There's a lot of things that GPT work can do that Grokbot cannot do."（有很多 GPT Work 能做而 Grok Bot 做不到的事情。）`[段落 12]` 但他在乎的是方向：这个设计让"与 AI 协作"的门槛大幅降低了。

## 三、AI Agent 平台的演化图谱：从"个人助手"到"Agent 团队" `[段落 7]`

### 核心观点

2025 年底到 2026 年上半年，各大平台的 Agent 形态高度趋同——都是从"终端里的 Claude Code"演化而来的超级应用。而 2026 年下半年开始的真正分野，出现在"个人 Agent"向"Agent 团队"乃至"人机混合团队"的演进路径上。Grok Bot 和 Buzz 分别代表了两条新路线。

### 深度阐述

Riley 从宏观视角梳理了 Agent 平台的进化史 `[段落 7]`：

**第一阶段（2025 年底至 2026 年上半年）：终端进化的超级应用**

这一时期发布的平台长得都差不多：Hermes Agent 看起来像 Claude Co-work，Codex 有 GPT Work，Claude 桌面端也是类似的布局——左侧一堆会话、右侧 Agent 执行区，外加 Skills、Plugins、Artifacts、Automations（定时任务）。它们本质上都是"Claude Code 在终端里运行"这一形态的 GUI 化产物。

**第二阶段（2026 年中开始）：形态分岔**

Riley 观察到，近期走红的两大 Agent 平台——**Buzz** 和 **Grok Bot**——开始呈现出与前辈们截然不同的"形状"：

- **Grok Bot**：让你的"AI 员工团队"一目了然。你可以快速创建多个有明确职责的 Agent，每个 Agent 拥有自己的 Routines 和云计算机。这是一种"个人 Agent 团队"的组织方式。

- **Buzz**：Riley 描述它"looks exactly like Slack"（看起来完全就是 Slack）。它允许你创建多个频道（Channels），每个频道里可以放一群不同的 Agent，甚至可以**邀请真人加入**。这是"Agent 原生的 Slack"——一个为人类和 AI 共同协作而重新设计的聊天工作流。

**第三阶段：企业级 Agent 协作**

Anthropic 公开层面很少谈论 Co-work，他们更专注于一个叫 **Claude Tag** 的新平台——它允许你在公司内部的 Slack 中直接创建 Agent。Riley 表示，据他所知 Claude Tag 目前只能配合 Teams 使用（此处可能指 Microsoft Teams 或 Slack 的 Team 版本，原文信息不明确）。但关键是：**Anthropic 已经把重心从"个人 Agent"转移到了"为团队/企业创建 Agent"**。

Riley 总结了这个趋势：

> "Maybe the first half of 2026 or the first 2/3 of the year was about the personal agent and the rest of this year is kind of about how do you create your own personal team of agents? And then in regards to Buzz and Claude Tag, how do you add an agent so that your entire team can get access to the same agent so you can collaborate using AI agents." `[段落 7]`

（也许 2026 年上半年或者前三分之二的主题是个人 Agent，而今年剩下的时间，主题是如何创建你自己的个人 Agent 团队。然后，在 Buzz 和 Claude Tag 的语境下，问题变成了：如何添加一个 Agent，让你的整个团队都能使用同一个 Agent 来协作？）

### 延伸思考：为什么"团队化"是必然方向？

从个人对话到团队协作，AI Agent 的演进其实在模仿人类组织的进化路径。个人 Agent 解决的是"我自己的效率"，但企业真正的杠杆来自协作。当 Agent 成为团队的一员（而不是个人工具），它可以被赋予共享上下文、跨部门执行任务、在 Slack 里@所有人——这将彻底改变组织的运行方式。Grok Bot 和 Buzz 的走红，恰恰说明市场已经准备好迎接这个转变。

## 四、Claude 的持续进化：从浏览器到价格战 `[段落 8-9]`

### 核心观点

Anthropic 本周的更新看似温和，实则意义深远：Claude 的 Chrome 会话全面打通桌面端与移动端，让 Co-work 能力潜入浏览器；Sonnet 5 宣布维持低价，标志着美国头部模型在中端市场开启防守战；同时，一款允许任何 Agent 完全控制手机的 Phone Harness 工具在 GitHub 上出现。

### 深度阐述

#### 更新一：Chrome 会话全面同步 `[段落 8]`

昨天，Claude 官方宣布：**你的 Claude Chrome 会话现在可以无缝延续到桌面端、网页端和移动端**。对话记录会被保存，Skills 和 Connectors 在浏览器中同样可用。

Riley 一语道破了本质：

> "Basically, what Claude and OpenAI are doing is they are inserting GPT work in the case of OpenAI and Claude co-work in the case of Anthropic directly into your browser."（基本上，OpenAI 和 Anthropic 正在做的事情，是把 GPT Work 和 Claude Co-work 直接嵌入你的浏览器里。）`[段落 8]`

Riley 同时配置了两家产品，并实际演示了 Claude 的 Chrome 扩展：他可以对网页内容说"Please tell me more about this"（请告诉我更多相关信息），而 Claude 在浏览器里执行的，就是等同于 Claude Co-work 的能力——包括调用 Connectors、使用 Skills。最重要的是，**所有这些浏览器里的会话会自动同步到 Claude 桌面应用**。当 Riley 回到 Claude 桌面端时，浏览器里的对话已经出现在聊天历史中，标题被自动命名为"More information request"。这种"从浏览器开始、在桌面端继续"的流畅体验，正在把 Agent 从独立 App 变成浏览器的原生功能。

#### 更新二：Sonnet 5 维持低价，价格战正式开打 `[段落 9]`

Sonnet 5 原本有一个"introductory price"（首发优惠价），计划在未来某个日期恢复原价。但 Claude 官方决定：**保持这个更便宜的价格不涨了**。OpenAI 对自家的 Terra 和 Luna 模型也采取了类似策略。

Riley 认为，这背后是全球模型市场竞争的直接影响：

> "I believe, and many believe, that this is due to the pressure from Chinese models out of Deep Seek, Kimmy, z.ai, and then now also Grok... Because if their middle models are way more expensive than these other alternatives that are actually better, then people have no reason to use them."（我相信，而且很多人也相信，这是因为来自 DeepSeek、Kimi、Z.ai 这些中国模型，以及现在 Grok 的压力。如果他们的中端模型比那些更好用、更便宜的替代品贵得多，那人们就没有理由用它们了。）`[段落 9]`

Riley 的推演很直白：如果竞争持续，Anthropic 和 OpenAI 的非前沿模型价格会继续下探。而一旦"前沿模型比中端模型更便宜"的倒挂局面出现，像 Sonnet、Opus、Terra、Luna 这类中端模型就会彻底失去市场空间。"This is causing them to lower their prices, and I expect this to continue."（这正在迫使他们降价，我预计这还会继续。）`[段落 9]`

#### 更新三：Phone Harness——让 Agent 控制你的手机 `[段落 9]`

这个更新并非来自 Anthropic 官方，而是 GitHub 上的一个开源项目。Riley 描述它非常直接：

> "You will find a repo which will allow you to fully control your phone from any agent, not just Claude code, but Claude code, CodeX, etc. You can fully control your phone with an AI agent."（你会找到一个仓库，它允许任何 Agent——不只是 Claude Code，还有 Codex 等等——完全控制你的手机。）`[段落 9]`

Riley 明确表示他还没有测试过，但认为这非常酷，值得分享。这个项目的意义在于：Agent 的"手"已经从电脑屏幕延伸到智能手机——未来，你的 Agent 或许能帮你发短信、订外卖、操作 App，而不只是处理文档和代码。

### 个人感受

Riley 对价格战的评论带着一丝"早就料到"的平静：他并不为美国大厂的降价感到惊讶，反而把它视为中国模型崛起带来的必然结果。他对 Phone Harness 的态度则像"看到一个很酷的新玩具"的兴奋分享——哪怕自己还没上手，也愿意第一时间告诉观众。

### 延伸思考：价格战会杀死谁？

当模型能力趋于同质化，价格就成了唯一的竞争维度。中国模型的低成本优势正在倒逼美国大厂放弃中端市场的利润。但 Riley 提出了一个更尖锐的问题：如果前沿模型持续降价，**中端模型这个品类本身会不会消失？** 当最好的模型只比"够用的模型"贵一点点时，没人会选择后者——整个产品线结构可能都需要重构。

## 五、DeepSeek V4：高调发布，光速翻车 `[段落 10]`

### 核心观点

DeepSeek V4 Pro 今早正式发布时声称"几乎和 Fable 一样好"，但大量实测者发现它只比上一代 V4 Flash 好一点点。尴尬之下，模型已基本被撤下。Riley 在 Cursor 中尝试使用时，它甚至直接报错。定价转向 usage-based 的做法也招致批评。

### 深度阐述

Riley 整理了这个"发布即翻车"事件的完整时间线 `[段落 10]`：

1. **昨晚**：DeepSeek 发布新的 Pro 模型，宣称它"几乎和 Fable 一样好"，而价格只是顶级昂贵模型（如 Fable）的一个零头。

2. **随即**：很多人开始实测，结果纷纷回来打脸——"No, it's only a little bit better than DeepSeek's previous model, which was DeepSeek V4 Flash."（不，它只比 DeepSeek 之前的 V4 Flash 好一点点。）`[段落 10]`

3. **结果**：场面非常尴尬，DeepSeek 基本上把模型下架了。

Riley 还提供了自己的亲测证据：他试图在 Cursor 中通过 Open Router 使用 DeepSeek V4 Pro（它还不是 Cursor 的官方内置模型），结果发了一句"Hi"，**模型立刻报错、完全无法使用**。

> "And so, this model just doesn't work right now, and so I can't fully cover it because there is some backlash."（这个模型现在根本用不了，因为存在争议，我也没法完整评测它。）`[段落 10]`

此外，DeepSeek 的**定价策略**也遭遇了批评——他们转向了 usage-based pricing（按用量计费），这被一些人视为变相涨价。

### 个人感受与延伸思考

Riley 对这起翻车事件的叙述带着一丝"行业观察者的冷静"。他没有幸灾乐祸，而是把它当作一个典型案例：在 AI 行业，"自信发布 + 缺乏实测"的风险正在加大。当一个模型宣称"接近顶级但价格便宜十倍"时，大众的第一反应是兴奋，第二反应是怀疑——而这次的实测结果，恰好坐实了怀疑。

这起事件也给所有 AI 公司提了个醒：**在社区的集体测试能力面前，营销话术的保质期只有几个小时**。模型好不好，发布后 24 小时内就会被全网验证。与其夸大其词，不如诚实定位。

So, this is the third best model by Claude and the second best model by OpenAI."（不过我确实注意到一个危险信号：他们拿来对比的模型——Gemini Flash 对比的是 Claude Sonnet 和 GPT Terra——也就是说，这是 Claude 的第三好模型和 OpenAI 的第二好模型。）`[段落 10]`

这种平淡本身就是一个重要的市场信号：**当 Grok 4.6 以 $8 价格横扫前沿时，Google 发布一个"更快的中端模型"已经很难激起核心用户的兴趣了。**

## 七、"Chat vs Work"之困：2026 年 AI 产品最大的 UX 难题 `[段落 11-13]`

### 核心观点

ChatGPT 正在被"Chat"和"Work"两个割裂的产品形态撕裂：简单问题被 Work 模式拖入冗长的规划与工具调用，而复杂任务又无法在 Chat 模式中完成。Signal 的批评引爆了行业讨论。Riley 将此命名为 "Chat vs Work Problem"，并认为 Grok Bot 的"会话拟人化"是目前最有希望的解药。

### 深度阐述

Riley 在视频最后部分抛出了本周最具思考深度的话题。他引用了 Signal 的推文 `[段落 11]`：

> "It's not clear to me that OpenAI realizes how strange the distinction between chat and work feels in practice and how fragmented the entire chat GPT experience has become. If you leave it on work, every simple question or search becomes an expedition. It starts thinking, planning, and using tools when you just wanted a quick answer." `[段落 11]`

（我不确定 OpenAI 是否意识到，Chat 和 Work 之间的区别在实际使用中感觉有多奇怪，整个 ChatGPT 体验已经变得多么碎片化。如果你把模式留在 Work 上，每个简单问题或搜索都会变成一次远征。它开始思考、规划、调用工具——而你只是想要一个快速答案。）

Riley 用"chat versus work problem"来概括这个问题 `[段落 11]`。他解释了两者的本质差异：

- **Chat（聊天）**：你熟悉的普通 ChatGPT，快速问答、简单直接
- **Work（工作）**：一个完整的 Agent 平台，可以操作 Slack、控制你的 Gmail 和 Notion、自动回复邮件、执行定时任务——是一台真正的"数字员工"

问题在于，**这两个产品被塞进了同一个 App，但体验边界极其模糊**：
- Chat 对真实任务来说太受限
- Work 对普通查询来说太慢、太重
- 频繁切换让整个产品变得无比复杂
- 本地 Chat 与云端 Chat 的同步不清晰
- 移动端与桌面端的割裂也让体验雪上加霜

Riley 感叹道：

> "Chat GPT went from the most usable, simple consumer experience to confusing AF in such a short period of time. Pretty nuts."（ChatGPT 在最短暂时间内，从最易用的简洁消费体验，变成了令人困惑到爆炸的东西。真的很疯狂。）`[段落 11]`

#### Grok Bot 给出的答案：拟人化会话

面对这个难题，Riley 认为 Grok Bot 做了一个"微小但深刻"的创新——**把聊天会话拟人化**。他在 Twitter 上专门发帖分析过这一点 `[段落 12]`：

> "An agent or a Grokbot is basically a named session or a named chat session with a mini system prompt."（一个 Agent 或 Grok Bot，本质上就是一个带名字的会话——一个有迷你系统提示词的命名聊天会话。）`[段落 12]`

具体来说：

- **描述即系统提示词**：每个 Bot 的描述字段就是它的迷你系统提示词
- **全局共享工具**：所有 Agents 共享 Plugins（如 Gmail）和 Skills
- **按职责分工**：想做内容脚本就去 Content Agent，想抓社交媒体也去 Content Agent；做每周更新就去找 Weekly Update Agent；处理合作事务就去 Partnership Bot
- **主动通知**：当 Slack 里有相关事件发生时，对应 Agent 会自动 ping 你

Riley 将这个设计的精妙之处归结为：**它让"与多个 AI 协作"的心智模型变得极其自然**。你不再面对一片混沌的聊天列表，而是像一个管理者，面前站着几个各司其职的员工。

> "I think the biggest innovation of Grokbot was kind of making this analogy easier to understand."（我认为 Grok Bot 最大的创新，是让这个类比变得更容易理解。）`[段落 12]`

他预言其他实验室会抄袭这个设计：

> "I have a feeling that the other labs are going to copy this design because I do find it's a lot easier to get started, and it just intuitively makes sense that you have a bot. Each bot has its own computer, and it has its own routines."（我有一种预感，其他实验室会抄袭这个设计。因为我确实发现它上手更容易，而且"你有一个 Bot"这个直觉非常好理解——每个 Bot 有自己的计算机，有自己的例行公事。）`[段落 13]`

#### Workspace Agents：ChatGPT 的秘密武器即将降临

Riley 还在视频中预告了一个重要消息：**Workspace Agents 即将登陆 ChatGPT 桌面端**。

这个情报来自他自己的"套话"经历。他 quote 了 OpenAI 关于 Workspace Agents 的推文，指出目前该功能**仅限 GPT Team 计划、仅限网页端**，而他发帖表达不满：

> "Wish this wasn't only a Teams plan and only on web. This should be on desktop as well."（真希望这不只是 Teams 套餐、不只是网页端。桌面端也应该有。）`[段落 13]`

结果，OpenAI 团队的 **Andrew** 在下面回复了一个字：**"Yes."** `[段落 13]`

这个简单的"Yes"被 Riley 解读为强烈信号——Workspace Agents 很快就会出现在 ChatGPT 桌面应用里，而且不会局限于 Team 计划。他甚至给出了很高的评价：

> "This is the most slept on OpenAI product yet, in my opinion."（在我看来，这是 OpenAI 迄今最被低估的产品。）`[段落 13]`

Workspace Agents 能做什么？Riley 解释说：它们与 GPT Work 一样强大，但每个 Agent 可以有自己的系统提示词（类似 Grok Bot 的描述字段）。你可以给这些自定义 Agent 发消息，甚至把它们加入 Slack、通过 Slack 直接对话——这是企业协作场景的杀手级功能。

#### Codex 登陆 Linux `[段落 13]`

最后一条小更新：Codex 应用（或使用 Codex 的 ChatGPT 应用）现在可以下载到 **Linux** 上。对 Linux 开发者社群来说，这是一条被淹没在本周海量新闻中的实用好消息。

### 个人感受

Riley 对"Chat vs Work"问题的剖析带着一线产品经理式的敏锐。他对 ChatGPT 的批评毫不留情——"confusing AF"——但随即又补充" I do think it's incredibly powerful"（我确实认为它非常强大）。这种"既爱又恨"的复杂态度，恰恰反映了 2026 年 AI 产品普遍面临的成长阵痛：能力越来越强，但体验越来越难驾驭。

### 延伸思考：从"对话"到"团队"的 UI 革命

这场讨论的本质，其实是 **AI Agent 产品界面应该长什么样**的争论。

- OpenAI 的答案是：一个 App 里塞两个模式（Chat / Work），用"模式"来区隔。
- Anthropic 的答案是：在 Co-work 里做深度 Agent 体验，让时间线和任务管理并行。
- xAI 的答案是：把每个会话变成"员工"，用拟人化的方式组织你的 AI 团队。
- Buzz 的答案是：干脆做成 Slack，让 Agent 和人类在同一个频道里共事。

目前没有任何一方拥有"标准答案"。Riley 预测，未来三个月内，各家会疯狂迭代、互相借鉴。"And I think there's just going to be a lot of innovation."（而且我认为未来会有大量创新。）`[段落 12]` 而这场竞争最终的受益者，是所有使用 AI 工作的普通人——因为只有当一个范式足够清晰、足够自然时，AI 才能真正从"玩具"变成"生产力"。

## 八、结语：本周最重要的五件事 `[段落 13-14]`

回看这一周，Riley 认为最值得记住的几件事是：

1. **Grok 4.6 是货真价实的前沿模型**，而且以 $8/百万 token 的综合成本碾压了 Opus 5、5.6 Soul 和 Claude Fable 5。DHH 用 $55 复现了 Fable 花 10 倍成本才能完成的工作——性价比的差距已经不是一个量级。

2. **Grok Bot 重新定义了 Agent 平台的交互方式**。"会话即 Agent"的拟人化设计，配合每个 Agent 自带的云端计算机和专属 Routines，让"拥有一个 AI 员工团队"从概念变成了上手即用的现实。

3. **行业正从"个人 Agent"走向"团队 Agent"**。Buzz 的 Agent 原生 Slack、Anthropic 的 Claude Tag、OpenAI 即将登陆桌面端的 Workspace Agents——企业级 AI 协作将成为下半年的主战场。

4. **价格战已经蔓延到中端模型**。DeepSeek、Kimi、Z.ai 和 Grok 的竞争压力，迫使 Anthropic 和 OpenAI 放弃中端市场涨价计划。如果前沿模型继续降价，中端模型这个品类可能走向消失。

5. **"Chat vs Work"是当前 AI 产品最大的 UX 难题**。当模型能力不再是瓶颈，如何设计出让普通人自然理解、轻松驾驭的 Agent 界面，将成为决定下一代 AI 平台格局的关键。

Riley 最后以他惯常的方式收尾："I'm Riley Brown. Thank you guys so much for watching and please like, please subscribe. I'll see you here for the next video." `[段落 14]` 但这一周的内容分量，显然比任何一期例行周报都要沉重——因为 AI Agent 的平台战争，在这一周真正打响了。
