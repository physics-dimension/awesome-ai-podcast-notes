# 给 GrokBot 配上专属邮箱和信用卡——AI 代理的自主购物指南

**来源**: Riley Brown

## 视频导语

今天，我将向大家展示，创建一个 GrokBot，并给它配备专属邮箱和信用卡，是多么简单的一件事。对于那些还不了解的朋友，GrokBot 是全球增长最快的通用代理平台，由 Cursor 打造，如今归 SpaceX 所有。今天，我们将为我们的 GrokBot 创建一个邮箱，并设置一个 Web Hook（网络钩子）。这样一来，我的机器人每收到一封邮件，都会触发他去采取行动。接下来，我们还将通过全新的 Stripe Link 集成，赋予他使用虚拟卡进行购物的能力，让我的智能代理能够自主地购买东西。让我们开始吧。

## 一、GrokBot 平台概览

我们现在就身处这个全球增长最快的代理平台——由 SpaceX 旗下的 GrokBot。在我左手边的是我的 GrokBot 团队。我们今天要做的事情是：创建一个新的 GrokBot，并给它配上**一个邮箱**和**一张信用卡**。

这意味着什么？这意味着，这里的每一个机器人，都将能够**使用自己专属的邮箱地址**来发送邮件。同时，这个代理还将具备**自主购买物品**的能力。你可以直接告诉它，去帮你买任何你想要的东西，它就能做到。而这一切，你只需要在**5到10分钟**内就能设置完成。

## 二、第一步：让代理拥有专属邮箱

我们进入第一部分——**给代理一个邮箱**。你可能会好奇，给 GrokBot 配上邮箱到底有什么好处？根据我的实际使用体验，有以下几个核心优势。

### 邮箱三大核心优势

1. **直接转发任务**：我可以直接把邮件转发给我的 GrokBot。当我收到一封不希望自己动脑处理、或者需要做调研的邮件时，我就可以直接转发给它，由它来负责回应，这非常有意思。

2. **邮件触发代理**：这是让 GrokBot 区别于 Claude Code、GPT Workspace 或其他代理平台的关键之处——**机器人可以被我们即将设置的邮件所触发**。这依赖于该平台一个非常特殊的功能：**Routine Web Hooks（例行网络钩子）**。

   让我解释一下。大多数代理平台都有"自动化"或"例行程序"功能，通常形式都是"工作日早上10点做某事"这类定时任务。然而，在 GrokBot 上，你可以创建一个**由触发器（Trigger）来驱动**的例行程序。这个触发器可以是任何预设好的事件，比如接收到 Slack 消息。但 GrokBot 还有一个叫做 **Web Hook** 的触发方式。虽然这有点进阶，但你只需要两三分钟就能搞定。通过它，你的代理可以被邮件**实时触发**，一旦 GrokBot 收到邮件，他会立即开始工作，这非常酷。

3. **独立收件箱收发邮件**：机器人可以使用自己的隔离收件箱来联系他人和接收邮件。如果你愿意，你可以给所有的 GrokBot 都分配一个专属邮箱。

### 创建代理：Jimmy

好的，让我们实际操作起来。首先要做的，是创建一个新的代理（Agent），也叫新机器人或新 GrokBot。这个机器人我们将配备邮箱和信用卡。在创建时，我们输入：

> 你的名字是 Jimmy，你负责购买东西。你是我们公司 Agent Native 的高管助理。你将拥有一个邮箱，当公司里的人请你购买办公用品时，你会负责采购。公司里的人可以给你发消息让你买东西，这是你的主要职能。你会成为一个有用的代理。

创建代理就是这么简单，只需要说清它的名字和职责即可。正如你看到的，它叫"new bot"，但系统会自动更新这个名字和描述。看，它自动生成了描述："我是 Jimmy，Agent Native 的高管助理。当人们提出请求时，我会购买办公用品。你批准每笔采购，并追踪承包商的付款。"

我还可以给它加一个小标签，就写 **EA**（高管助理）。现在这个机器人还是未分配的，我将其置顶，Jimmy 正式成为团队的一员。

### 安装 AgentMail 插件

接下来，要给 Jimmy 配一个邮箱，我们需要使用一个插件。我目前安装了 14 个插件，包括完整的 Slack、Notion 控制权、Gmail、我的 ClickUp、X 平台等等。我们需要的插件叫 **AgentMail**。

我对它说："让我们设置这个插件，连接它。" 系统会返回一个连接卡片——一个用于配置 AgentMail 的小型 UI 组件。卡片弹出后，点击"授权"，然后点击"允许"，你只需要创建一个账户，系统会提示"授权完成"，点击"完成"就好。

我继续对它说："制作他的邮箱地址，然后给我仪表盘的链接。" 系统生成了一个我满意的邮箱：**jimmy-bot@agentmail.to**。我让它把邮箱写进自己的描述里，让它永远不要忘记这就是它的邮箱。

### 发送测试邮件

接下来，我们进入 AgentMail 控制台（也就是 AgentMail 的管理后台），可以看到收件箱，其中已配置好名为 **jimmy-bot@agentmail.to** 的邮箱。为了测试这个邮箱地址是否有效，我复制这个邮箱地址，粘贴到发件栏，写了一封"测试 Jimmy 收件箱"的邮件并发送。

成功了！这封邮箱地址是真实可用的。我（Riley，来自 agentnative.inc）成功发送了一封邮件到 jimmy-bot@agentmail.to。

我回到机器人界面，说："请告诉我这个邮箱地址有没有新邮件。" Jimmy 回应道："正在检查 jimmy-bot@agentmail.to……好的，有一封来自你（Riley）的未读邮件，主题是：测试，内容为：测试 Jimmy 收件箱。"

至此，我们的代理拥有了邮箱地址并可以查看邮件了。

### 配置 Web Hook：实现邮件自动触发

现在，我们希望 Jimmy 能持续监控这个邮箱，以便任何人给他发邮件，他都能**立即感知到**。要实现这一点，我们需要用到 **Web Hooks**。

我给 Jimmy 下指令：

> 我想配置一个例行程序（Routine），让你能够通过 Web Hooks 监听这个邮箱地址。请设置好它，并给我完整的说明，告诉我如何在 AgentMail 上完整地设置这个自动化。

这个指令运行后，Jimmy 创建了一个例行程序。点击进去可以看到：**当 web hook 触发时**，它将执行这些指令：读取 Web Hook，从 AgentMail 获取完整的邮件线程、不要只依赖 Web Hook 的预览信息，然后在聊天里简短地通知我是谁发来的、主题是什么等等。

### 手动连接 Web Hook 与 AgentMail

为了让这个流程正式生效，我按照 Jimmy 给我的指示来操作：

1. 导航到 **AgentMail** 后台。
2. 找到并点击 **Web Hooks** 选项。
3. 点击 **添加端点（Add Endpoint）**。
4. 回到 GrokBot 界面，找到刚生成的 Web Hook，点击进入。
5. 在"POST to"这一栏，点击并**复制这个 URL**。
6. 返回 AgentMail，将 URL **粘贴**到刚才的端点配置框中。
7. 在描述栏填写："Jimmy 的收件箱 Web Hook"。
8. 在**订阅事件**中，选择"**消息（Message）**"事件，这样新消息就会触发这个 Web Hook。向下滚动并点击"完成"。

这样，端点就配置好了，名为"Jimmy 的收件箱 Web Hook"。

### 配置自定义请求头（最终步骤）

创建好端点后，还需要最后一步：进入 **Advanced（高级）** 选项卡，找到 **Custom Headers（自定义请求头）** 部分。

1. 回到 Jimmy 的聊天界面，按照系统提示，复制他提供的**密钥（Key）**。
2. 返回 AgentMail，在"自定义请求头"中，首先输入**授权（Authorization）**作为请求头名称。
3. 接着输入 **Bearer**，按一下空格，然后**粘贴刚才复制的密钥**。
4. 点击保存按钮。

现在，所有配置项都已设置完毕。

### 实时测试：让邮件触发代理

现在，让我们试一下。我发送一封邮件到 jimmy.bot@agentmail.to：

> 嘿，请帮我更新我八月份的 YouTube 数据。我八月份获得了多少观看量？我最热门的视频是哪几个？

邮件发出后，我们立刻就能看到 Jimmy 的"收件箱"监控程序在运转。图标正在旋转——它工作了！点击进去可以看到运行历史，显示它刚刚执行过。我的消息应该已经被它看见了。

看，它回来报告了："**jimmy-bot@agentmail.to 收到新邮件，来自 Riley Brown**"，并附上了我邮件的内容。这时我可以继续指示它"好的，请做个研究，然后回复一封邮件"，Jimmy 因为有联系人权限，将来就能自己执行研究并回复邮件。其实我也可以直接告诉它"以后当收到我的邮件时，在这里和邮件里都进行回复"，它就会更新例行程序，把这个规则纳入未来执行逻辑。它确认道："你给 Jimmy 发邮件，我会在这里和邮件线程中回复。其他人发来的邮件我只会在这里提醒。" 这非常理想。

就这样，它完成了邮件里要求的任务，整个流程配置完毕。我们的 GrokBot 现在拥有了邮箱功能。

## 三、第二步：给代理配置信用卡

现在进入第二步：具体来说，是给 Jimmy 配一张**信用卡**。我对这个功能非常兴奋，原因有三点。

### 信用卡三大核心优势

1. **独立研究并自主购物**：这意味着代理可以进行数小时的研究，做出购买决策，然后直接结算付款。
2. **支持设置定时采购**：你可以设置例行程序来实现定时购买，比如"每周五我需要你订购这个东西或那个东西"。
3. **交易有我掌控**：我认为这一点在当前 AI 代理的发展阶段至关重要——**我会收到审批通知**。当代理准备付款时，我的手机就会收到一个通知，问"你是否批准这笔交易？"我只需按下一个按钮，代理就能完成交易，这太酷了。

### 配置 Stripe Link

这里，我将设置 **Link**（Stripe 旗下的支付服务）。我给 Jimmy 下指令：

> 嘿，我想让你能用 Link 买东西。请设置好它。

系统回应："现在安装 Link。" 聊天中弹出一个连接卡片，我点击"授权"，然后点击"允许"。系统提示"授权完成，你可以关闭此标签页。连接卡片已在聊天中，准备好后点击它。"

我问道："告诉我，你现在能进行付款了吗？" Jimmy 回答："是的，Link 已连接为 Riley Brown，关联一张尾号 5160 的 Visa 卡。我可以购买，但每一笔费用仍需你先审批。" 这太棒了。

我继续对它说：

> 现在我想让你修改自动化，也就是我们之前设置的那个例行程序。如果你收到我发来的邮件，并且在邮件里让你买东西，我希望你能直接执行购买。

最终目标是：我只需要给机器人发一封邮件，它就会去为我买东西。这样，邮箱和信用卡两个功能就完美结合起来了。

### 实战测试：通过邮件让 AI 自主购物

现在我们来实际测试一下。我打开邮箱，给 Jimmy 发送邮件：

> 嘿，我需要你买点东西。我需要你在亚马逊上买一本不错的笔记本，要尽快送到。我想要红色的，请买一本质量好的。

邮件发出后，Web Hook 立即被触发，Jimmy 收到了发送到他自己邮箱地址的邮件。接下来，他会使用信用卡来购买邮件中要求的笔记本了。

我能够**实时观看** Jimmy 在自己的电脑上操作！他正在做调研，找到了一个皮革面硬壳笔记本——让他继续操作。他已经到了收货地址填写页面。

我拿起手机，应该会收到审批通知。果然，屏幕上弹出了批准请求，我需要做的就是点击"允许"。点击之后，系统会显示交易的明细，包括含税总价。

为了展示通知的样子，假设我现在不坐在电脑前我会收到什么？看这个：**"GrokBot 正在请求在亚马逊上消费 27.76 美元"**。我点击"批准"，然后通过 Face ID 验证即可。**以后每当你的代理尝试购买任何东西，你都会在 Link 应用上收到一个类似的通知。**

批准后，系统提示"Link 已批准"。

### 后台运作机制解析

让我解释一下这里发生了什么。这个 AI 运行在一个**虚拟电脑**上（因为 GrokBot 具备访问计算机的能力，而且现在仍在用它操作）。它完成了以下步骤：

1. **确定价格**：它确定了购买物品的确切成本。
2. **生成虚拟卡**：它使用 Link 生成了一张**全新的、金额正好等于商品价格的虚拟卡**。
3. **请求审批**：它通知我，而我批准了这张卡的创建。
4. **自动付款**：几秒钟后，它自动使用这张新卡完成了购买。

大功告成！它在亚马逊上下单了这本笔记本，花费 27.76 美元，预计 9 月 2 日（星期三）送达，还生成了对应的亚马逊订单号。

整个流程是：我发送一封邮件给 Jimmy，然后拥有信用卡的 GrokBot 便自主登录亚马逊完成了购买。

## 总结与展望

好的，这就是我们今天所做的全部内容：**我们给 GrokBot 配备了一个邮箱和一张信用卡**。

- **邮箱功能** 使用的是 **AgentMail** 插件。
- **信用卡功能** 使用的是 **Link**，它背后是 **Stripe** 支付服务。

这个方案设置起来非常简单，而且因为基于 Stripe，**非常值得信赖**。当你的代理需要支付时，它会先确定价格，随即创建一个限额匹配的新虚拟卡，然后向你发送审批请求。得到批准后，它便使用这张虚拟卡自动完成支付。

我推测，在不久的将来，这个审批步骤很可能会被移除。不过目前，由于这是一个太新的功能，审批环节仍然很有必要，而且它也确实非常有趣。
