## 第一部分：基础知识

好的，各位。我们今天要覆盖的内容很多，但同样，整个课程分为三个部分。我们先讲基础，然后是动手构建。我还有"第 2.5 部分"，会讨论一些进阶话题——具体来说，是如何将应用发布到互联网上，以及如何为你的应用配置好数据库。最后，我们会讨论所有帮助你高效使用 Cursor 的高级功能。

### 什么是 Cursor？

在介绍如何下载 Cursor 之前，我想先谈谈：**什么是 Cursor？为什么有人想用 Cursor？**

简单来说，**Cursor 是一种让你与 AI 代理（AI Agent）沟通、从而为你构建应用的工具**。

比如，我刚刚输入了一个提示词并发送给了这个模型——GPT 5.6 Soul。我说："我想构建一个让我记录卡路里的小应用。简单的应用，本地运行，非常极简，保持简单。" 我这样做是因为我想让它跑得更快，保持简单只是为了说明一个事实：**你可以把你的想法直接输入给 AI 代理**。

在这里，代理问了我一个后续问题："这个应用应该叫什么？" —— 就叫 **Call Track**。这只是一个非常简单的小应用，用来表达我的意思。

1 分 12 秒后，Cursor 就完成了构建。它显示"Calotra 已构建完成并在本地运行"，意思是它正在我的电脑上运行。我们稍后会详细讨论这个。现在我可以点击它，在外部浏览器（比如 Google Chrome）中打开，也可以右键点击它，在 Cursor 浏览器中打开。

就这样，我们现在有了一个非常简单的卡路里追踪应用。我可以输入"披萨 100"，然后点击"添加"。

**Cursor 本质上就是一个 AI 编码代理（AI Coding Agent），你可以跟它对话，它几乎能帮你构建任何你想象中能想到的应用。**

### 如何下载 Cursor

要下载 Cursor，你需要前往——你猜对了——**cursor.com**。

当你访问 cursor.com 时，页面看起来会很像这样。如果你使用的是 Mac，页面上会显示"Download for Mac OS"（为 Mac OS 下载）。你只需点击这个按钮，Cursor 就会下载到你的电脑上。

由于我已经在电脑上下载好了 Cursor，接下来你需要做的就是点击它、打开它，然后**用你的 Cursor 账号登录**。如果你没有账号，系统会提示你创建一个。

### 界面初识：IDE 窗口与 Agents 窗口

当你最终成功登录 Cursor 后，你的屏幕要么是这个样子，要么是这个样子：

- 这个窗口是 **IDE 窗口**（编辑窗口）。
- 这个窗口是 **Agents 窗口**（代理窗口）。

如果你想从 Agents 窗口切换到 IDE 窗口，可以点击上方这个写着 "IDE" 的按钮。你可以看到，在 IDE 窗口里有一个写着 "Agents 窗口"的按钮。**本视频我们主要讨论的是 Agents 窗口。**

### Agent 会话（Chat Sessions）

如果你从未用过 Cursor，打开应用时你的屏幕会是这样：

- 你看不到任何"已固定"（Pinned）的项目，因为你还没有固定任何东西。
- 你看不到任何工作区（Workspaces），因为你还没有在 Cursor 里创建任何工作区。
- 你会看到 **New Agent**（新建代理）、**Search**（搜索）、**Automations**（自动化）、**Customize**（自定义）等选项。我们一会儿会讲到这些。

但最重要的是，你会看到这个 **Agents 视图**（Agents View）。当你创建一个新代理时，你就在这个位置与你的代理对话。

这个工具的布局方式是：你的代理聊天记录或会话显示在左侧。让我们创建一个聊天会话。为了本视频的演示，因为 Grock 是这个平台独有的，我们可以使用 **Grock 4.5 Highfast**。

现在我要做的是输入："你好，你是什么模型？" 当我们这样做时，它其实就创建了一个名为 "model inquiry"（模型询问）的聊天会话。如果我们滚动到左侧底部，就会看到这个名为 "model inquiry" 的新会话。这里我正在与代理聊天。

如果我想重命名这个聊天会话——因为你一周内可能会有 20 个正在进行的会话，你可能想给它们命名或固定——我可以重命名它，比如改成 "testing gro"，然后我们把它固定下来。这样我们就不会丢失这个会话了。现在我们有固定好的 "testing gro"，这就是我们的聊天会话。

**这就是 Agent 会话**。当然，你可以随时固定这些 Agent 会话。

### 工作区（Workspaces）

接下来我想谈谈工作区。如果我们按下 **Command + N**，这等同于点击 "New Agent"。这只是 Command + N。现在我们创建了另一个代理，也就是一个独立的聊天会话。

你可以看到这里写着 **no repo**（无仓库），这意味着我们实际上不在任何工作区中工作。如果你在一个大型项目上工作——比如我们稍后想创建一个网站或应用——我会希望在一个工作区中创建它。

所以我要做的是点击 **Create Workspace**（创建工作区），然后选择 "Create New Folder"（创建新文件夹）。现在我们正在选择电脑上的一个位置，比如"下载"文件夹，用于存放这个项目。我打算把它创建在我的桌面（Desktop）文件夹中。你可以在任何你觉得安全的位置创建它。

我将把这个项目命名为 **agent native**。你一会儿就会明白为什么叫 "agent native"——这只是我想创建的网站和应用的名字。然后点击 "Create"（创建）。

现在我们已经创建了一个名为 "agent native" 的新项目。你会注意到，agent native 工作区一开始并没有显示在左侧，直到我们真正创建了一个会话，它才会出现在 agent native 文件夹下。

### Plan Mode（计划模式）

你会注意到，默认情况下它开启了 **Plan Mode**（计划模式）。提示是："帮助我规划名为 agent native 的应用和网站。"

我输入了提示词。你可以看到 agent native 现在出现在左侧了，而且它自动开启了 Plan Mode。现在它正在加载——然后它输入了一些问题，希望我来回答。

**Plan Mode 只是一种让代理进入规划状态的模式**，帮助你规划某件事。当你想要做的事情非常长，或者你还不太清楚自己到底想构建什么时，Plan Mode 会非常有用。也许在这种情况下，你可以进入 Plan Mode，代理会帮你思考一些你原本不会想到的问题。

就我个人而言，我并不经常使用这个模式。事实上，如果我想让它制定计划，我只会直接说："嘿，你能制定一个计划吗？" 没有必要进入 Plan Mode，因为归根结底，你只是在跟一个代理对话。如果你要一个计划，它就会创建计划；如果你要一些歌词，它就会创作歌词。**这是一个代理**。

Plan Mode 是在一个不同的时代被创造出来的——那时候它更像是跟一个构建应用的 AI 对话，而不是现在这样像跟一个通用代理对话。不过，如果你确实喜欢使用 Plan Mode，你可以输入 `/plan` 自动进入 Plan Mode；或者按加号（+），然后点击 "Plan"，也能进入 Plan Mode。

但再说一次，如果我要计划，我直接开口要就是了。我不太去想 Plan Mode，我只是像跟人对话一样跟代理交流。

### 模型选择与切换

我可以直接回复代理的问题。但如果我真的想创建一个真正的网站，我可能需要**切换模型**。

比如说，我想用 **Fable 5** 模型——它更贵一些；或者我想用 **GPT 5.6 Soul**——这是我最常用的模型。我可以很容易地选择这个模型并切换它。这就是一个模型切换器（Model Switcher）。如果你用过任何 AI 工具，你只需要在这里选择模型就可以了。

如果你没有看到你想用的模型，你还可以进入 **Settings**（设置）→ **Models**（模型），然后向下滚动，添加你在这里没有看到的模型。还有一个 "View All Models"（查看所有模型）的开关，但这些通常是较旧的模型，你不太可能想用——比如有 GPT 5.6 Luna 可以添加，还有 GPT 5.4 Nano。这些是比较老的模型，大概率你并不需要它们。它们不会是最好、最便宜或者最前沿的模型。

### 实际构建：从截图到落地页

现在来回复代理。我输入："Agent native 是我的品牌、播客，以及即将推出的移动应用，它帮助人们了解最新的 AI 代理工具和策略。我想从落地页开始。我们可以创建一个看起来像这样的落地页吗？"

假如我想创建一个跟某个页面长得一样的页面，我可以直接截取这个页面的截图，然后复制它。就像我可以把文字输入到提示框中一样，我也可以**粘贴一张图片**进来。这里有一个提示词，这里有一张图片。然后我们运行它。

我接着说："请创建一个这样的网站。在本地运行。我要它显示 'agent native'。我要文字在屏幕上从左到右水平移动。"

现在 AI 代理正在工作。我们可以看到我们的提示词。我们可以展开提示词；如果点击外面，它就会收起来。我喜欢 Cursor 这一点——它在运行时会像这样把提示词收纳起来。

我们还能看到它正在编辑什么：它正在编辑 4 个文件，探索了 2 个文件，执行了 1 次搜索，运行了 3 条命令。这里是它编写或删除的所有不同代码行。

记住，这个 agent native 文件夹在我们的桌面文件夹里。如果我们打开 Finder（访达），进入桌面，就能看到 agent native。在这个 agent native 文件夹里——也就是我们的工作区——是它创建的所有文件。它刚刚创建的应用，为这个 agent native 项目写好了所有文件。

现在应用已经运行了。默认情况下，当你使用 Cursor 时，它会运行在你的电脑上。如果你点击这里，在外部浏览器中打开，就会打开你的应用。

应用现在运行在我们电脑的本地。这就是我们的代理刚才在 Cursor 内部创建的网站/应用。看看这个，其实挺酷的。我喜欢它为这个应用创建的图形设计，我觉得非常棒。

### 内部浏览器（In-App Browser）

不过，我在使用 Cursor 时，实际上从不用外部浏览器，我用的是**应用内浏览器（In-App Browser）**。所以我会右键点击，选择 "Open in Cursor Browser"（在 Cursor 浏览器中打开）。

我可以把它全屏，然后关闭侧边面板。现在我们就在 Cursor 浏览器内部了，可以查看我们的应用或网站。

当我想做修改时，我可以直接来到底部，点击 "Message Cursor"（给 Cursor 发消息），或者按下 **Command + I**，它就会打开这个界面。这是一个非常有趣的交互界面。

我可以这样说："右上角带 AI 的那张图，我不喜欢它。我挺喜欢其他图片的那种风格，它们更丰富多彩。你能把那张换掉吗？"

如果这个任务可能需要更长时间，我想用一个更快的模型——我们可以切回 Grock，然后直接运行这个提示。

### 排队（Queuing）与转向（Steering）

现在这个提示在运行中。这个界面看起来像一个完全不同的界面，但实际上它做的事情跟刚才那个视图里完全一样，只是现在是在浏览器里。当你关闭浏览器时，这个提示框就会移到这个地方，你可以直接跟它对话，给它发各种提示。

哦，它完成修改了。它换了一张新图片——我甚至不知道它是怎么生成这些图片的。

为了让这个例子继续，我们可以向下滚动到 "Publish Press"（发布新闻）部分。我喜欢这部分，这个板块不错。我们可以直接这样复制粘贴。

"看这张照片，这就是我想要的样子：在 native 字样下面画一条横线横跨底部，然后保留邮箱输入框，再加八篇博客文章。你可以反复使用相同的图片作为占位符，不要花太多时间生成新图片。"

我们可以把这个提示发出去。我们可以看到它在工作，这真的很酷。而且你可以同时发出多个请求。

比如你可以说："你能把顶部的订阅按钮改成蓝色而不是红色吗？红色太刺眼了。"

现在我们有**两个提示同时在工作**。

接下来我想谈谈一个在学习这些"超级应用"（Super Apps）时**非常被低估**的概念——**排队（Queuing）和转向（Steering）的区别**。

所有这些 AI 超级应用都有一个功能：你可以输入一个提示并让它**排队**——也就是说，等当前任务完成后，这个提示会被自动输入进去，相当于在排队等待；或者你可以按下这个按钮**转向（Steer）**，也就是**立即发送（Send Now）**——等于在 AI 还在工作时就把新提示发进去。

不过它刚才其实很快就把所有修改都做完了。现在订阅按钮已经变成蓝色了，底部区域也有了。

现在我要再发一个提示。我按下 **Command + I**：

"嘿，我想告诉你，我希望在输入邮箱的 pro 区域下面多一些间距。然后那八个矩形出现的时候，我希望它们之间多一些空间。还有，我不想要那个巨大的黑色 'A' 图标，我们不需要它。"

我发出这个提示后，Grock 快速完成了它的工作：间距加上了，效果不错。**而这只花了 10 秒钟。**

### 设计模式（Design Mode）

接下来我想谈谈另一个功能，这是最酷的功能之一——**设计模式（Design Mode）**。

如果我点击 "Design Mode"，你会看到 "Design" 这个开关打开了。现在我可以选择界面的不同部分，然后针对它们发出修改提示。

比如，我觉得这个字体有点太大了，我可以直接选中它，然后说："请把这个字体调小一点。" 我可以直接发出这个提示。

又比如："这个 'G' 底部被切掉了，请修复。" 我们就一个个地发出去。你可以看到这个提示在排队中。我会继续。

记得吗，你随时可以全屏，然后再打开浏览器返回浏览器视图。

"这个图标有点奇怪，请不要用这个箭头，换成其他有意义的图标。"

同样，我们只是不断地发出修改指令。**设计模式让我们能获得更精细的修改能力。** 就这样，它完成了修改。**这就是设计模式。**

### 从其他工具迁移技能（Skills）

如果你使用 Codex 或 Claude Code，你可以使用同样的提示词：

"嘿，我需要你给我指令，告诉我你的技能在哪里，我想把它们添加到另一个代理平台 Cursor 上。请给我一段我可以复制给 Cursor 的提示词，让它能够获取你的技能并添加它们。"

对于那些不知道的人来说，**技能（Skills）**是 Cursor 和其他代理工具中一个非常有用的功能。我可以按 `/`，然后我有一个 "YouTube Researcher"（YouTube 研究）技能，我有一个 "YouTube Thumbnail"（YouTube 缩略图）技能。所有这些技能都可以通过输入斜杠和技能名称来引用。

**技能本质上是一个指令文件**，代理在必要时会使用它。比如你可以有一个名为"彩色图片"的技能，这个技能可以让代理以某种特定风格生成图片。如果你请求代理创建带有图形的网站，它就会在认为必要时自动使用那种风格。

由于技能文件只是我电脑上的一些 Markdown 文件，我可以很容易地让 Cursor 去找到它们。所以我复制这段提示词，回到 Cursor，然后说：

"嘿，我想从 Codex 下载一些技能。请列出所有你可以导入到这个技能库中的技能，然后我会告诉你应该导入哪些。"

然后我粘贴这段提示词。接下来我切换模型，用 **GPT 5.6 Soul** 来运行这个提示。

它完成了。它说："所有指向精确 Codex 文件夹的现有符号链接都视为已可用。同名文件夹或指向其他位置的链接将报告为冲突或未处理。设置完成。已通过符号链接添加 77 个 Codex 技能。"

我最近添加的技能之一是 "Riley Media"。现在我们确实有了 Riley Media 这个技能。这个细节不展开，但重点是：**我在 Codex 或 Claude Code 上拥有的所有技能，现在都导入到 Cursor 中了。**

这就是第一部分的全部内容——基础知识。我们涵盖了所有内容，包括如何从 Codex、Claude Code 或你使用的任何其他 AI 代理工具迁移技能。

## 第二部分：实战构建

现在我们进入更紧张的构建环节，真的要开始把 Cursor 推向极限了。我们将**同时构建多个项目**。

首先，我们会在落地页上取得一些进展——我们已经在这个页面上有了一些成果。然后我们将创建一个应用：为 agent native 构建一个**移动应用**。另外我们还会创建一个 **Cursor Canvas**（稍后我会解释），它就像一个拥有 cursor 域名的迷你网站，我们可以为它设置自动化任务，让它每天做研究，并实际更新这个网站。这样我们就能为我们的网站和移动应用做研究了。我会演示这一切是如何工作的。

### 创建 iOS 应用

### 插件（Plugins）/ 自定义（Customize）标签页

接下来我要讲的是**插件（Plugins）**，在 Cursor 里他们称之为 "Customize"（自定义）标签页。

进入 Cursor 里的 Customize 标签页，我们可以看到我们已经安装了一个：**Convex**。我们一会儿会讲到它。我现在要关注的是：点击 "Browse Marketplace"（浏览市场）。

本视频中我想重点介绍两个具有特定且重要功能的插件。我们即将添加两个新插件，它们将用于**数据库（Database）**。

### 什么是数据库？

我对数据库的理解是：**它能把你在构建的东西从"网站"升级为"应用"。**

如果你访问某个落地页并在上面输入内容，用户输入的数据实际上不会存储在任何地方。我认为这就是"网站"的定义。而应用——比如 Twitter 或 YouTube——如果你留言，你能看到是谁留的言，因为**这些数据实际上存储在数据库中**。

所以我要添加的第一个插件是 **Convex**。Convex 是一家数据库服务商，我认为它跟 Cursor 的配合是最好的——Cursor 非常擅长控制 Convex 并为应用创建数据库。

### 为 iOS 应用添加 Convex 数据库与认证

我来操作：去我们的 iOS 应用，然后说：

"请使用 @convex，我要做认证（Authentication）和数据库（Database）。"

回到设计思路：为了把数据保存到正确的用户名下，我们需要认证。**认证（Authentication）就是登录（Sign-in）**，对吧？你需要登录应用。这就是你看到"使用 Google 登录"的原因——它让你知道哪个用户已登录。

而**数据库（Database）就是数据存储的地方**。当用户以用户 00001 的身份登录后，用户 00001 发布内容时，数据就会被存储。无论是发布图片，还是使用 AI——如果我们希望数据被保存，我们就需要知道究竟是哪个用户在输入这些消息，也需要知道 AI 在回复哪个用户。所有这些都会存储在数据库中。

你可能觉得这听起来很复杂。别担心，**AI 会帮你完成所有这一切。**

"用户应该能用邮箱和密码登录。然后我希望所有用户数据——比如用户可以在工具页保存他们最爱的工具。请在工具旁边加上那个小书签图标，用户点击时它会从浅灰色变成黑色，并保存到他们的账户中。另外，我希望所有聊天数据也存储在数据库中。"

我发出这个提示。现在它会添加数据库。这可能需要 5 到 10 分钟，但它会自动在 Convex 内部创建一个新的数据库。

如果你没有 Convex 账户，你可以直接去 Google 注册。连接账户非常简单：进入 Customize 标签页，找到 Convex，点击安装，它会自动引导你直接登录 Convex，然后就可以使用了。

我们可以进一步自定义。注意当前聊天就像一个大杂烩会话。也许这样也行，但为了演示数据库的能力，我想展示如何在聊天页面里做增强：

为了再次说明这一点，我们去看 Convex 数据库。如你所见，这里有更多的聊天会话，还是相同的用户 ID。但我们看到一个新的表，叫做 **conversations**（对话）。记得吗，我们创建了两个新对话，每个都有自己的 ID。

**所有东西都被存储起来了。** 现在其他人也可以登录、创建多个聊天会话，所有数据都会存入 Convex。我们用**一个插件加几个提示**就完成了这一切——就是这么简单。

我知道这对你来说可能有点难理解，但数据库本身就可以单独拍一整期视频。你要做的其实就是**依赖 AI**。如果你想深入了解，直接问 Cursor："嘿，你能解释一下这些表是什么、这意味着什么吗？"

所以，当你使用 AI 构建带数据库的应用时，你的职责是：**测试所有不同的场景**——登录账户、进行多次聊天、退出登录、用新账户登录——你要做的本质上就是测试一切是否正常工作。如果有问题，就告诉 Cursor（AI 代理）。基本就是这样测试的。

好了，这就是数据库的内容。**你可以把它应用到网页应用、iOS 应用、任何类型的应用、桌面应用上——任何你需要数据库的地方，都可以用 Convex 轻松搭建。**

### 托管（Hosting）：用 Vercel 把应用发布到互联网

接下来要讲的是**托管（Hosting）**。这是让你的应用或网站从"在你自己电脑上运行"变成"在互联网上运行"的步骤。

让我解释一下我的意思。在 Cursor 里，应用运行在这个小地址上，对吧？你不需要知道这意味着什么，因为当你对 Cursor 说"请帮我在本地运行"时，应用就会在你的电脑上运行。

但是，如果你想让朋友看到你的应用，想让它真正上线到互联网，你就需要**把它托管到某个地方**。

为了托管，我们将使用另一个插件。去 Customize 标签页 → Browse Marketplace（浏览市场）→ 输入 **Vercel** → 点击 "Add"（添加）。

添加完成后，会显示"已启用 29 个工具"。这是因为我在过去已经连接过我的账户。你可能会需要先连接你的 Vercel 账户，会有一个额外的界面。

现在回到我们的 agent native 网页应用，输入 `@vercel`，可以看到有 29 个不同的工具。

我的指令是：

"请为这个项目创建一个全新的 Vercel 项目，并让它真正上线到互联网。完成后，请把 Vercel 上实际托管的链接发给我。我也希望你在浏览器里打开它。"

这需要一点时间，但它会将应用部署到 Vercel——也就是把它放到互联网上。

完成了！我们现在看到这个链接。点击打开——我们看到了 `agentnative-site.bice.vercel.app`。这域名有点随机，但这就是我们的网站，**它真的在互联网上了。** 任何人都可以在互联网上打开这个链接，看到这个网站。

### 同步 Web 与 iOS 的数据库

请深入研究那个项目，把它完美地做出来，让数据库等一切都能协同工作。

我还希望你在 Web 端添加一个与我们 iOS 应用上完全相同的聊天标签页，这样我就能跟同一个 AI 代理聊天。我希望这是一个完全相同的流程，所有数据在数据库中都是相同的。"

这个任务有点难度。我其实不确定它第一次就能成功，但让我们看看。

它回复说："一个共享的身份系统，一个 Convex 部署，Web 和 iOS 共享聊天历史。我会先检查两个项目，然后将 Web 应用接入移动应用现有的后端，而不是创建第二个系统。" 非常酷。

这个任务花了更长时间，我相信它已经完成了。让我们看看这个网站。我将在 Cursor 浏览器中打开它。

我们现在在 agent native 网站上。我尝试用之前的同一个账户登录——就是我在 iOS 应用上使用的同一个邮箱，用同样的方式登录。

现在我们已登录。如果我去看历史记录，可以看到之前的那些聊天。看这里！我还可以创建新聊天，切换模型："你好，我想了解 AI。"

现在我们已登录同一个账户。如果打开模拟器——回到"学习"标签页，再进入"代理"标签页——输入"你好，我想了解 AI"。

**Web 应用已经在互联网上，托管在 Vercel 上，而后端（数据库）也完美同步了。** 随着我在这里进行更多聊天，它们也会保存到这里。工具部分我还可以收藏最爱工具，这同样会存储在数据库中。

### 用 GitHub 保存工作

在进入第三部分大量高级功能之前，构建部分的最后一项内容，是对 Cursor 的其他功能来一轮快速浏览（Lightning Round）。我想先谈谈 **GitHub**。

现在我想讲的是如何在 Cursor 中保存我们的工作。为此我们将使用 **GitHub**。

**GitHub 是一个应用，你几乎可以把它想象成"开发者的 Google Drive"。** 注册后，你可以创建一个 GitHub 仓库（Repository）。

点击 "New"（新建），基本上就能创建一个新的 GitHub 仓库。比如我可以命名为 "riley-ios-agent-native"。我可以创建一个项目，可以写描述——"agent native iOS 应用"。

我们基本上是在"开发者的 Google Drive"上创建一个文件夹。我需要选择我的个人资料，然后点击 "Create Repository"（创建仓库）。

这就创建了一个我可以复制的空文件夹。现在我要做的就是在 Cursor 中操作。回到我们的 iOS 应用，然后说：

"嘿，我为这个 iOS 应用创建了这个新仓库。你能把代码推送到这里吗？"

然后粘贴链接，运行它。

如果你还没有登录 GitHub，它会在此时提示你登录 GitHub。如果它没有自动提示，你就说："嘿，帮我把 Cursor 连接到 GitHub。" Cursor 会告诉你具体怎么做，大约只需要 20 秒。

现在它正在检查这个项目。你可以把 GitHub 仓库设为公开或私有。我顺便说一句："顺便说一下，把这个仓库设为私有。"

看，它显示完成了。现在我去 GitHub，按 **Command + R** 刷新浏览器页面——你看，所有文件都出现在这里了，GitHub 仓库已经更新。

### 让 Cursor 自动创建 GitHub 仓库

我向你展示了手动方法：去 GitHub 创建新仓库并粘贴链接。或者你也可以直接让 Cursor 做：

"嘿，我需要你为 agent native 的 Web 应用创建一个新的 GitHub 仓库，命名为 'agent native web app'。这个要设为私有。创建仓库，完成后把仓库链接发给我。"

**仓库（Repository）**的意思就是——它就像一个 Google Drive 文件夹，但面向开发者。

这样做的好处是，代码基本上被保存了，以后你就能更容易地回滚（Revert）到之前的版本。而且你应该**更频繁地更新仓库**。

好了，完成了。右键点击——在外部浏览器中打开——这是为 agent native Web 应用创建的新仓库。

现在你的项目基本上已经保存在云端了。**如果你要和其他人协作，理解 GitHub 极其重要。**

GitHub 对接下来要讲的 **Cursor iOS 应用**也至关重要，因为要使用 Cursor iOS 应用——在我看来，这是从手机上进行编码（或"氛围编码"Vibe Coding）最酷的方式之一——你**必须**创建一个 GitHub 仓库。是的，你必须使用 GitHub。

### 使用 Cursor iOS 应用进行云端开发

注意，顶部写着 "All Repos"（所有仓库）。点击 "All Repos"，我们可以创建一个代理。在这里我们可以选择要编辑哪个仓库。

还记得我们的 Web 应用仓库叫什么吗？我们叫它 "agent native web app"。就在这里，我们可以点击它。

我想做的是，直接对它语音输入：

"嘿，我希望你为这个应用探索一种不同的设计风格。先不要推送到 main（主分支）。我希望你探索一种新的 Web 应用风格，并给我发送截图。如果我喜欢，我们再批准它。我现在只想看到一些探索性的方案，提出一个新的视觉概念。"

停止录音——好了，我们有了提示词。

我要切换模型，这次我们用 **5.6 Soul**，然后发出提示。

我们把项目放在了 GitHub 上，它基本上就是一堆代码文件，存储在云端。现在，它正在**云端设置一台电脑**，将根据我们的提示重写应用代码，然后在云端实际运行应用、测试应用，然后把截图发送给我们。

**这就是 Cursor 未来的方向。他们正在搭建云电脑**，你可以发送提示，AI 会实际编辑应用、运行应用、替你测试一切。它甚至能给你发送屏幕录制，也就是视频——它实际使用应用的画面。你可以提供反馈，然后说"好的，我喜欢这些改动，请创建一个 PR（Pull Request，拉取请求）"。

这需要一点时间。你可以像在 Cursor 里一样观看代码编写过程，或者干脆把手机放一边，等它完成后你会收到通知。打开后就能看到它做的所有修改。

让我们等几分钟让任务完成。你看，顶部灵动岛（Dynamic Island）出现了一个小对勾。我点击它——

**这就是我从手机上进行编码的方式。** 当我觉得它准备好了，就点击 "Marked as Ready"（标记为就绪）。

如果我合并这个 Pull Request，改动就会提交到 main 分支，Web 应用就不再是原来的样子，而是变成这个样子。但我个人觉得这个新设计有点丑，所以我不会合并这些更改。

但这让你了解了如何使用 iOS 应用来抛出你的各种想法。**它会创建一个新分支，所以你不必担心它改动任何线上内容。** 你直接让它给你发屏幕录制或截图就行。**这就是使用 Cursor iOS 应用从手机上进行构建的基本方式。**

### Side Chat（侧边对话）

好的，这就是 iOS 应用。接下来我们谈谈 **Side Chat（侧边对话）**。

回到 Cursor。如果我们正在跟 Cursor 对话——如果代理正在工作——我输入 `/side` 并按回车，这会允许我跟一个**侧边代理（Side Agent）**对话。

这个代理不能像主代理那样编辑应用，但它允许我提问。比如："嘿，我应该给应用添加什么？"

于是我们可以与主代理运行的同时进行这个侧边对话。这与 Claude Code 和 Codex 中的某些功能非常相似。

### 在 Cursor 中使用 Claude Code

说到 Claude Code 和 Codex，我知道很多开发者——尤其是我在创业公司一起工作的同事——我们实际上经常同时在 Cursor 里使用 Claude Code。

如果你想在 Cursor 内部使用 Claude Code，非常容易：打开一个终端（Terminal），像打开一个网站、浏览器或 Canvas 一样打开一个新标签页，输入 `claude`——现在我们就直接能在浏览器里使用运行着 Fable 5 的 Claude Code 了。

这只是个有趣的小操作。**你可以通过这个方式进入终端。** 这是一个真正的高级功能。理解如何使用终端（除了运行 Claude Code 之外）非常困难，但终端的酷之处在于：**AI 非常擅长使用终端**。任何你可能想在终端里做的事情，你都可以直接让 AI 去做。

### 成本控制建议

最后我想谈的——因为我一直在大量使用 Fable 5 和 GPT 5.6 Soul——是**成本节省（Cost Saving）**。

如果你想省钱，第一件应该做的事是：要么使用 **Auto Mode（自动模式）**，要么使用 **Grok 4.5**。

- **Auto Mode** 会根据你的提示自动决定最佳模型，它会在质量和速度之间取得平衡。**大多数任务都推荐使用它。** 大多数情况下，你并不需要最智能的模型，它能完成任务就够了。
- 如果你只用 Fable，你会在这上面花很多钱。我确实推荐使用 **Grok**，因为以它的质量来说，这是一个非常实惠的模型。我预计 Cursor 会在 Grok 模型上做很多补贴，而且我认为 Grok 会变得更智能 10 倍，价格也会与其他前沿模型非常有竞争力。

所以我会建议：**避免使用 Fable 5 和 GPT 模型**，使用 Grok 模型或 Auto 模式来降低 Cursor 的使用成本。而且它们也**快得多**。Auto 模式和 Grok 4.5 的组合明显更快。

这就是我最后的建议。
